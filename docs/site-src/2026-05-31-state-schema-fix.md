# Decision: Fix `dismissed_gap_flags` type in `state.json` (PR #102)

**Date:** 2026-05-31  
**PR:** [#102](https://github.com/theoju/claude-code-self-assessment/pull/102)  
**Breaking:** No

## Context

The engineering-docs-agent orchestrator stores run state in `.engineering-docs-agent/state.json`. On startup the orchestrator performs strict JSON Schema validation against this file and exits with code 2 if validation fails — no subagents are dispatched.

The schema requires `dismissed_gap_flags` to be a keyed object indexed by `{owner}/{name}#{pr}` strings. The bootstrap PR that initially seeded `state.json` emitted an empty JSON array (`[]`) for this field instead of an empty object (`{}`). These are not equivalent types in JSON Schema: `[]` is `array`, `{}` is `object`.

## Failure

The nightly docs-agent run on 2026-05-31 failed within approximately 0.2 seconds:

```
state invalid at $.dismissed_gap_flags: [] is not of type 'object'
```

The orchestrator exited with code 2 before dispatching any subagent. No pages were authored or updated that run.

## Fix

PR #102 corrects the single-character mismatch — replacing `[]` with `{}` in `.engineering-docs-agent/state.json`. The current file reads:

```json
{
  "version": "1",
  "last_successful_run": {
    "head_sha": "6c782ead5731960d3a0a9dd5b4e2ffcb9e1c2135",
    "pr_number": 0
  },
  "dismissed_gap_flags": {}
}
```

`dismissed_gap_flags` is now correctly typed as an empty object, which satisfies the schema and unblocks orchestrator startup.

## Follow-up

**CCE-66** tracks the plugin-side root cause: the setup skill and `state.example.json` must be updated so the bootstrap path never emits `[]` for an object-typed field again. Until CCE-66 lands, any fresh `state.json` generated by the setup skill may reproduce this failure on first run.
