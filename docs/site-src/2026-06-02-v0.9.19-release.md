# v0.9.19

`package.json` bumped to `0.9.19` in [PR #120](https://github.com/theoju/claude-code-self-assessment/pull/120).
The PR itself only touches the version field — the substantive change it
ships is the CCE-78 scoring-honesty fix that landed one PR earlier, plus
housekeeping accumulated since v0.9.18.

## What's in this release

The headline fix (PR #119, CCE-78) unblends a cumulative all-time counter
out of a 30-day windowed ratio. The Memory Execution scorer's `/btw`
numerator was previously built with:

```js
Math.max(maxProbe(s, field), cumulativeCounter);
```

`cliBtwUseCount` is a lifetime invocation count read from `~/.claude.json`;
`btwCommandUses` is a 30-day session-coverage counter. `Math.max`-ing the two
together let the cumulative, ever-growing field silently override the
windowed one, which overstated the Memory Execution ratio and made it drift
upward with account age rather than reflect recent posture — the opposite
of what the dimension is supposed to measure.

The fix exposes the cumulative count on its own field
(`cliBtwUseCountAllTime`) instead of folding it into the windowed numerator,
and reroutes the tip 33 predicate (an `>=1` adoption check, which is the
right shape for a cumulative field) to read from that field directly. The
windowed numerator goes back to measuring only what it's supposed to:
session-coverage in the lookback window.

This is a release-cadence note, not an architecture change — see the CCE-78
PR for the scorer diff itself. The follow-up redesign of the Memory
Execution scorer's numerator (moving from a fungible sum of fields to
per-field semantic categorization) is tracked separately as CCE-79.

## Why this shape of fix

The two axes to check before adding any field to a ratio numerator are (a)
time window — windowed vs. cumulative — and (b) counter class —
session-coverage vs. raw invocation count. `cliBtwUseCount` and
`btwCommandUses` disagreed on axis (a); mixing them into one `sum`/`max`
overstated the ratio. Route a field that disagrees with the rest of a
numerator on either axis to its own surface instead: a separate
`*AllTime` field for evidence text, or a separate predicate for an
adoption check, rather than blending it into the ratio.
