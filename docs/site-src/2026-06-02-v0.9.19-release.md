# v0.9.19: stop blending cumulative `/btw` counts into the windowed signal

`package.json` now reads `0.9.19` (PR #120). The release itself is a version
bump — the substance shipped one PR earlier (#119) and this note documents
what it changed and why, since it's the kind of fix that's easy to
re-regress if the underlying rule isn't written down somewhere durable.

## What changed

`signalsSummary.btwCommandUses` used to blend two things that look
similar but aren't: the 30-day windowed count of `/btw` invocations
(session-coverage) and `cliBtwUseCount`, a cumulative all-time invocation
counter from `~/.claude.json`. The blend was a `Math.max(...)` at
`run-assessment.mjs:134-137`, done for predicate ergonomics — it made the
tip 33 "have you used `/btw`" check trivially satisfied. But it also meant
`btwCommandUses` silently stopped being a 30-day signal for anyone whose
account was old enough to have accumulated lifetime uses, even if they
hadn't touched `/btw` in the current window.

The fix exposes the cumulative counter on its own field,
`cliBtwUseCountAllTime`, and reroutes the tip 33/54 `satisfiedWhen`
predicate to read from it instead. `btwCommandUses` goes back to meaning
only what it says: uses observed in the current windowed transcript scan.

This release also archives the CCE-72 and CCE-76 plans now that both have
landed — housekeeping, no behavior change.

## Why it matters

This is now a named hard rule in `CLAUDE.md`, not just a one-off fix:

> Don't blend cumulative all-time counters into windowed ratio surfaces.
> Numerator counters that share a ratio with a 30-day windowed denominator
> must also be 30-day windowed.

Two axes matter for any field feeding a ratio or a summary signal: **time
window** (windowed vs. cumulative) and **counter class** (session-coverage
vs. raw invocation count). The original `/btw` blend crossed both — a
cumulative, raw-invocation-count field folded into a windowed,
session-coverage field — and the result looked ergonomic (one field,
predicate satisfied) while quietly overstating recent-practice signal in a
way that only got worse with account age.

## What's still open

The Memory Execution scorer's numerator (`/btw` + `/clear` + `/compact` +
`/rewind`) still mixes counter classes beyond this one field — that
redesign is tracked separately as CCE-79 and isn't part of this release.
This release only fixes the `/btw`-specific blend and gives the cumulative
value a home (`cliBtwUseCountAllTime`) so a future CCE-79 pass has
something clean to build the redesigned numerator from.
