# v0.9.19 — fixing the /btw windowed/cumulative blend

`package.json` bumped to `0.9.19` in [PR #120](https://github.com/theoju/claude-code-self-assessment/pull/120),
the release-bump commit for a cycle that bundles a scoring-honesty fix
(CCE-78) with a housekeeping archive of landed plans. PR #120 itself only
touches the version field; the substance shipped in the PR it bundles —
read that one if you're auditing the `/btw` numbers, this page is the
release-note summary.

## What changed

Memory Execution's ratio numerator was silently corrupted by a blend at
`run-assessment.mjs:134-137`: `Math.max(maxProbe(s, field), cumulativeCounter)`
folded `cliBtwUseCount` — a **cumulative, all-time** invocation count of the
`/btw` command — into `btwCommandUses`, a **30-day windowed, session-coverage**
signal. The two fields differ on both semantic axes the project tracks for
ratio numerators (time window, and counter class), and mixing them meant the
Memory Execution ratio drifted upward with account age rather than reflecting
recent posture — exactly the failure mode the project's per-field
categorization rule exists to catch.

The fix:

- `cliBtwUseCount` (cumulative, all-time) is now exposed on its own
  `signalsSummary` field, `cliBtwUseCountAllTime`, instead of being blended
  into the windowed numerator.
- The `btw-side-channel` rubric predicate — the one checking "have you ever
  used `/btw`" — is rerouted to read `cliBtwUseCountAllTime` directly, since
  that's the field whose semantics actually match a lifetime-adoption check.
- `btwCommandUses` stays untouched: a pure 30-day session-coverage signal,
  no cumulative counter mixed in.

This is the concrete instance behind the CLAUDE.md hard rule added the same
cycle: *"Don't blend cumulative all-time counters into windowed ratio
surfaces."* The redesign of the Memory Execution scorer to a per-field
semantic model (rather than a fungible sum) is tracked separately as
**CCE-79**.

## Housekeeping

The release also archives plans that have already landed, keeping
`docs/superpowers/plans/` scoped to work still in flight.

## Why this matters if you're reading a dashboard score

If you ran `npm run assess` on a version before `0.9.19`, your Memory &
Context Execution number may read higher than your actual 30-day `/clear` +
`/compact` + `/btw` session coverage warrants, because the old blend let a
lifetime `/btw` count silently top up the ratio. Re-run on `0.9.19` or later
to get the corrected figure; `cliBtwUseCountAllTime` is still visible as
evidence text, it's just no longer folded into the score.
