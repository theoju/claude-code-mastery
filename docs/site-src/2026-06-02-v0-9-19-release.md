# v0.9.19 — Memory Execution scorer honesty fix (CCE-78)

Released 2026-06-02. This version bundles two previously merged PRs: a scoring
correctness fix (PR #119 / CCE-78) and routine plan archiving (PR #118).

---

## What changed

### CCE-78: Unblend `cliBtwUseCount` from `btwCommandUses` (PR #119)

The Memory Execution scorer contained a silent numerator corruption introduced
in v0.9.18. The blending looked like this:

```js
// run-assessment.mjs:134-137 (pre-fix)
btwCommandUses: Math.max(
  insights.btwCommandUses,      // 30-day windowed session-coverage
  signals.cliBtwUseCount        // cumulative all-time invocation count
)
```

`btwCommandUses` is a 30-day windowed session-coverage counter —
"in how many recent sessions did `/btw` fire?" `cliBtwUseCount` is a
cumulative all-time invocation count from `~/.claude.json`. Blending them
via `Math.max` conflates two incompatible semantic axes: **time window**
(windowed vs. cumulative) and **counter class** (per-session-coverage vs.
raw invocation count). The practical effect: Memory Execution scores drifted
upward with account age, independent of recent usage posture.

**The fix** exposes `cliBtwUseCountAllTime` as a separate
`signalsSummary` field and reroutes the tip 33 predicate to that field for
adoption checks (`>= 1`). The ratio scorer's numerator stays purely
windowed. The `Math.max` blend is gone.

If your Memory Execution score drops slightly after upgrading, that's
the correction landing — the old score was overstated.

### Plan archiving (PR #118)

The completed implementation plans for CCE-72 (ship-journal stage counters)
and CCE-76 (all-twelve-dimension Execution scorers) were moved to the
`docs/superpowers/plans/archived/` directory. No scoring or behavior change.

## Hard rule reinforced

This fix is the reference implementation for the following rule now in
`CLAUDE.md`:

> **Don't blend cumulative all-time counters into windowed ratio surfaces.**
> Numerator counters that share a ratio with a 30-day windowed denominator
> must also be 30-day windowed. … Keep the cumulative source on a separate
> `signalsSummary` field (e.g. `cliBtwUseCountAllTime`) and route
> habit-only predicates (`>= 1` adoption checks) at the cumulative field.

When you add a new Execution ratio scorer, verify both axes — time window
and counter class — before wiring the numerator.
