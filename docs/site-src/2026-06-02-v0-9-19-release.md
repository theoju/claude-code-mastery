# v0.9.19

`package.json` bumps to `0.9.19` (PR #120). The version bump itself is a
one-line diff, but it's the marker for two prior PRs landing together:

- **CCE-78 / PR #119** — unblends the cumulative all-time `cliBtwUseCount`
  out of the Memory Execution scorer's windowed `btwCommandUses` numerator.
  The scorer had been `Math.max`-ing a lifetime `/btw` invocation count into a
  30-day session-coverage ratio, which silently overstated Memory Execution
  coverage and drifted upward with account age rather than recent posture.
  `cliBtwUseCountAllTime` is now exposed as its own `signalsSummary` field and
  the tip 33 predicate reroutes to it, leaving the ratio numerator
  session-coverage-only. See the CLAUDE.md "Hard rules" entry for the full
  before/after — the follow-up redesign of the whole Memory Execution
  numerator (restricting it to `/clear` + `/compact`, moving `/btw` to
  evidence text) is tracked separately as **CCE-79**.
- **PR #118** — archives the already-landed CCE-72 and CCE-76 plan documents.
  Housekeeping only; no scoring or dashboard behavior changes.

Nothing in this release touches `app/`, the rubric shape, or any rendering
surface. If you're auditing why a Memory Execution score moved between runs
around this date, it's the `/btw` blend fix in PR #119, not a rubric retune.
