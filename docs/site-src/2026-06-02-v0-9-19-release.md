# v0.9.19

`package.json` bumped to `0.9.19` in [PR #120](https://github.com/theoju/claude-code-self-assessment/pull/120).
The PR itself is a one-line version bump; it exists to cut a release around
two pieces of already-landed work rather than to introduce new behavior.

## What's in this release

**CCE-78: `/btw` scoring-honesty fix.** Before this release,
`signalsSummary.btwCommandUses` — the field the Memory Execution scorer reads
as a windowed, session-coverage numerator — was silently blended with
`cliBtwUseCount`, a cumulative all-time invocation count pulled from
`~/.claude.json`. The blend was ergonomic (one field, one `Math.max`) but
wrong on both axes CLAUDE.md now asks you to check before adding to a
numerator: time window (30-day vs. lifetime) and counter class
(session-coverage vs. raw invocation count). An account that had used `/btw`
heavily months ago, then gone quiet, still reported high recent Memory
Execution coverage.

The fix un-blends the two: `btwCommandUses` now reflects only the 30-day
windowed signal, and the cumulative count is exposed separately as
`cliBtwUseCountAllTime` on the signals summary. The `/btw` adoption predicate
(a binary "have you ever used this" check) was rerouted to read the
cumulative field directly, so the habit-adoption check still works — it's
just no longer laundered through the ratio numerator.

This landed as its own change ahead of the version bump (referenced in the
project's CLAUDE.md as the reference incident for the "don't blend cumulative
counters into windowed ratios" rule); v0.9.19 is the release that ships it.

**Follow-up filed, not included here.** The Memory Execution scorer's
numerator still isn't fully redesigned along per-field semantic lines —
that broader pass (restricting the numerator to genuinely comparable
session-coverage signals, surfacing `/btw` as evidence text rather than a
scoring input) is tracked separately as **CCE-79** and is explicitly out of
scope for this release.

**Housekeeping.** The same PR archives plan files for work that had already
landed, keeping `docs/superpowers/plans/` limited to in-flight plans.

## Why cut a release for this

Anyone reading `signalsSummary.btwCommandUses` downstream — the dashboard's
Memory & Context dimension, or any script consuming the assessment JSON
directly — was getting an inflated, non-windowed number. Tagging a release
at the fix gives the archive a clean point to say "scores computed after
this point use the corrected `/btw` semantics."

## Related

- CCE-78 (the scoring-honesty fix itself)
- CCE-79 (Memory Execution scorer redesign — not yet done)

  counter-class classification before being summed.
