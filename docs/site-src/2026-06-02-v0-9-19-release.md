# v0.9.19 — Memory Execution score honesty fix (CCE-78)

Released 2026-06-02. Bundles two previously-merged PRs: the CCE-78 scoring bugfix (PR #119) and plan archiving for completed CCE-72 and CCE-76 work (PR #118).

---

## What changed

### CCE-78: unblend `cliBtwUseCount` from the Memory Execution ratio (PR #119)

The Memory Execution scorer computes a ratio of session-coverage for context-management commands over a 30-day window. Before this fix, `run-assessment.mjs` blended `cliBtwUseCount` — a **cumulative all-time** `/btw` invocation count — into `btwCommandUses` via `Math.max`. That made the numerator grow with account age rather than with recent posture, silently inflating Memory Execution scores on older accounts.

The fix separates the two signals:

| Signal | Class | Time window | Routed to |
|---|---|---|---|
| `btwCommandUses` | session-coverage | 30-day windowed | Memory Execution ratio numerator |
| `cliBtwUseCountAllTime` | raw invocation count | cumulative all-time | evidence text (tip 33 predicate) |

`cliBtwUseCountAllTime` is now exposed as a separate field in `signalsSummary`. The tip 33 (`satisfiedWhen`) predicate targets the cumulative field for the habit-adoption check — a `≥1` adoption signal is legitimately lifetime-scoped. The ratio numerator is restricted to the windowed, session-coverage signal.

**Effect:** Memory Execution scores on accounts with a long `/btw` history will read lower and more accurately after this release. The number now reflects recent practice, not account age.

### Plan archiving (PR #118)

Archived completed plans for CCE-72 (ship-journal stage counters) and CCE-76 (all-twelve-dimensions Execution scorers). Both shipped in earlier releases; archiving marks them closed so the active plans directory tracks only in-flight work.

## What's still open

**CCE-79** (Memory Execution scorer redesign) is the follow-up. The CCE-78 fix corrects the blending bug, but the broader redesign — restricting the numerator to `/clear` + `/compact` session-coverage signals, surfacing `/btw` only as cumulative evidence text, and recalibrating the rubric target 92 → 60 to match the narrowed realistic ceiling — is a separate PR. Until CCE-79 lands, the Memory Execution ratio numerator contains `/btw` (now correctly windowed), `/clear`, and `/compact`. See the redesign spec at `docs/superpowers/specs/2026-06-04-cce79-memory-scorer-redesign-design.md`.

---

## Upgrade notes

No migration steps. Run `npm run assess` after pulling; the scoring change takes effect automatically. If you track `assessment-history.json`, expect a step-down in Memory Execution scores on the next run — that's the correction, not a regression.
