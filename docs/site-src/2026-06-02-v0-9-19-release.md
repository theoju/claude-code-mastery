# v0.9.19: unblending the `/btw` signal

v0.9.19 is a minor release cut (PR #120, `package.json` version bump to
`0.9.19`) that ships one scoring-honesty fix and one housekeeping pass. The
release PR itself touches only the version field — the substantive change
had already landed on `main` via the two PRs it bundles.

## What shipped

**CCE-78 / PR #119 — stop blending cumulative `/btw` counts into the
windowed signal.** Before this fix, the Memory & Context Execution signal
`signalsSummary.btwCommandUses` — a 30-day windowed, session-coverage
counter — was `Math.max`'d against `~/.claude.json`'s `btwUseCount`, which
is a cumulative all-time invocation count. Blending the two silently
overstated recent `/btw` usage, and the effect grew with account age rather
than reflecting actual 30-day posture: the exact failure mode the project's
"don't blend cumulative all-time counters into windowed ratio surfaces"
rule now warns against.

The fix exposes the cumulative source on its own field,
`cliBtwUseCountAllTime`, and reroutes the `btw-side-channel` rubric
predicate to read from it directly instead of folding it into
`btwCommandUses`. The windowed signal now measures only what it claims to
measure; the cumulative one is available where a habit-adoption check
(`>=1`) actually wants it.

This was the specific incident that produced the two-axis-classification
rule in this repo's CLAUDE.md — every new field added to a ratio numerator
now gets checked against **(a)** time window (windowed vs. cumulative) and
**(b)** counter class (session-coverage vs. raw invocation count) before it
goes in. A fuller redesign of the Memory Execution scorer along those lines
is filed as a follow-up, **CCE-79**.

**PR #118 — archive landed planning docs.** Housekeeping: the CCE-72 and
CCE-76 plans, both already shipped, moved out of the active `plans/`
directory now that there's nothing left to track against them.

## Why it matters

Nothing on the dashboard's rendered scores changes for most setups — the
bug only showed up as an inflated Memory & Context Execution number for
accounts with real `/btw` history predating the 30-day window. But it's a
useful release to point at as the reference case for the windowed-vs-
cumulative distinction: if you're adding a new field to any ratio
numerator in `scripts/insights-signals.mjs` or `scripts/_usage-data.mjs`,
this is the incident to reread first.
