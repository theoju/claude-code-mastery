# v0.9.19 — scoring-honesty fix for `/btw` counter semantics (CCE-78)

**Released:** 2026-06-02  
**PR:** [#120](https://github.com/theoju/claude-code-self-assessment/pull/120) (version bump bundling PR #119 + PR #118)

---

## What changed

### CCE-78: unblend cumulative `/btw` count from the windowed session-coverage surface (PR #119)

The Memory Execution scorer maintained a `btwCommandUses` field in `signalsSummary` that was silently corrupted by a `Math.max` blend at `run-assessment.mjs:134–137`. The blend merged two semantically incompatible counters into a single value:

| Field | Time window | Counter class |
|---|---|---|
| `cliBtwUseCount` | Cumulative all-time | Raw invocation count |
| `btwCommandUses` | 30-day windowed | Per-session coverage |

Because `cliBtwUseCount` grows monotonically with account age, the blend caused `btwCommandUses` — the Memory Execution ratio's numerator — to drift upward over time regardless of recent posture. A user who used `/btw` heavily 18 months ago and never since would still score as an active user.

The fix does three things:

1. **Removes the blend.** `btwCommandUses` now carries only the 30-day windowed session-coverage count, which is what the ratio denominator expects.
2. **Exposes the cumulative value separately** as `cliBtwUseCountAllTime` in `signalsSummary`. Cumulative-only predicates ("`/btw` adopted at any point") route there; ratio numerators don't touch it.
3. **Reroutes the `btw-side-channel` predicate** (tips 33 and 54 in `app/data/rubric.json`) to `cliBtwUseCountAllTime`, so habit-adoption checks still pass for users who have adopted `/btw` but not necessarily in the current 30-day window.

The Memory Execution score itself is **unchanged by design** — the numerator change affects the absolute counter value, but the scorer's target was already calibrated against the corrected semantics. No rubric target adjustments were needed.

### PR #118: plan file archival

Completed plan files for CCE-72 and CCE-76 were moved to `docs/superpowers/plans/archived/`. No scoring or signal logic was affected.

---

## Why it matters

This is a **data-honesty fix**, not a feature. The old blend violated the hard rule documented in CLAUDE.md:

> Don't blend cumulative all-time counters into windowed ratio surfaces. Numerator counters that share a ratio with a 30-day windowed denominator must also be 30-day windowed.

The same blend pattern could silently corrupt any ratio scorer that adds a `Math.max` ergonomic between a cumulative all-time adoption signal and a windowed session-coverage field. The fix makes the two semantic axes — time window and counter class — structurally separate rather than defensively documented.

A new CLAUDE.md hard rule ("Per-field semantic categorization before adding to any numerator") captures the two-axis classification requirement for future scorer additions. It references this fix as the canonical failure mode.

## What is not in this release

**CCE-79 (Memory Execution scorer redesign)** is a follow-up filed but not included here. The original Memory Execution numerator summed four commands (`/btw + /clear + /compact + /rewind`) across three incompatible counter classes. CCE-78 fixed the immediate blend regression; CCE-79 will narrow the numerator to the two genuinely session-coverage signals (`/clear + /compact`), surface `/btw` as cumulative evidence text, keep `/rewind` only as a next-action probe, and recalibrate the rubric target from 92 to 60 to match the realistic ceiling.

## Upgrade notes

No action required. `package.json` version is the only file changed in this release PR. The substantive changes landed in the previously merged PR #119 and PR #118; `npm run assess` on the current `main` already runs the corrected scorer.

If you have `assessment.json` from a pre-0.9.19 run, the next `npm run assess` will recompute with the corrected `btwCommandUses` value. The score may shift slightly downward if the cumulative `/btw` count was carrying the numerator above what the windowed count alone supports.
