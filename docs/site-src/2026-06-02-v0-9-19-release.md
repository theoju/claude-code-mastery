# v0.9.19 — Memory Execution scoring-integrity fix (CCE-78)

Released 2026-06-02. Bundles two PRs: **#119** (the substantive fix) and **#118** (housekeeping).

## What changed

### PR #119 — fix: unblend `cliBtwUseCount` from `btwCommandUses` (CCE-78)

The Memory Execution scorer had a silent data-integrity bug. At
`scripts/run-assessment.mjs:134-137`, the assembly step blended two
semantically incompatible counters via `Math.max`:

```js
// before — incorrect
btwCommandUses: Math.max(signals.btwCommandUses, cliSignals.cliBtwUseCount)
```

- `btwCommandUses` — a **30-day windowed session-coverage** counter (how many
  sessions in the scoring window included a `/btw` invocation).
- `cliBtwUseCount` — a **cumulative all-time invocation count** (how many
  times `/btw` has ever been called since account creation, read from
  `~/.claude.json`).

Because `Math.max` always picks the larger number, and `cliBtwUseCount` only
ever increases over an account's lifetime, the Memory Execution numerator
drifted upward with account age regardless of recent behavior. An engineer who
hadn't used `/btw` in three months still saw their windowed ratio inflated by a
count from six months ago. This violated the [hard rule against blending
cumulative all-time counters into windowed ratio surfaces](https://github.com/theoju/claude-code-self-assessment/blob/main/CLAUDE.md).

**The fix** separates the two signals cleanly:

- `btwCommandUses` stays a 30-day windowed session-coverage counter — no
  longer touched by the cumulative source.
- A new field, `cliBtwUseCountAllTime`, exposes the cumulative count on a
  dedicated surface (evidence text) rather than as a ratio numerator.
- The tip-33 predicate (`/btw` adoption check, a binary `>= 1` test) is
  rerouted to `cliBtwUseCountAllTime`, where a cumulative counter is the
  semantically correct signal for an adoption check.

The windowed ratio now reflects only sessions in the scoring window.
Previously-overstated Memory Execution scores will decrease after upgrading;
that decrease is a correction, not a regression.

### PR #118 — chore: archive CCE-72 and CCE-76 plan files

Moves the landed plan files for CCE-72 (ship-journal stage counters) and
CCE-76 (all-twelve-dimensions Execution scorers) to the archived plans
directory. No scoring or behavioral changes.

## What this is not

**CCE-79** — a deeper redesign of the Memory Execution scorer that addresses
the broader numerator composition problem (the original numerator summed
`/btw + /clear + /compact + /rewind` across three semantic classes) — is
**not part of this release**. v0.9.19 fixes the immediate data-integrity issue
(the cumulative/windowed blend). The per-field semantic redesign, target
recalibration (92 → 60), and `/rewind` demotion to a next-action-only probe
are filed as CCE-79 and remain open.

## Upgrade notes

No migration needed. Run `npm run assess` after pulling; the corrected counters
are computed at runtime from your existing `~/.claude/` and
`~/.claude/usage-data/` files.
