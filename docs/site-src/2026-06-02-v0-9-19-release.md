# v0.9.19 — Scoring honesty fix (CCE-78)

**Released:** 2026-06-02  
**PR:** [#120](https://github.com/theoju/claude-code-self-assessment/pull/120)  
**Breaking:** No

## What changed

### CCE-78: cumulative counter removed from windowed ratio numerator

The Memory Execution scorer had a silent accuracy problem: `run-assessment.mjs` was blending the cumulative all-time `~/.claude.json#btwUseCount` invocation count into `signalsSummary.btwCommandUses` via a `Math.max(maxProbe(s, "btwCommandUses"), cumulativeCounter)` call. The result fed the 30-day windowed Memory Execution ratio numerator.

The blend had two compounding defects:

1. **Wrong time window.** `btwCommandUses` is a 30-day session-coverage counter; `btwUseCount` is a lifetime invocation count. Mixing them into the same numerator meant the ratio's "recent posture" claim was backed by all-time account history.
2. **Wrong counter class.** Session-coverage counts how many sessions used a command (deduped per session); raw invocation counts how many times the command ran total. The ratio denominator is session-based, so a non-session-deduped numerator can overstate coverage for power users.

For a long-term user with high lifetime `/btw` usage, the blend pushed `btwCommandUses` well above what the 30-day window alone would report — inflating the Memory Execution score without reflecting recent behavior.

**The fix:**

- The `Math.max` blend at `run-assessment.mjs:134-137` is removed.
- A new `signalsSummary` field `cliBtwUseCountAllTime` exposes the raw lifetime counter separately, keeping it accessible for evidence text and adoption checks without polluting any ratio numerator.
- The `btw-side-channel` predicate in `app/data/rubric.json` for tips 33 and 54 is rerouted to `cliBtwUseCountAllTime`, which is the correct source for a binary "has the user ever adopted `/btw`?" check (a cumulative all-time field is fine for a ≥1 adoption gate; it's a ratio numerator where it's wrong).

The Memory Execution scorer body itself (`scripts/score.mjs`) was not using `btwCommandUses` in the ratio — it already called `maxProbe` directly — so the displayed Memory Execution radar score is unchanged by this fix. CCE-79 is filed as a follow-up for a deeper redesign of the Memory Execution numerator (restricting it to the two genuine 30-day session-coverage signals, `/clear` and `/compact`, with calibrated target adjustment).

### New CLAUDE.md hard rule: per-field semantic categorization

A new hard rule formalizes the analysis that caught this bug. Before adding any field to a ratio numerator (or summing multiple fields), classify each field on two independent axes:

| Axis | Classes |
| --- | --- |
| (a) Time window | windowed (e.g., 30-day) / cumulative (lifetime) |
| (b) Counter class | session-coverage (deduped per session) / raw invocation count |

If the new field's class on either axis differs from the existing numerator inputs, it doesn't belong in the same sum. Route it to a separate surface: evidence text, a binary adoption predicate, or a separate ratio with a matched denominator. The Memory Execution redesign in CCE-79 is the reference implementation.

### Plan archival

The landed plans for CCE-72 and CCE-76 are moved from `docs/superpowers/plans/` to the archived subdirectory. No functional change.

## Who is affected

Scorers that read `signalsSummary.btwCommandUses` directly will now see the 30-day windowed value only — not the `Math.max` of that and the lifetime counter. If you've forked the scorer or written custom predicates referencing `btwCommandUses`, verify the predicate semantics are satisfied by the windowed signal alone. For a binary "ever adopted `/btw`?" check, route the predicate to `cliBtwUseCountAllTime` instead.

The displayed scores in `assessment.json` are not affected for most users. For long-term users with high lifetime `/btw` usage and low recent 30-day `/btw` session coverage, the Memory Execution score may decrease slightly — reflecting true recent posture rather than all-time history.

## Follow-up: CCE-79

The Memory Execution numerator currently sums `/btw + /clear + /compact + /rewind`. CCE-78 fixed the blend problem for the `btwCommandUses` field, but the broader numerator still mixes fields across the two axes (cumulative vs windowed, raw count vs session-coverage). CCE-79 redesigns the scorer to restrict the ratio numerator to the two genuine 30-day session-coverage signals (`/clear` + `/compact`) and adjusts the rubric target from 92 to 60 to match the narrowed realistic ceiling. The per-field classification table is in `docs/superpowers/specs/2026-06-04-cce79-memory-scorer-redesign-design.md` §Context.
