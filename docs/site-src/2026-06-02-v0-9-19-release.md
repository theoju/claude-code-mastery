# v0.9.19 — Memory Execution scoring-honesty fix (CCE-78)

Released 2026-06-02. Bundles one scoring-integrity bugfix (PR #119 / CCE-78) and one housekeeping item (PR #118).

## What changed

### CCE-78: unblend cumulative `/btw` count from the Memory Execution ratio (PR #119)

The Memory Execution scorer measures how consistently you invoke context-management commands within the 30-day scoring window. Before this fix, the ratio numerator included a `Math.max(maxProbe(s, field), cliBtwUseCount)` blend that injected `cliBtwUseCount` — a **cumulative all-time invocation count** from `~/.claude.json` — into a position that the denominator treated as a **30-day windowed session-coverage** value.

The result: on accounts with long usage histories the numerator silently grew larger than the denominator's 30-day ceiling, overstating the Memory Execution score in proportion to account age rather than recent posture.

**The fix** (confirmed in `package.json` v0.9.19 wrapping PR #119):

- `cliBtwUseCount` is removed from the ratio numerator.
- A new field `cliBtwUseCountAllTime` is exposed as a **separate evidence-only surface** — it feeds display text and the tip-33 predicate (which is an adoption check, not a session-coverage ratio).
- The ratio numerator is now strictly composed of 30-day windowed session-coverage signals. The score reflects what you did in the window, not your lifetime `/btw` call history.

This is a **scoring-honesty fix**, not a feature. If your Memory Execution score drops after upgrading, the new number is accurate; the old one was inflated.

#### Why the blend was wrong

Two independent axes classify every counter field before it can join a numerator:

| Axis | `cliBtwUseCount` | `btwCommandUses` |
| --- | --- | --- |
| (a) Time window | cumulative all-time | 30-day windowed |
| (b) Counter class | raw invocation count | session-coverage (deduped per session) |

`cliBtwUseCount` differs from `btwCommandUses` on **both** axes. A `Math.max` blend looks ergonomic — it ensures the numerator is never under-counted when the per-session signal is sparse — but it conflates incompatible semantics and produces a ratio that drifts upward with account age. The rule is: if a field's axis classification differs from the existing numerator, route it to a separate surface.

### CCE-79 (follow-up, not in this release)

A broader redesign of the Memory Execution scorer — per-field semantic categorization of `/btw`, `/clear`, `/compact`, and `/rewind` before summing — is filed as CCE-79. This release only removes the confirmed-wrong blend; the redesign is separate work.

### PR #118: housekeeping

Archived the landed CCE-72 and CCE-76 plan documents. No scoring or UI changes.

## Upgrade notes

No migration required. Run `npm run assess` after pulling v0.9.19; `assessment.json` is rewritten on every run. If `assessment-history.json` shows a Memory Execution drop at this version boundary, that's the correction landing — not a regression.
