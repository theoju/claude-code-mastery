# v0.9.18 release notes

Released 2026-06-16. Bundles 13 PRs accumulated since v0.9.17 (2026-05-26).

## Headline changes

### All 12 dimensions are now Execution-scored (CCE-76)

Memory & Context Management and Terminal & Customization were the last two
dimensions flagged as _unmeasured_ on the Execution axis. Both now use
transcript-derived posture-command counters via
`withGates({ transcripts: true, universe: "interactive_or_unknown" })`.

The `interactive_or_unknown` session universe counts `interactive_cli +
unknown`-classified sessions — the same conservative fallback set used by the
learning and parallel scorers. Sessions classified as `sdk_orchestrated`,
`observer`, or `subagent` are excluded; those run with the SDK's defaults and
diluting posture ratios with them overstates the numerator.

The radar's italic-label / `¹` footnote treatment for unmeasured Execution dims
now applies only to dims whose scorer returns `gapReason !== null` (e.g. zero
interactive sessions in the lookback window). All 12 vertices get a real number
when session data exists.

### POSTURE / VOLUME command partition (CCE-71)

A canonical split now separates commands by whether their signal is
posture-sensitive or volume-sensitive:

- **Posture commands** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) — counted
  from transcripts only when `classifySessionKind` returns `interactive_cli` or
  `"unknown"`. Observer/SDK/subagent sessions are excluded because those sessions
  can't reflect user-driven posture choices.
- **Volume commands** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) —
  counted across every scanned session kind; autonomous-workflow signal is real
  regardless of which session type emitted it.

A fail-loud `assertCommandPartition` assertion runs at `_usage-data.mjs` module
load and enforces three invariants: disjointness between the two sets, no
unclassified commands, no dead classifications. A drift in either list fails
`npm run assess` at startup with a clear error before any scoring runs.

### Single-source predicate evaluator

`scripts/predicate.mjs` is now the canonical implementation of the
`satisfiedWhen` DSL. `app/lib/assessment.ts:evaluatePredicate` is a 1-line
passthrough re-export — never a copy. The test
`app/lib/__tests__/predicate-passthrough.test.ts` asserts reference equality;
a duplicate implementation fails CI.

### Pre-computed `rankedNextActions` in `assessment.json`

`scripts/rank-next-actions.mjs` computes and writes the sorted top-N
weight×deficit next-actions into `assessment.json` on every `npm run assess`
run. The `/self-assessment` slash command reads the pre-computed list from the
file rather than re-implementing the filter or ranking. Surfacing a
satisfied action as a TODO is a data-layer regression, not a consumer bug —
fix it in the scorer.

### `/progression` timeline gains three new dimension detectors (CCE-33)

The telemetry milestone walker now includes detectors for `scheduled`, `remote`,
and `verification` — the three dimensions that had no detector in v0.9.17 and
left the timeline frozen past the first-run config wall for heavy users of those
features. Detectors are self-dated from session `start_time` and use full
history (independent of `--insights-lookback`).

## Scoring impact

If you run `npm run assess:print` before and after updating, expect the Memory
and Terminal & Customization Execution columns to change from `—` (unmeasured)
to a real number the first time you have interactive session data in the
lookback window. The Execution overall changes accordingly. Platform Setup
scores are unaffected.

## Upgrade

```bash
git pull origin main
npm install
npm run assess:print
```

No config changes are required. `assessment.config.json` and `.env.local` are
untouched by this release.
