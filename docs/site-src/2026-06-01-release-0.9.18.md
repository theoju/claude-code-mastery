# Release v0.9.18

**Released**: 2026-06-01  
**PR**: [#117](https://github.com/theoju/claude-code-self-assessment/pull/117) (version bump; all feature work in PRs #99–#116)

v0.9.18 completes Execution scoring across all 12 dimensions, locks down
counter semantics so posture signals can't leak from observer and SDK sessions,
and hardens several cross-cutting contracts (predicate evaluator, next-action
pre-computation, journal format compatibility). The version bump is a single
`package.json` change; the 13 bundled PRs carry the substance.

## What changed

### Execution scoring: all 12 dimensions now measured

Memory & Context Management and Terminal & Customization were the last two
dimensions routing to `noTelemetry()` stubs. Both now have transcript-gated
ratio scorers that count posture-command invocations (`/clear`, `/compact`,
`/color`, `/voice`, `/focus`, etc.) only from `interactive_cli` and `unknown`
sessions — the same conservative universe used by Learning and Permissions
Execution. The radar's italic-label / ¹-footnote treatment for
"honestly-unmeasured" dimensions now applies only to dims whose scorer returns
`gapReason !== null` at runtime (e.g. zero interactive sessions in the scoring
window), rather than being hardcoded.

### Per-command POSTURE/VOLUME partition

`scripts/_usage-data.mjs` now maintains two disjoint sets: `POSTURE_COMMANDS`
(`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`,
`/rewind`, `/fewer-permission-prompts`) and `VOLUME_COMMANDS` (`/loop`,
`/schedule`, `/babysit`, `/go`, `/batch`). Posture commands are counted only
from `interactive_cli | unknown` sessions; volume commands are counted across
every scanned session kind. A `assertCommandPartition` boundary check runs at
module load and fails loudly if the sets drift (overlap, missing classification,
dead entry). This prevents observer and SDK sessions from inflating posture
ratios — the v0.9.17 regression where scheduled-dimension Execution dropped
from 75 to 63 was caused by over-broad session filtering; the per-command
partition is the correct shape.

### /ship journal format compatibility

The Stage 2 (verify-agent) and Stage 3 (simplify) dispatch counters in
`scripts/signals.mjs` now read all three journal format generations via
`stageRanInEntry()`: the singular `entry.stage` field, the legacy-numeric
`stages_run` array, and the current-string `stages_run` array. Before this
fix, run-counts for those stages were silently under-counted in older journal
files.

### Predicate evaluator consolidated

`scripts/predicate.mjs` is the single canonical DSL evaluator.
`app/lib/assessment.ts:evaluatePredicate` is now a 1-line passthrough
re-export. A new test (`app/lib/__tests__/predicate-passthrough.test.ts`)
asserts the two are reference-equal and fails CI on any duplication.
`assessment.json` now includes a pre-computed `rankedNextActions` field (top
10, weight×deficit ranked, satisfied predicates excluded). The
`/self-assessment` command reads from that field directly and must never
re-implement the filter or ranking.

### /progression timeline: new dimension detectors

The progression timeline gains telemetry-dated detectors for the three
dimensions that previously had no coverage: `scheduled`, `remote`, and
`verification`. Heavy usage in those areas now produces milestone entries
rather than a frozen timeline past the initial config wall. Existing detectors
are unchanged; the new ones follow the same `start_time`-dated pattern as
the nine original telemetry detectors.

### Supporting changes

- **Engineering-docs-agent plugin onboarding**: the MkDocs-based docs site
  (`docs/site-src/`) is now managed by the engineering-docs-agent plugin.
  Nightly builds deploy to GitHub Pages via the `docs-agent-pages.yml`
  workflow; every PR is verified by `docs-build-check.yml`.
- **`state.json` shape fix**: corrected a field-name mismatch in the ship
  skill's state file that caused Stage 0 to mis-read prior-run context.
- **Jira workflow: client-id auth**: the Atlassian MCP server integration
  migrated from OAuth token auth to client-id auth to match the updated
  Atlassian API requirements.

## Breaking changes

None. All scoring changes are additive; the two new Execution scorers replace
`noTelemetry()` stubs, so existing `assessment.json` files will now show
non-null Execution scores for Memory and Terminal dimensions where they
previously showed `—`. Trend history will show a step-change on the first run
after upgrading — this is expected, not a regression.

## Upgrade notes

Run `npm run assess` once after pulling. The new `rankedNextActions` field
is written automatically; no manual migration of `assessment.json` is needed.
If you have a custom scorer in `scripts/score.mjs` that calls `noTelemetry()`
for Memory or Terminal, you can keep it — the new scorers only replace the
built-in stubs, not user overrides.
