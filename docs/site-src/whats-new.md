## 2026-08-13 — Docs site is now published (mkdocs + GitHub Pages)

This page — and the rest of `docs/site-src/` — is now built into a
real, searchable site at
<https://theoju.github.io/claude-code-self-assessment/>, instead of
sitting as flat unpublished markdown. PR #121 flipped the
engineering-docs-agent integration from `framework: none` to
`framework: mkdocs` in `.engineering-docs-agent/config.yml`, which
activated the orchestrator's publish-verifier stage.

What changed under the hood:

- **New `mkdocs.yml` scaffold** at the repo root: Material theme,
  `search` + `awesome-pages` + `literate-nav` plugins (nav is driven
  by `docs/site-src/SUMMARY.md`), pinned dependencies in
  `requirements-docs.txt`.
- **Two GitHub Actions workflows**: `docs-agent-pages.yml` builds and
  deploys the site on every push to `main` that touches
  `docs/site-src/**`, `mkdocs.yml`, or `requirements-docs.txt`
  (`mkdocs build --strict` → `actions/upload-pages-artifact` →
  `actions/deploy-pages`); `docs-build-check.yml` runs the same
  `mkdocs build --strict` gate on PRs touching those paths, without
  deploying — so a broken link is a review-time failure, not a
  post-merge surprise.
- **The existing flat `docs/*.md` files moved into `docs/site-src/`**
  verbatim via `git mv`. Nine relative links inside
  `self-assessment.md` and `ship-pattern.md` that pointed outside the
  new `docs_dir` (into `.claude/` or `docs/superpowers/specs/`) were
  rewritten to absolute GitHub blob URLs, since mkdocs's strict mode
  rejects link targets outside `docs_dir`.

If you're contributing docs going forward: everything under
`docs/site-src/` is agent-editable and gets built by the workflow
above — verify locally with `mkdocs build --strict` before opening a
PR, the same check `docs-build-check.yml` runs in CI.
