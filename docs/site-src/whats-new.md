## 2026-06-02T08:43:14.528725+00:00
- PR #120: Release bump to v0.9.19 bundling two prior PRs: (1) a scoring-honesty fix (CCE-78) that removes the Math.max blend of the cumulative all-time `cliBtwUseCount` into the 30-day windowed `btwCommandUses` session-coverage field in `signalsSummary`, exposing the cumulative source as a new `cliBtwUseCountAllTime` field and rerouting the `btw-side-channel` predicate (tips 33 and 54) to it; and (2) housekeeping archival of the CCE-72 and CCE-76 plans that shipped in v0.9.18. Adds a new hard rule in CLAUDE.md on cumulative-vs-windowed counter semantics for scorer authors.
- PR #117: Release v0.9.18 version bump (package.json only) bundling 13 PRs landed since v0.9.17. Headline changes: (1) Memory and Terminal & Customization Execution scorers replace noTelemetry() stubs with real ratio scorers gated to interactive_or_unknown sessions, making all 12 dimensions Execution-scored. (2) Per-command POSTURE/VOLUME partition prevents observer/SDK sessions from inflating posture counters, with a fail-loud assertCommandPartition boundary check. (3) /ship Stage 2 and Stage 3 dispatch counting fixed across all three journal format generations. (4) scripts/predicate.mjs established as the single canonical DSL evaluator; pre-computed rankedNextActions land in assessment.json. (5) Progression timeline gains telemetry-dated detectors for scheduled, remote, and verification dimensions. Test suite grew from 647 to 666 tests.
- PR #116: Replaced the unmeasured (`noTelemetry()`) Execution scorers for the Memory & Context Management and Terminal & Customization dimensions with real ratio-based scorers backed by transcript posture-command coverage. The new scorers use a `withGates({ transcripts: true, universe: "interactive_or_unknown" })` gate, introduce a new `interactiveOrUnknownSessionsAnalyzed` denominator signal (interactive_cli ∪ unknown sessions), and switch `focusCommandUses` and `rewindCommandUses` from per-message to per-session-coverage counting. All twelve scoring dimensions now return numeric Execution scores; on the author's live system Memory landed at 16/100 and Customization at 3/100, surfacing previously hidden posture-command usage deficits. The full test suite grew from 647 to 666 passing tests, and the probe tracker, CLAUDE.md scoring model description, and methodology page were updated to reflect the new measurement basis.
- PR #114: Four shipped implementation plans were moved from docs/superpowers/plans/ into docs/superpowers/plans/archived/: 2026-05-26-runtime-adoption-probes.md (landed in #94), 2026-05-31-cce-33-progression-detectors.md (#108), 2026-05-31-per-command-partition.md (#110), and 2026-05-31-predicate-ranker.md (#104). Pure renames with no content changes; a routine plans-audit housekeeping pass.
- PR #113: Added a `stageRanInEntry(entry, legacyNumber, newName)` pure helper to `scripts/signals.mjs` that detects `/ship` Stage 2 (verify-agent) and Stage 3 (simplify) across all three `ship/journal.jsonl` format generations — singular `entry.stage`, legacy-numeric `stages_run`, and new-string `stages_run`. Previously `gatherShipJournal` only parsed `entry.stage === 2`, silently missing ~41% of journal entries (the entire `stages_run` cohort), causing `simplifyCommandUses` to score as 0 even for users with `/ship` deeply integrated. The fix also introduces a new `simplifyStageCount` counter, MAX-merges it into the `simplifyCommandUses` projection in `run-assessment.mjs`, and widens the production call-site lookback from a hard-coded 14 days to `insightsLookbackDays` (default 30), aligning journal-derived signals with transcript-derived ones. The probe-tracker spec and CLAUDE.md Conventions section were updated in the same PR.
- PR #111: Two-line edit to `.github/workflows/docs-agent-nightly.yml` migrating the docs-agent nightly CI workflow off deprecated `app-id` (from `actions/create-github-app-token@v3`) to the replacement `client-id` parameter, and moving `JIRA_EMAIL` from a repository Secret to a repository Variable (since it is a basic-auth username, not a credential).
- PR #110: Introduced a per-command posture-vs-volume partition in the transcript scanner (`scripts/_usage-data.mjs`). Posture commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are now counted only from `interactive_cli` and `unknown` sessions, preventing observer and SDK-orchestrated sessions from double-counting command invocations that were echoed from the primary session. Volume commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) continue to be counted across all session kinds, preserving autonomous-workflow signal. A fail-loud `assertCommandPartition` assertion runs at module load to catch future partition drift. Eleven new tests were added covering the partition helper and fixture-fed scorer paths. The design spec and implementation plan are committed under `docs/superpowers/`.
- PR #108: Added three new telemetry-dated milestone detectors to `scripts/progression.mjs` — `scheduled` (Boris tip 48, triggers on first `/loop`/`/schedule`/`/babysit` invocation), `remote` (tip 35, triggers on first `RemoteTrigger`/`PushNotification`/`SendMessage` tool use), and `verification` (tip 73, triggers on first `/go` invocation). This closes the `/progression` timeline coverage gap identified in CCE-33: the catalog previously tracked only 8 of 12 scored dimensions; all three previously un-detected dimensions now have telemetry-dated milestones that back-date to the user's true first adoption. A supporting change to `scripts/_usage-data.mjs::scanTranscriptModes` adds a per-session `commands: Set<string>` field to enable the two transcript-required detectors. The probe-tracker spec was also synced in the same PR per project convention, with a new Part 1 Progression layer and evidence updates for tips 35/48/73.
- PR #107: Closed two deferred Minor findings from the PR #106 review cycle. Added an explicit regression test for the internal `axisOrder()` mapping to assert that unknown axis values sort at tier 2 (adjacent to `"either"`), not ahead of `"platform"`. Extended the equality-predicate test to cover string cross-type coercion (`{ x: "5" }` → `true`), locking the `String(value) === lit` contract so a future strict-equality refactor cannot silently break predicates whose LHS values arrive as strings. Also dropped a stale `stash@{0}` WIP entry superseded by PRs #104 and #106. No production code was touched — diff is test-only across two test files.
- PR #106: Extracts a canonical predicate DSL evaluator (`scripts/predicate.mjs`) from the existing TypeScript implementation and collapses `app/lib/assessment.ts:evaluatePredicate` to a 2-line re-export passthrough, enforced by a CI equivalence test. Adds `scripts/rank-next-actions.mjs` which filters satisfied next-actions via the canonical evaluator and ranks the remainder by weight × deficit with a deterministic 5-tier tie-break. Wires the ranker into `scripts/run-assessment.mjs` so every `npm run assess` writes a pre-computed `rankedNextActions[10]` array into `assessment.json`. Simplifies the self-assessment SKILL.md to read from the pre-computed list, adds two CLAUDE.md hard rules pinning the contract, and adds 30 new tests including a named regression for the originating `babysit-loop` bug. TypeScript `Assessment` interface gains a `RankedNextAction` type threaded through `loadAssessment`.
- PR #104: PR #104 adds a 12-line `satisfiedWhen` DSL grammar block to the `/self-assessment` skill (`.claude/skills/self-assessment/SKILL.md`) documenting all 7 operator classes with a canonical-implementation pointer and a worked example. It also commits the design spec (`docs/superpowers/specs/2026-05-31-predicate-ranker-design.md`) and implementation plan (`docs/superpowers/plans/2026-05-31-predicate-ranker.md`) that blueprint the structural follow-up (PR 2 of 2), which will move filtering into `scripts/predicate.mjs` and pre-compute ranked next-actions into `assessment.json.rankedNextActions`.
- PR #102: Fixed a one-character schema mismatch in `.engineering-docs-agent/state.json`: the `dismissed_gap_flags` field was seeded as an empty JSON array (`[]`) by the bootstrap PR, but the plugin's state schema requires it to be an empty object (`{}`). The strict validator caused the orchestrator to exit with code 2 within ~0.2 s of startup, blocking all subagent dispatches on the docs-agent nightly run.
