- PR #106: Extracts a single canonical predicate DSL evaluator (scripts/predicate.mjs) from app/lib/assessment.ts, which now collapses to a re-export guarded by an equivalence test. Adds scripts/rank-next-actions.mjs, which filters already-satisfied rubric actions using the canonical evaluator and ranks the rest by weight×deficit with a deterministic tie-break; this is wired into run-assessment.mjs so every `npm run assess` writes a pre-computed `rankedNextActions[10]` into assessment.json. The self-assessment SKILL.md is simplified to just read that pre-computed array instead of re-implementing the filter/ranking logic itself. The TS `Assessment` interface and its loader were updated to declare and thread through `rankedNextActions`.
- PR #107: Added two regression tests to the predicate/ranker test suite: one pinning the internal axisOrder() tie-break mapping so an unknown axis value sorts into tier 2 rather than ahead of "platform", and one extending the `=` equality predicate test to assert string-vs-string coercion (`evaluatePredicate("x=5", { x: "5" })` returns true). Also dropped a stale git stash entry superseded by prior PRs. No production code was touched.
- PR #108: Added three new telemetry-dated milestone detectors to the /progression timeline — 'scheduled' (fires on first /loop, /schedule, or /babysit), 'remote' (fires on first RemoteTrigger/PushNotification/SendMessage tool use), and 'verification' (fires on first /go) — closing a coverage gap where those three of the twelve scored dimensions never produced a progression milestone even with heavy real usage. Also extended the transcript scanner (scanTranscriptModes) with an additive per-session commands set consumed by the new detectors, and synced the probe-implementation-status tracker spec per project convention.
- PR #110: Introduces a per-command partition between 'posture' commands (/color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) and 'volume' commands (/loop, /schedule, /babysit, /go, /batch) in the transcript-scanning scorer. Posture commands are now only counted from transcripts when the session classifies as interactive_cli or unknown, preventing observer and SDK-orchestrated sessions from inflating posture counters by echoing the primary session's command markup. Volume commands continue to be counted across all session kinds. A fail-loud assertCommandPartition check runs at module load to catch future drift (disjointness, missing/dead classification).
- PR #111: The nightly docs-agent GitHub Actions workflow was updated to stop using the deprecated `app-id` input in favor of `client-id` for GitHub App token generation, and to source `JIRA_EMAIL` from a repository Variable instead of a Secret (since it's a non-sensitive basic-auth username, not a credential).
- PR #113: Widened the /ship journal scoring logic (gatherShipJournal in scripts/signals.mjs) so that Stage 2 (verify-agent) and Stage 3 (simplify) dispatches are correctly credited across all three historical `~/.claude/ship/journal.jsonl` format generations, via a new pure helper `stageRanInEntry(entry, legacyNumber, newName)`. Previously only the singular `entry.stage === 2` format was read, silently missing ~41% of journal entries (the entire `stages_run` cohort), which caused `simplifyCommandUses` to read 0 even for heavy /ship users. The fix also widens the journal lookback window from a hardcoded 14 days to the configurable `insightsLookbackDays` (default 30) to align journal-derived signals with transcript-derived ones, and MAX-merges the new `simplifyStageCount` counter into the `simplifyCommandUses` projection in run-assessment.mjs.
