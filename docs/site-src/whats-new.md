The scorers consume transcript-derived posture-command coverage signals (counting `/clear`, `/compact`, `/color`, `/voice`, `/focus`, etc.) restricted to `interactive_cli ∪ unknown` sessions. With this change all 12 scoring dimensions now carry live Execution scores — the `noTelemetry()` fallback is no longer used by any dimension. Supporting changes include updated signal gathering in `_usage-data.mjs` and `insights-signals.mjs`, new test coverage in three new/updated test files, a refreshed `_fixtures.mjs` contract, and a methodology page update.

- PR #113: Introduced a pure helper function `stageRanInEntry(entry, legacyNumber, newName)` in `scripts/signals.mjs` that normalises detection of `/ship` stage execution across all three historical `~/.claude/ship/journal.jsonl` format generations (singular `entry.stage`, legacy-numeric `stages_run`, and new-string `stages_run`). This allows the scoring pipeline to correctly credit Stage 2 (verify-agent) and Stage 3 (simplify) dispatches regardless of which journal format version produced the entry. Tests were added to `gather-ship-journal.test.mjs` and `build-signals-summary.test.mjs`, the probe-implementation-status tracker was updated, design and plan docs were filed, and the ship-journal counter convention was documented in CLAUDE.md.
- PR #111: Two-line credential migration in the docs-agent nightly workflow: the GitHub App authentication parameter was renamed from `app-id` (backed by `secrets.DOCS_AGENT_APP_ID`) to `client-id` (backed by `vars.DOCS_AGENT_APP_CLIENT_ID`), and the `JIRA_EMAIL` environment variable was moved from `secrets.JIRA_EMAIL` to `vars.JIRA_EMAIL`. No logic was changed; this is a pure configuration update to align with the companion plugin PR (engineering-docs-agent#91).
- PR #110: Codifies a posture-vs-volume command partition in `scripts/_usage-data.mjs`. Posture commands (/clear, /compact, /btw, /simplify, /rewind, /voice, /color, /focus, /fewer-permission-prompts) are now counted only from `interactive_cli` and `unknown` session kinds, preventing observer/SDK-orchestrated/subagent sessions from double-counting user-issued commands. Volume commands (/loop, /schedule, /babysit, /go, /batch) continue to count across every session kind because autonomous-workflow signal is valid regardless of who emitted it. A fail-loud `assertCommandPartition` guard runs at module load to enforce disjointness and catch any future drift. The probe-implementation-status tracker and CLAUDE.md were updated to document the new partition as a hard rule.
- PR #108: PR #108 closes the `/progression` timeline coverage gap (CCE-33) by adding three new telemetry-dated milestone detectors — `scheduled`, `remote`, and `verification` — to `scripts/progression.mjs`. Before this change, 3 of 12 scored dimensions had no milestone detector, so substantial real usage in those dimensions produced no timeline entry and the progression page appeared frozen past the first-run wall. A supporting change extends `scripts/_usage-data.mjs::scanTranscriptModes` with a per-session `commands: Set<string>` field to give the detectors the input they need. New tests in `scripts/__tests__/progression.test.mjs` cover the added detectors, and spec/plan docs record the design rationale.
- PR #107: Added two regression tests to close post-code-review debt from PR #106: (1) an explicit test pinning the internal `axisOrder()` mapping so the sort order cannot silently regress, and (2) an extension to the `=` equality predicate test asserting that string `"5"` satisfies `x=5`. Also removes a leftover WIP stash reference preserved during the earlier PR #19 cleanup.
