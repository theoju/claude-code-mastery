## 2026-07-18T07:44:17.182729+00:00
- PR #101: Documented the /progression timeline's dual milestone-source architecture: telemetry-based milestones (scripts/progression.mjs) self-date from session start_time using a lookback independent of the scoring window, while config-based milestones (scripts/config-progression.mjs) stamp firstSeenAt at the first run that observes the signal and freeze it thereafter — explaining why all 8 config milestones share an identical first-run timestamp. Also records a coverage gap: 3 of 12 scored dimensions (scheduled, remote, verification) currently have no milestone detector, so real adoption in those areas doesn't appear on the timeline.
- PR #100: Onboards the claude-code-self-assessment repo onto the engineering-docs-agent plugin, adding the plugin's config (`.engineering-docs-agent/config.yml`), state tracking files (`state.json`, `state.example.json`), and a GitHub Actions nightly workflow (`docs-agent-nightly.yml`) that runs the docs agent on a schedule. The config declares `framework: none`, reflecting that this repo's docs are plain markdown with no static-site generator, after an earlier synthetic mkdocs scaffold (added to satisfy an older enum constraint) was removed once CCE-64 introduced `framework: none` as a first-class config value.
- PR #102: Fixed a one-character JSON bug in the engineering-docs-agent plugin's `.engineering-docs-agent/state.json` bootstrap file: `dismissed_gap_flags` was seeded as an empty array (`[]`) but the plugin's state schema requires it to be an object (keyed by `{owner}/{name}#{pr}`). Strict schema validation rejected the malformed state, causing the orchestrator to exit with code 2 within ~0.2s of starting.
- PR #104: Documents the canonical grammar for the `/self-assessment` skill's `satisfiedWhen` predicate DSL (a string form like `"loopCommandUses>=1"`) directly in SKILL.md, and adds a design spec + plan for a follow-up predicate-ranker that will centralize evaluation logic. The change is tactical: it fixes a recurring bug class where a model running the skill re-implements the filter against a wrong assumed shape (an object `{field, op, value}`), causing the evaluator to silently return null for every predicate and letting already-satisfied next-actions (e.g. `babysit-loop` despite `loopCommandUses=14`) wrongly surface as top priorities.
- PR #106: Consolidates the rubric's `satisfiedWhen` predicate evaluation into a single canonical implementation (`scripts/predicate.mjs`), with `app/lib/assessment.ts` reduced to a 1-line passthrough re-export enforced by a reference-equality test. Also pre-computes the ranked next-actions list (weight×deficit filtering against satisfied predicates) at assessment-write time and stores it as `assessment.json.rankedNextActions`, so downstream consumers (the `/self-assessment` skill) read the precomputed array instead of hand-implementing the filter/ranking logic themselves.
- PR #107: Added regression tests hardening the predicate-ranker's axis-ordering and tie-break logic (closing two Minor review findings deferred from PR #106): a test pinning the internal axisOrder() mapping so an unknown axis value sorts into tier 2 (adjacent to "either") rather than ahead of "platform", plus related rank-next-actions test coverage. No production code was touched.
- PR #108: Added three new telemetry-dated milestone detectors — scheduled (Boris tip 48, first /loop|/schedule|/babysit), remote (tip 35, first RemoteTrigger|PushNotification|SendMessage tool fire), and verification (tip 73, first /go) — to scripts/progression.mjs, closing the /progression timeline's long-standing coverage gap (previously only 8 of 12 scored dimensions had a detector). Extended scanTranscriptModes in scripts/_usage-data.mjs with a per-session commands Set to support the new command-based detection. Added a design spec and implementation plan, and updated the probe-implementation-status tracker to reflect the new detectors.
- PR #110: The scoring pipeline now partitions transcript-scanned slash commands into two classes, 'posture' commands (e.g. /color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) and 'volume' commands (e.g. /loop, /schedule, /babysit, /go). Posture commands are only counted from transcripts when the session's classifySessionKind resolves to interactive_cli or the conservative 'unknown' fallback, while volume commands continue to be counted across all scanned session kinds. A fail-loud assertCommandPartition check runs at module load to catch drift (disjointness, missing classification, dead classification).
- PR #111: Migrated the docs-agent nightly GitHub Actions workflow from a deprecated `app-id` secret to `client-id` (backed by a repo Variable) for the GitHub App token action, and switched `JIRA_EMAIL` from a repo Secret to a repo Variable since it's a basic-auth username rather than a credential. Requires the `DOCS_AGENT_APP_CLIENT_ID` and `JIRA_EMAIL` repo Variables to exist before merge.
- PR #113: Fixed the /ship journal scanner (gatherShipJournal in scripts/signals.mjs) so it credits Stage 2 (verify-agent) and Stage 3 (simplify) dispatches across all three historical journal.jsonl format generations, not just the current numeric-stage format. A new pure helper, stageRanInEntry(entry, legacyNumber, newName), normalizes the three detection shapes (singular entry.stage, legacy-numeric stages_run, new-string stages_run) into one Array.includes check. Previously the scanner only matched entry.stage === 2, silently missing the entire stages_run-array cohort (~41% of entries), which meant heavy /ship users could score simplifyCommandUses=0 despite real usage.
- PR #114: Moved four already-shipped planning documents (runtime-adoption-probes, cce-33-progression-detectors, per-command-partition, predicate-ranker) from docs/superpowers/plans/ into docs/superpowers/plans/archived/, with no content changes to any of the four files.

## 2026-06-02 — Docs site is now published, with a build gate

This page — and everything else under `docs/site-src/` — is now built
into a real site at
[theoju.github.io/claude-code-self-assessment](https://theoju.github.io/claude-code-self-assessment/)
instead of living as flat markdown you had to browse on GitHub.

- The `engineering-docs-agent` integration moved from `framework: none`
  to `framework: mkdocs` (`.engineering-docs-agent/config.yml`). The
  existing `docs/*.md` files migrated verbatim into `docs/site-src/`;
  no content changed, only the location.
- `mkdocs.yml` configures the Material theme plus `search`,
  `awesome-pages`, and `literate-nav` (nav is driven by
  `docs/site-src/SUMMARY.md`) — deliberately no Python-only plugins, to
  keep the build fast and the dependency surface small.
- `.github/workflows/docs-agent-pages.yml` builds and deploys the site
  to GitHub Pages on every push to `main` that touches
  `docs/site-src/**`, `mkdocs.yml`, or `requirements-docs.txt`.
- `.github/workflows/docs-build-check.yml` runs `mkdocs build --strict`
  on every PR that touches those same paths — a broken internal link or
  bad nav entry now fails CI instead of silently landing on `main` and
  only showing up after the Pages deploy.
- The `core` lens (this site) is the only lens configured so far
  (`lens_paths.core: docs/site-src/`); it doesn't yet have
  `architecture/` or `operations/` sections, so new pages land as flat
  root-level files until there's enough content to warrant subfolders.

[mkdocs migration decision](2026-06-02-mkdocs-migration.md) for the
full rationale, and
