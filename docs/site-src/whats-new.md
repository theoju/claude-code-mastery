A fail-loud boundary assertion at module load enforces disjointness and completeness of the partition, catching any future drift. Docs, specs, and the probe-implementation-status tracker were also updated in the same PR.

- PR #119: Unblends `cliBtwUseCount` (cumulative all-time `~/.claude.json#btwUseCount`) from `btwCommandUses` (30-day windowed transcript+history session-coverage) in the Memory Execution scorer. - PR #122: Post-merge documentation additions (133 lines across three files) recording durable operational lessons from the PR #121 / CCE-81 MkDocs upgrade deploy incident. Specifically: (1) the `actions/configure-pages@v6 enablement: true` gotcha — that option does not bootstrap GitHub Pages on first deploy due to token scope limits, requiring a one-time `gh api POST .../pages` call instead; (2) a zsh monitor-script trap — `status` and `pipestatus` are read-only built-ins in zsh, so monitor scripts must use bash or rename loop-local variables to avoid crashing; and (3) a general lesson that monitor-script exit failures should be confirmed against the watched system before treating them as real failures. Changes land in CLAUDE.md (project-wide conventions), the mkdocs upgrade spec, and the implementation plan.
