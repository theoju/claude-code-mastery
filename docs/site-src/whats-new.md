- PR #108: Adds three new milestone detectors to the progression timeline — `scheduled_first_loop`, `remote_first_mcp`, and `verification_first_rewind` — closing the coverage gap documented in CLAUDE.md (CCE-33). - PR #110: Introduces a per-command partition in `scripts/_usage-data.mjs` that divides slash commands into two sets: **POSTURE_COMMANDS** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) counted only from `interactive_cli` and `unknown` sessions, and **VOLUME_COMMANDS** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) counted across all session kinds. A `assertCommandPartition()` guard runs at module load to enforce disjointness and complete classification, failing CI on any drift. Companion unit tests cover partition boundary and regression cases.

- PR #113: Extended the ship-journal signal reader (`scripts/signals.mjs`) to correctly credit `/ship` Stage 2 (verify-agent) and Stage 3 (simplify) runs across all three journal format generations: the oldest singular `entry.stage` integer format, the intermediate `entry.stages_run` numeric-array format, and the latest `entry.stages_run` string-array format. - PR #119: Fixes a silent numerator-corruption bug in the Memory Execution scorer introduced in v0.9.18. The `run-assessment.mjs` entry point was Math.max-blending `cliBtwUseCount` (a cumulative all-time invocation counter from `~/.claude.json`) into `btwCommandUses` (a 30-day windowed session-coverage counter), causing the Memory Execution ratio numerator to be silently overstated for any account that had historically used `/btw` even when recent usage was zero. The fix exposes `cliBtwUseCount` as a separate `cliBtwUseCountAllTime` field in `signalsSummary`, removes the blend entirely, and reroutes Tip 33's predicate to a binary `cliBtwUseCountAllTime >= 1` habit-adoption check. The probe catalog and rubric are updated accordingly, and tracker counts are corrected.
