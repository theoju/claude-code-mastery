## 2026-06-02 — Docs site upgraded to MkDocs, published on GitHub Pages

This site now exists because of [PR #121](https://github.com/theoju/claude-code-self-assessment/pull/121).
Before it, `.engineering-docs-agent/config.yml` had `framework: none` —
docs lived as flat markdown under `docs/`, rendered only by GitHub's
blob viewer, and the nightly engineering-docs-agent run skipped its
`publish-verifier` stage with `verify_skipped` because there was
nothing published to check against.

The PR flips five fields in `.engineering-docs-agent/config.yml`
(`framework`, `whats_new_file`, `lens_paths.core`, `publishing.base_url`,
`publishing.build_workflow`), which activates that verifier stage for
real. It also:

- Moves the existing `docs/*.md` files verbatim into `docs/site-src/`
  (this file included), fixing the relative links that broke in the
  move.
- Adds `mkdocs.yml` — Material theme, `awesome-pages` +
  `literate-nav` (nav driven by `docs/site-src/SUMMARY.md`), plus
  `admonition`, `tables`, `pymdownx.superfences` (with a `mermaid`
  fence), and `pymdownx.details` extensions.
- Adds `.github/workflows/docs-agent-pages.yml`: on every push to
  `main` touching `docs/site-src/**`, `mkdocs.yml`, or
  `requirements-docs.txt`, it runs `mkdocs build --strict`, writes
  `site/.nojekyll`, and deploys via `upload-pages-artifact` +
  `deploy-pages`. This is separate from the existing nightly
  authoring workflow — the nightly opens `docs-agent/YYYY-MM-DD` PRs
  with new content, this one only builds and deploys what's already
  merged.
- Adds `.github/workflows/docs-build-check.yml` as a PR-level gate:
  the same `mkdocs build --strict` runs on every PR touching docs
  paths, so a broken link fails review instead of surfacing only
  after merge on the Pages workflow.

The published site lives at
<https://theoju.github.io/claude-code-self-assessment/>. Six other
files (README, CLAUDE.md, the `/self-assessment` and `/ship-pattern`
references, and others) had their `docs/*.md` path references
retargeted to `docs/site-src/`.

This was the intended path documented in the config's own comments —
`framework: none` was carrying a note to "swap framework to mkdocs and
fill in base_url + build_workflow" once a real scaffold existed. A
3-agent pre-execution validation (correctness, completeness,
test-rigor) caught the broken cross-tree links and the missing
build-time gate before merge, per CCE-81.

**Not yet in scope:** IA restructuring (the published site is
intentionally flat right now — no architecture/operations/archive
subsections under `docs/site-src/` for the `core` lens yet), and
content rewriting during the migration — the moved files kept their
original prose verbatim.
