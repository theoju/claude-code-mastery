Supporting change extends `scanTranscriptModes` in `scripts/_usage-data.mjs` with a per-session `commands: Set<string>` field to power the new detectors.
- PR #110: Codifies a posture-vs-volume command partition in the transcript-scanning layer used by the assessment scorer. Posture commands (/color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) are now counted from transcripts only when the session's classified kind is interactive_cli or the conservative unknown fallback, so observer and SDK-orchestrated sessions can no longer inflate posture counters by echoing the primary session's <command-name> markup. Volume commands (/loop, /schedule, /babysit, /go, /batch) continue to be counted across every scanned session kind, since autonomous-workflow signal from those commands is real regardless of which session emitted it. A fail-loud assertCommandPartition check runs at module load to catch future drift (disjointness, missing classification, dead classification).
