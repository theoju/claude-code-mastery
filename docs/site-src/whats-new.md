- PR #122: Post-merge documentation follow-up to PR #121 (mkdocs upgrade / CCE-81). Records three durable operational lessons from the actual deploy incident: (1) `actions/configure-pages@v6 enablement: true` does not self-bootstrap GitHub Pages on a first deploy — the workflow's GITHUB_TOKEN lacks admin scope and `permissions:` blocks can only restrict default scopes, never expand them; the fix is a one-time `gh api -X POST .../pages -f build_type=workflow` call. (2) Monitor shell scripts must avoid zsh's read-only built-ins `status` and `pipestatus`; assigning to either crashes the shell silently, and a monitor exiting non-zero with no event lines is almost always a script bug rather than evidence the watched system failed. (3) CCE-81 was filed post-execution rather than pre-planned. Changes land across CLAUDE.md (two new convention bullets), the mkdocs upgrade spec (POST-IMPLEMENTATION CORRECTION block under Gate 5), and the mkdocs upgrade plan (Post-merge outcomes section detailing three deviations).
