## 2026-07-08T07:56:00.448524+00:00
- PR #101: Documented the /progression timeline's dual milestone-source architecture in the project's CLAUDE.md: telemetry milestones (scripts/progression.mjs) are self-dated from session start_time across full history, while config milestones (scripts/config-progression.mjs) stamp firstSeenAt at first-observed time and freeze it, explaining why all 8 config milestones share the identical first-run timestamp 2026-05-09T08:37:16.111Z. Also records the known coverage gap where scheduled, remote, and verification dimensions have no telemetry detector, causing the timeline to appear frozen for those dims past the first run.
- PR #100: Bootstraps the engineering-docs-agent plugin onto this repository: adds the plugin's configuration file (`.engineering-docs-agent/config.yml`), an initial state-tracking file with a checked-in example, and a nightly GitHub Actions workflow that will keep the docs lenses refreshed automatically going forward.
- PR #102: Fixed a one-character JSON schema violation in the engineering-docs-agent plugin's internal state file (.engineering-docs-agent/state.json): dismissed_gap_flags was seeded as an empty array but the state schema requires an object keyed by {owner}/{name}#{pr}, causing the orchestrator to fail strict schema validation and exit with code 2 within ~0.2s of starting.
- PR #104: Updated the /self-assessment skill's SKILL.md to document the satisfiedWhen DSL grammar explicitly, and added a spec + implementation plan for a predicate-based next-action ranker. The change is a tactical fix (first of two PRs) addressing a bug class where the model running the skill hand-implemented the DSL filter using an incorrect object shape ({field, op, value}) instead of the actual string DSL (e.g. "loopCommandUses>=1"), causing the evaluator to silently return null for every predicate and produce unfiltered next-action rankings.
- PR #106: Introduces a single canonical predicate-evaluation DSL (scripts/predicate.mjs) shared by the Node-based scorer and the TypeScript app, with app/lib/assessment.ts reduced to a one-line passthrough re-export rather than a duplicate implementation. Also adds scripts/rank-next-actions.mjs, which pre-computes a filtered and weight×deficit-ranked top-N next-actions list and writes it into assessment.json.rankedNextActions, so downstream consumers (including the self-assessment skill) read pre-computed rankings instead of re-deriving them.
- PR #107: Added test hardening for the predicate-ranker test suite, closing two minor review findings deferred from PR #106 (predicate.test.mjs and rank-next-actions.test.mjs). No production code was touched.
- PR #108: Adds three new telemetry-dated milestone detectors to the progression timeline system: 'scheduled' (fires on first /loop, /schedule, or /babysit usage), 'remote' (fires on first RemoteTrigger/PushNotification/SendMessage tool invocation), and 'verification' (fires on first /go usage). This closes a longstanding coverage gap where the progression milestone catalog only tracked 8 of the 12 scored dimensions, leaving scheduled/remote/verification usage invisible on the /progression timeline even when heavily used.
- PR #110: Replaced the transcript command-counting logic in scripts/_usage-data.mjs with a per-command partition between 'posture' commands (/color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) and 'volume' commands (/loop, /schedule, /babysit, /go, /batch). Posture commands are now only counted from transcripts classified as interactive_cli or the conservative 'unknown' fallback, while volume commands continue to be counted across every scanned session kind. A fail-loud assertCommandPartition check runs at module load to catch drift (disjointness, missing classification, dead classification).
- PR #111: Migrated the docs-agent-nightly GitHub Actions workflow from deprecated `app-id`/`secrets.DOCS_AGENT_APP_ID` to `client-id`/`vars.DOCS_AGENT_APP_CLIENT_ID` for GitHub App token creation, and switched `JIRA_EMAIL` from a repo Secret to a repo Variable since it's a basic-auth username rather than a credential.
- PR #113: Extends the ship-journal credit logic (`stageRanInEntry` in scripts/signals.mjs) so that /ship Stage 2 (verify-agent) and Stage 3 (simplify) dispatches are recognized across all three historical `~/.claude/ship/journal.jsonl` format generations: the original singular `entry.stage` field, the legacy-numeric `stages_run` array, and the newer string-based `stages_run` array. Previously `gatherShipJournal` only matched `entry.stage === 2`, silently missing roughly 41% of journal entries (the entire `stages_run` cohort), which caused `simplifyCommandUses` to read 0 even for users with /ship deeply integrated into their workflow.
- PR #114: Four internal planning documents that had already shipped were moved from the active plans directory into an archived subfolder, closing out a housekeeping audit item. No functional or documentation content changed — it was a pure file relocation.

Both scorers consume transcript-derived posture-command coverage signals (interactive_cli ∪ unknown session gating) against a new `interactive_or_unknown` session universe, following the same pattern already used for the learning (★ Insight banner) and parallel (worktree usage) dimensions. Supporting changes span the signal-gathering layer (`scripts/_usage-data.mjs`, `scripts/insights-signals.mjs`), the scoring rules (`scripts/score.mjs`), the assessment runner, the methodology page, and the probe-implementation-status tracker.

- PR #122: Post-merge follow-up to PR #121 (CCE-81) that records three durable lessons learned from the actual GitHub Pages deploy incident: (1) `actions/configure-pages@v6`'s `enablement: true` does not actually bootstrap GitHub Pages on a first deploy because the default `GITHUB_TOKEN` lacks the required admin scope, requiring a one-time `gh api -X POST .../pages -f build_type=workflow` call or UI toggle before the first run; (2) monitor scripts polling CI/deploy status must avoid zsh's read-only `status`/`pipestatus` built-in parameter names (crashes the shell) by renaming loop locals or shebanging the script as bash. Adds two new CLAUDE.md Conventions bullets and a post-implementation-correction section to the mkdocs-upgrade spec and plan.

Flipped the corresponding vitest assertion into a regression guard against re-adding the line, appended a one-line resolution footer to the existing POST-IMPLEMENTATION CORRECTION block in the mkdocs-upgrade design spec, and trimmed the CLAUDE.md gotcha bullet to point at the plugin repo's CLAUDE.md as the durable explanation.
- PR #127: Added a new project-convention rule to CLAUDE.md: plan-step verification steps must invoke the actual consumer tool for a published artifact (e.g. `mkdocs build --strict`, `tsc --noEmit`, `ajv validate`) rather than a filesystem existence check like `test -f`.
