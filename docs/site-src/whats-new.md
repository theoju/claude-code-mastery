## 2026-06-05 — Docs site live at GitHub Pages (PR #121)

[theoju.github.io/claude-code-self-assessment](https://theoju.github.io/claude-code-self-assessment/)

**What shipped:**

- **`framework: mkdocs` in the engineering-docs-agent config.** Activates the
  publish-verifier stage of the nightly pipeline so future `whats-new.md`

  `mkdocs build --strict` on every PR — broken links fail the check before
  they merge.

  `docs/site-src/`. Nine broken relative links that crossed tree boundaries
  (into `.claude/` and `docs/superpowers/specs/`) were rewritten to absolute

- **21 new vitest cases** covering path migration, scaffold
  existence/content/SUMMARY resolution, JSON validity, and the config contract
  with negative tests.

**One operational note:** `configure-pages@v6` with `enablement: true` does
**not** bootstrap GitHub Pages on a first deploy — the `GITHUB_TOKEN` lacks the
admin scope required. Before the first deploy on a new host repo, run:

```bash
gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
```

Or use Settings → Pages → Source = "GitHub Actions" in the UI. After that one
step all subsequent push-triggered deploys work without intervention. The
`enablement: true` line was removed from the workflow in this same PR; the
workaround is documented in `CLAUDE.md` Conventions.
