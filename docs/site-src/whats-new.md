- PR #122: Post-merge documentation update following PR #121/CCE-81 that records two durable operational lessons in CLAUDE.md and the mkdocs-upgrade spec/plan docs: (1) `actions/configure-pages@v6`'s `enablement: true` does not actually bootstrap GitHub Pages on a first deploy because the workflow's default GITHUB_TOKEN lacks admin scope, requiring a one-time `gh api -X POST .../pages -f build_type=workflow` (or equivalent UI step) before the first deploy; and (2) monitor scripts must use bash rather than zsh because `status`/`pipestatus` are read-only zsh built-ins, and assigning to them inside a poll loop crashes the shell and silently masks successful deploys. The PR also appends post-merge outcome notes to the existing spec and plan documents. No source code changed — docs-only, +133 lines across 3 files.

The PR also flips the corresponding vitest assertion in `scripts/__tests__/docs-mkdocs-scaffold.test.mjs` into a regression guard, and updates `CLAUDE.md` plus the mkdocs-upgrade design spec to document the real fix (a one-time `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow` call before the first deploy).
- PR #127: Adds a new engineering convention to CLAUDE.md: plan-step verification must invoke the actual downstream consumer tool for a published artifact (e.g. `mkdocs build --strict`, `npx tsc --noEmit`, `ajv validate`) rather than relying on filesystem-only checks like `test -f`. The rule is being landed identically across three sibling repos (this one, advanced-data-import-system, and engineering-docs-agent).
