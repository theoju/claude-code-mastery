- PR #122: Post-merge follow-up to PR #121 / CCE-81 recording three durable operational lessons from the mkdocs GitHub Pages deploy incident: (1) `actions/configure-pages@v6 enablement: true` does not bootstrap Pages on a first deploy because the workflow GITHUB_TOKEN lacks the admin scope required — the fix is a one-time `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow` call or the equivalent Settings UI toggle; (2) monitor/polling scripts must avoid zsh's read-only built-ins `status` and `pipestatus` — assigning to either crashes the shell, and a monitor exiting non-zero with no event lines is almost always a script bug rather than a system failure; (3) `build_type=workflow` disables branch-deploy publishing. Two new convention bullets were added to CLAUDE.md, the mkdocs upgrade spec received a POST-IMPLEMENTATION CORRECTION block under Gate 5 with the actual recovery steps (gh api call + workflow dispatch), and the plan received a 'Post-merge outcomes' section documenting all three deviations from the planned rollout.
