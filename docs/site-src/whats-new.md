This is PR 1 of 2 (tactical documentation fix); a follow-up PR lands the code-level canonical evaluator.

- PR #108: Adds three new telemetry-dated milestone detectors to the `/progression` timeline system (`scripts/progression.mjs`): `scheduled` (fires on first `/loop`, `/schedule`, or `/babysit` use), `remote` (fires on first `RemoteTrigger`/`PushNotification`/`SendMessage` tool invocation), and `verification` (fires on first `/go` use). Also extends `scripts/_usage-data.mjs`'s `scanTranscriptModes` with a per-session `commands: Set<string>` field to support the new detection logic.
- PR #110: The transcript-based command counter now partitions slash commands into two classes: posture commands (/color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) are only counted from transcripts when the session's classified kind is interactive_cli or the conservative "unknown" fallback, while volume commands (/loop, /schedule, /babysit, /go, /batch) continue to be counted across every scanned session kind. A fail-loud assertCommandPartition check runs at module load to catch drift such as overlapping command lists or missing/dead classification arms.
- PR #111: Migrated the docs-agent-nightly GitHub Actions workflow's authentication configuration from repository Secrets to repository Variables: the GitHub App token step now uses `client-id` (vars.DOCS_AGENT_APP_CLIENT_ID) instead of the deprecated `app-id` (secrets.DOCS_AGENT_APP_ID), and the JIRA_EMAIL value is now sourced from vars.JIRA_EMAIL rather than secrets.JIRA_EMAIL, since it is a basic-auth username rather than a credential. Requires two new repo Variables (DOCS_AGENT_APP_CLIENT_ID and JIRA_EMAIL) to exist before merge.
