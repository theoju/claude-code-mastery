## 2026-08-11T08:13:18.459587+00:00
- PR #101: Documents the /progression timeline's dual milestone-source architecture in CLAUDE.md: telemetry-derived milestones (scripts/progression.mjs, self-dated from session start_time, independent of the insights lookback window) merged with config-derived milestones (scripts/config-progression.mjs, stamped with a first-seen-at-first-run timestamp rather than back-dated from mtimes/git). It also records a known coverage gap — 3 of 12 scored dimensions (scheduled, remote, verification) have no milestone detector, so heavy usage in those areas doesn't move the timeline.
- PR #100: Bootstraps the engineering-docs-agent plugin onto this repository by adding its config (`.engineering-docs-agent/config.yml`), example and live state files, and a nightly GitHub Actions workflow. The config is set to `framework: none` rather than a synthetic mkdocs scaffold, since this repo did not yet have a real docs site at the time.
- PR #102: Fixed a one-character JSON bug in the engineering-docs-agent plugin's `.engineering-docs-agent/state.json`: the `dismissed_gap_flags` field was seeded as an empty array `[]` but the plugin's state schema requires an object `{}`. The type mismatch was blocking the docs-agent nightly run.
- PR #104: Added a concise DSL grammar reference block to the `/self-assessment` skill's SKILL.md, plus a design spec and implementation plan for a predicate-ranker feature. This is the tactical first half of a two-PR fix for a recurring bug class where the model hand-reimplements the `satisfiedWhen` DSL filter instead of using the canonical evaluator.
- PR #106: Extracted the `satisfiedWhen` predicate DSL evaluator into a single canonical module (`scripts/predicate.mjs`) and added `scripts/rank-next-actions.mjs`, wired into `run-assessment.mjs` so every `npm run assess` run now pre-computes and writes a ranked top-10 `rankedNextActions[]` array into `assessment.json`. The TypeScript side (`app/lib/assessment.ts`) becomes a passthrough re-export of the canonical evaluator rather than a duplicate implementation.
- PR #107: Test-only cleanup that hardens the predicate-ranker test suite by addressing two Minor review findings left over from PR #106. Only test files (scripts/__tests__/predicate.test.mjs and scripts/__tests__/rank-next-actions.test.mjs) were touched; no production/source code changed.
- PR #108: Adds three new telemetry-dated milestone detectors to the /progression timeline system — `scheduled`, `remote`, and `verification` — closing the coverage gap where only 8 of 12 scored dimensions had detectors (leaving those three dimensions' timelines looking frozen despite real usage). Also extends `scanTranscriptModes` with a per-session `commands` Set field to support the new detection logic.
- PR #110: Introduces a strict posture-vs-volume partition for slash-command counting in the transcript scanner. Posture commands (e.g. /color, /voice, /btw, /clear, /compact) are now only counted from transcripts when the session's classified kind is interactive_cli or the conservative unknown fallback, preventing observer/sdk/subagent sessions from inflating posture-adoption signals. Volume commands (e.g. /loop, /schedule, /babysit, /go, /batch) continue to be counted across all scanned session kinds since autonomous-workflow signal is valid regardless of source. A fail-loud assertCommandPartition check now runs at module load to catch any future drift (disjointness, missing classification, dead classification) between the two command sets.
- PR #111: Updated the docs-agent-nightly GitHub Actions workflow's authentication configuration: replaced the deprecated `app-id` input with `client-id` for the GitHub App auth step, and moved `JIRA_EMAIL` from a repo Secret to a repo Variable since it is a basic-auth username rather than a credential.
- PR #113: Added a pure `stageRanInEntry` helper that detects whether /ship Stage 2 (verify-agent) or Stage 3 (simplify) ran for a given `~/.claude/ship/journal.jsonl` entry, correctly handling all three historical journal format generations (singular `entry.stage`, legacy-numeric `stages_run`, and new-string `stages_run`). Wired the helper into `scripts/signals.mjs` and `scripts/run-assessment.mjs` so Platform Setup scoring credits verify-agent and simplify dispatches regardless of which journal schema era wrote the entry.
- PR #114: Pure file-move: four already-shipped internal plan documents were relocated from docs/superpowers/plans/ into docs/superpowers/plans/archived/, with no content changes.

Supporting changes touch the methodology page's formula breakdown, transcript invocation scanning, and score/signals plumbing, plus new design spec and plan docs and fixture/test updates (16 new tests; full suite 647→666).
