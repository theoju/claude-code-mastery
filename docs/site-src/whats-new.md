- PR #122: Post-merge follow-up to PR #121 / CCE-81 recording three durable operational lessons from the mkdocs GitHub Pages deployment incident: (1) `actions/configure-pages@v6 enablement: true` does NOT bootstrap Pages on a repository's first deploy — the workflow's GITHUB_TOKEN lacks the required admin scope and `permissions:` blocks can only restrict scopes, never expand them; the fix is a one-time `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow` call or the equivalent Settings UI toggle; (2) monitor shell scripts must avoid assigning to zsh's read-only built-in variables `status` and `pipestatus`, or must shebang with `#!/usr/bin/env bash`; (3) a monitor process exiting non-zero with no emitted event lines is almost always a script crash, not evidence of the watched system failing — always confirm via direct query before treating it as a deployment failure.
