Simplifies the `/self-assessment` skill to read the pre-computed top-N entries from that field rather than re-implementing the filter itself. Adds a passthrough test asserting `app/lib/assessment.ts` re-exports the canonical evaluator without duplicating it.
- PR #107: Closed two Minor findings deferred from the PR #106 predicate-ranker review cycle. Changes are confined to test files only — `scripts/__tests__/predicate.test.mjs` and `scripts/__tests__/rank-next-actions.test.mjs`. No production code was touched.
- PR #108: Added three new telemetry-dated milestone detectors — `scheduled`, `remote`, and `verification` — to `scripts/progression.mjs`, closing the `/progression` timeline coverage gap that had left those three dimensions without any milestone markers. A supporting change extends `scripts/_usage-data.mjs::scanTranscriptModes` with a per-session `commands: Set<string>` field required by the new detectors. The progression timeline now covers all 12 scored dimensions instead of just 8.
- PR #110: Codifies the posture-vs-volume command partition in `scripts/_usage-data.mjs`. Posture commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are now counted from transcripts only when `classifySessionKind` returns `interactive_cli` or `unknown`, preventing observer and subagent sessions from inflating posture signal. Volume commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) continue to count broadly across all session kinds. A fail-loud `assertCommandPartition` runs at module load to enforce disjointness and completeness, catching future partition drift at startup rather than silently at runtime. The probe tracker and design spec are updated to reflect the new constraint.
- PR #111: Migrated the docs-agent-nightly GitHub Actions workflow from using a GitHub App `app-id` secret (`secrets.DOCS_AGENT_APP_ID`) to the newer `client-id` variable (`vars.DOCS_AGENT_APP_CLIENT_ID`), and moved the `JIRA_EMAIL` value from a repository secret (`secrets.JIRA_EMAIL`) to a repository variable (`vars.JIRA_EMAIL`).
