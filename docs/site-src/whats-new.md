## 2026-08-21T14:58:22.803241+00:00
- PR #196: Reworked the `commands` criterion in the CLAUDE.md health auditor (`scripts/claude-md-audit.mjs`). It previously scored 7 points per fenced code block containing a recognized tool keyword, which rewarded fragmenting commands into many small blocks and ignored commands documented in linked `.md` files. The new `countCommandLines()` counts actual executable command lines inside fences (stripping `$ ` prompts, skipping blanks/comments), and `extractDocRefs`/`resolveLinkedCommands` follow backticked-path, markdown-link, and `@import` references to linked docs (bounded to the target root, `.md` only, max 25 files, 256 KB each) and credit their command lines at half weight (capped at 10 of the 20 possible points). The recognized tool-token list was also broadened to cover Python-first tooling (`uv`, `pytest`, `ruff`, `mypy`, `alembic`, `prefect`) alongside existing tokens. `scoreFile()` gains an optional 4th `opts.linkedCommandLines` parameter (default 0); all existing 3-arg call sites are unaffected.
- PR #198: Lands a design spec (CCE-163) proposing a redesign of the Memory & Context Management Execution scorer, plus the telemetry survey and probe-catalog/test updates that back it — no scorer numerator change ships in this PR. The spec documents three measurement defects in the same class as CCE-161's fenced-block-counting bug, surveys 2,019 transcripts over a 30-day window, and finds graphify (127 sessions) as a real but currently uncounted usage signal, while noting claude-mem is passive hook capture (Platform posture, not Execution behavior). It recommends unioning session-coverage across /clear, /compact, graphify invocations, and claude-mem tool_use, gated against interactiveOrUnknownSessionsAnalyzed. One open decision — whether auto-compact configuration should be evidence-only (A) or suppress the manual-command expectation (B) — blocks implementation; the spec recommends (A).
- PR #199: Fixed the session-kind classifier (`classifySessionKind` in `scripts/_usage-data.mjs`) to fail closed on unrecognized transcript entrypoints. Previously it enumerated known SDK entrypoints and let anything else fall through to `unknown`, which is admitted by the `interactive_or_unknown` posture universe used by Memory & Terminal Execution scoring. An unhandled `sdk-py` entrypoint plus a 5-line scan bound (too shallow for transcripts that lead with `queue-operation`/`attachment` rows) caused 265 of 612 in-window sessions (43%) to misclassify as `unknown`, diluting the Memory Execution denominator to 353 against a true 93 (3.8x) and scoring a well-instrumented machine at 37/100. The fix inverts the classifier to an allow-list (`INTERACTIVE_ENTRYPOINTS = {cli, claude-desktop}`) so every other entrypoint resolves to `observer` or `sdk_orchestrated` instead of `unknown`, and raises the scan bound to `ENTRYPOINT_SCAN_BOUND = 200`.

## 2026-08-13 — Docs site is now published (mkdocs + GitHub Pages)

This page — and the rest of `docs/site-src/` — is now built into a
real, searchable site at
<https://theoju.github.io/claude-code-self-assessment/>, instead of
sitting as flat unpublished markdown. PR #121 flipped the
engineering-docs-agent integration from `framework: none` to
`framework: mkdocs` in `.engineering-docs-agent/config.yml`, which
activated the orchestrator's publish-verifier stage.

What changed under the hood:

- **New `mkdocs.yml` scaffold** at the repo root: Material theme,
  `search` + `awesome-pages` + `literate-nav` plugins (nav is driven
  by `docs/site-src/SUMMARY.md`), pinned dependencies in
  `requirements-docs.txt`.
- **Two GitHub Actions workflows**: `docs-agent-pages.yml` builds and
  deploys the site on every push to `main` that touches
  `docs/site-src/**`, `mkdocs.yml`, or `requirements-docs.txt`
  (`mkdocs build --strict` → `actions/upload-pages-artifact` →
  `actions/deploy-pages`); `docs-build-check.yml` runs the same
  `mkdocs build --strict` gate on PRs touching those paths, without
  deploying — so a broken link is a review-time failure, not a
  post-merge surprise.
- **The existing flat `docs/*.md` files moved into `docs/site-src/`**
  verbatim via `git mv`. Nine relative links inside
  `self-assessment.md` and `ship-pattern.md` that pointed outside the
  new `docs_dir` (into `.claude/` or `docs/superpowers/specs/`) were
  rewritten to absolute GitHub blob URLs, since mkdocs's strict mode
  rejects link targets outside `docs_dir`.

If you're contributing docs going forward: everything under
`docs/site-src/` is agent-editable and gets built by the workflow
above — verify locally with `mkdocs build --strict` before opening a
PR, the same check `docs-build-check.yml` runs in CI.
