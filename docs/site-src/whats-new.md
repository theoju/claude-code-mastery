## 2026-06-02 — Docs site is live (MkDocs upgrade, PR #121 / CCE-81)

The published docs site is now at **<https://theoju.github.io/claude-code-self-assessment/>**.

Previously the engineering-docs-agent ran in `framework: none` mode — it
could author pages but had no build or deploy path. PR #121 flips the config
to `framework: mkdocs` and wires up two CI workflows:

- **`docs-agent-pages.yml`** — push-to-main deploy pipeline. Builds the
  Material-theme MkDocs site and publishes to GitHub Pages via the
  `actions/deploy-pages` workflow.
- **`docs-build-check.yml`** — PR-level gate. Runs `mkdocs build --strict`
  on every pull request so broken links or bad nav entries fail before they
  reach `main`.

Existing docs under `docs/*.md` were migrated verbatim into `docs/site-src/`
with 9 broken relative links (pointing into `.claude/` paths) repaired in
the process. Scaffold files added: `mkdocs.yml`, `requirements-docs.txt`,
and the `docs/site-src/{index,SUMMARY,whats-new}.md` stubs this file is
part of.

**One-time GitHub Pages bootstrap caveat.** `actions/configure-pages@v6`
with `enablement: true` does _not_ bootstrap Pages on a first deploy — the
`GITHUB_TOKEN` lacks the admin scope for `POST /repos/.../pages` regardless
of the `permissions: pages: write` declaration. Before the first deploy you
need to run:

```bash
gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
```

Or enable it via Settings → Pages → Source → "GitHub Actions". Once Pages
exists the `enablement: true` line is a silent no-op; it was removed in
PR #125 / CCE-82. The `build_type=workflow` flag also disables branch-deploy
publishing, so the only route to the live site is through the
`deploy-pages@v5` artifact upload in `docs-agent-pages.yml` — which is what
you want for a MkDocs build.

**Test coverage.** 21 new vitest tests were added covering scaffold
existence, config contract, and path migration. All 689 tests pass.
