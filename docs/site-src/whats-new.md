Adds `scripts/rank-next-actions.mjs`, which filters out already-satisfied next-actions via the canonical evaluator and ranks the remainder by weight×deficit with a deterministic tie-break; this is wired into `scripts/run-assessment.mjs` so every `npm run assess` writes a pre-computed `rankedNextActions[10]` array into `app/data/assessment.json`. The `self-assessment` SKILL.md is simplified to just read `rankedNextActions[0..2]` instead of re-implementing the filter, and the TS `Assessment` interface now declares `rankedNextActions` end-to-end.
- PR #107: Added two regression tests closing review-debt items from the PR #106 predicate-ranker cycle: a test pinning the internal axisOrder() tie-break mapping so an unknown axis value sorts into tier 2 (adjacent to "either") rather than ahead of "platform", and an extension of the `=` equality predicate test asserting string-vs-string coercion (`evaluatePredicate("x=5", { x: "5" })` returns true). Also dropped a stale git stash entry from PR #19 that would have conflicted with PR #106's changes.
- PR #108: Added three new telemetry-dated milestone detectors to the /progression system — `scheduled` (fires on first /loop, /schedule, or /babysit), `remote` (fires on first RemoteTrigger/PushNotification/SendMessage tool use), and `verification` (fires on first /go) — closing the coverage gap where only 8 of 12 scored dimensions had progression milestones. Also extended the transcript scanner (`scanTranscriptModes`) with a per-session `commands` set that the two transcript-dependent detectors consume, and synced the probe-implementation-status tracker spec with the new Progression layer rows.
- PR #110: Introduced a fail-loud partition between 'posture' Slack/CLI commands (/color, /voice, /focus, /btw, /clear, /compact, /simplify, /rewind, /fewer-permission-prompts) and 'volume' commands (/loop, /schedule, /babysit, /go, /batch) inside the transcript scanner. Posture commands are now only counted from transcripts when the session classifies as interactive_cli or unknown, preventing observer and SDK-orchestrated sessions from double-counting a primary session's echoed <command-name> markup. Volume commands remain counted across every session kind. A new assertCommandPartition check runs at module load to catch drift (disjointness, missing classification, dead classification) between the two command sets.
- PR #111: Migrated the nightly docs-agent GitHub Actions workflow's authentication configuration: the GitHub App token step now uses `client-id: ${{ vars.DOCS_AGENT_APP_CLIENT_ID }}` instead of the deprecated `app-id: ${{ secrets.DOCS_AGENT_APP_ID }}`, and `JIRA_EMAIL` is now sourced from a repository Variable (`vars.JIRA_EMAIL`) instead of a Secret.
- PR #113: The scoring pipeline's `/ship` journal reader (`gatherShipJournal` in scripts/signals.mjs) is widened to credit Stage 2 (verify-agent) and Stage 3 (simplify) dispatches across all three historical `~/.claude/ship/journal.jsonl` format generations (singular `entry.stage`, legacy-numeric `stages_run`, new-string `stages_run`), via a new pure helper `stageRanInEntry(entry, legacyNumber, newName)`. `run-assessment.mjs` now MAX-merges a new `simplifyStageCount` counter into the `simplifyCommandUses` projection, and the production journal lookback window widens from a fixed 14 days to the configurable `insightsLookbackDays` (default 30) so journal-derived signals align with transcript-derived ones.
