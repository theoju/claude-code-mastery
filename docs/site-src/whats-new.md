- PR #122: Post-merge follow-up to PR #121 / CCE-81 that records three operational lessons from the mkdocs Pages deployment incident: (1) `actions/configure-pages@v6 enablement: true` does not bootstrap GitHub Pages on first deploy — the workflow token lacks admin scope and a manual `gh api` call is required; (2) monitor scripts must use bash, not zsh, because `status` and `pipestatus` are read-only built-in parameters in zsh and silently crash a poll loop with `read-only variable: status`; (3) plan-step verification must invoke the actual consumer tool (e.g. `mkdocs build --strict`) rather than `test -f`, because a file can exist on disk while violating the consumer's validity contract. Changes land in CLAUDE.md (+44 lines of new conventions), the mkdocs upgrade plan doc (+64 lines of recovery/post-merge notes), and the mkdocs upgrade design spec (+25 lines of post-implementation correction).
