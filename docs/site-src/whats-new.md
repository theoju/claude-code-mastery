## 2026-06-02 — Docs site moved to MkDocs

This page you're reading is the first artifact of it: the
project's docs went from a flat `docs/*.md` folder to a published
[Material-theme site](https://theoju.github.io/claude-code-self-assessment/),
built by [PR #121](https://github.com/theoju/claude-code-self-assessment/pull/121).

What changed:

- `docs/*.md` moved to `docs/site-src/` (the new `docs_dir` boundary
  MkDocs builds from), with every internal link repaired to match.
- `.engineering-docs-agent/config.yml` flipped from `framework: none`
  to `framework: mkdocs` — five fields in total (`framework`,
  `whats_new_file`, `lens_paths.core`, `publishing.base_url`,
  `publishing.build_workflow`).
- Two CI workflows landed: `docs-agent-pages.yml` builds and deploys
  the site on every push to `main` that touches `docs/site-src/**`,
  `mkdocs.yml`, or `requirements-docs.txt`; `docs-build-check.yml`
  runs `mkdocs build --strict` on every PR so a broken link fails CI
  instead of the live site.
- Six downstream path references — README, CLAUDE.md, `rubric.json`,
  the in-app `/docs/ship-pattern` page, and the `self-assessment`
  command/skill — were updated to point at the new locations.

The upgrade was validated by three independent pre-execution review
passes (correctness, completeness, test-rigor) before merge, which is
how a set of real blockers — links that assumed the old flat `docs/`
layout, a couple of missed path refs under `.claude/commands/`, and a
missing PR-level build gate — got caught and fixed rather than
shipped broken.

One rough edge from the rollout, for anyone repeating this pattern
on another repo: `actions/configure-pages@v6`'s `enablement: true`
does not actually bootstrap GitHub Pages on a first deploy — the
workflow's default `GITHUB_TOKEN` lacks the admin scope Pages
enablement needs, so the very first run fails until an admin runs
`gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow`
once by hand. That line was later removed as a no-op ([CCE-82](https://github.com/theoju/claude-code-self-assessment)).
See `CLAUDE.md` for the full recovery notes if you hit the same
`Resource not accessible by integration` error.
