**One-time host onboarding note:** `actions/configure-pages@v6` with
`enablement: true` does **not** bootstrap GitHub Pages on a first deploy — the
`GITHUB_TOKEN` lacks the admin scope needed to call `POST /repos/.../pages`
even with `permissions: pages: write` declared. The first run failed with
`Resource not accessible by integration`. Fix: run

```bash
gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
```

from an admin login (or use Settings → Pages → Source = "GitHub Actions" in
the UI) before the first workflow dispatch. The `enablement: true` line was
removed in PR #125 / CCE-82. The `build_type=workflow` setting is durable —
subsequent push-triggered runs work cleanly with no further admin action.
