## 2026-06-02 — Docs site now published via mkdocs

This site is the result: docs now build with mkdocs (Material theme)
and publish to
[theoju.github.io/claude-code-self-assessment](https://theoju.github.io/claude-code-self-assessment/)
on every push to `main` that touches `docs/site-src/**`, `mkdocs.yml`,
or `requirements-docs.txt` — see
[`docs-agent-pages.yml`](https://github.com/theoju/claude-code-self-assessment/blob/main/.github/workflows/docs-agent-pages.yml).
A companion PR-level gate,
[`docs-build-check.yml`](https://github.com/theoju/claude-code-self-assessment/blob/main/.github/workflows/docs-build-check.yml),
runs `mkdocs build --strict` on every pull request, so a doc link that
resolves on disk but not inside `docs_dir` now fails CI instead of
shipping broken.

What moved: the flat `docs/*.md` files migrated into `docs/site-src/`
via `git mv`, with 9 broken relative links repaired in the process and
cross-tree references (into `.claude/`, `app/`, `scripts/`) rewritten
to absolute GitHub blob URLs, since those targets sit outside
`docs_dir` and can't be relative mkdocs links.
`.engineering-docs-agent/config.yml` flipped from `framework: none` to
`framework: mkdocs`, with `lens_paths.core: docs/site-src/` — that's
what turns on the publish-verifier stage of the nightly run going
forward, checking that `docs-agent-pages.yml` actually ran and that
each lens page is reachable at the published `base_url`.

If you had bookmarks into the old flat `docs/` layout, update them —
those paths no longer resolve. The canonical source is
`docs/site-src/`; the browsable, searchable version is the Pages URL
above.
