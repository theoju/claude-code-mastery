**One bootstrap caveat to know about:** `actions/configure-pages@v6`
with `enablement: true` cannot actually create GitHub Pages on a
first deploy — the default `GITHUB_TOKEN` lacks the required admin
scope. If you fork this repo and see a `Resource not accessible by
integration` failure on the first workflow run, bootstrap Pages
manually before re-running:

```bash
gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
```

After that one-time call, every subsequent push-triggered deploy runs
cleanly and the `enablement: true` line is a silent no-op. The
`docs-agent-pages.yml` workflow has had the line removed since PR #125
to avoid the confusion entirely.
