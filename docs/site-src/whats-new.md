## 2026-06-02 — Docs site published to GitHub Pages

This site — the one you're reading — is new. PR #121 flipped this
repo's engineering-docs-agent integration from `framework: none` to
`framework: mkdocs` and stood up a published Material-theme site at
<https://theoju.github.io/claude-code-self-assessment/>.

What changed under the hood:

- The flat `docs/*.md` files moved into `docs/site-src/`, with
  cross-tree links repaired for the new layout (see
  [`docs/site-src/SUMMARY.md`](SUMMARY.md) for the nav).
- Two CI workflows now guard the site: `docs-build-check.yml` runs
  `mkdocs build --strict` on every PR that touches `docs/site-src/**`,
  `mkdocs.yml`, or `requirements-docs.txt`, and `docs-agent-pages.yml`
  builds and deploys the same site to Pages on every push to `main`
  that touches those paths.
- `.engineering-docs-agent/config.yml` now points `whats_new_file` at
  this file, `lens_paths.core` at `docs/site-src/`, and declares the
  published `base_url` and `build_workflow` — the fields the
  publish-verifier stage checks on each nightly run.
- README, CLAUDE.md, `app/data/rubric.json`, the in-app
  `/docs/ship-pattern` page, and the `/self-assessment` command and
  skill were all retargeted to the new `docs/site-src/` paths so
  in-repo links don't rot.
- 21 new vitest cases in `scripts/__tests__/` cover the migration,
  the mkdocs scaffold, and the config contract.

Why now: the config had already documented this as the intended
upgrade path ("swap framework to mkdocs and fill in base_url +
build_workflow"). This PR executes it after a spec, a plan, and a
3-agent pre-execution review surfaced and fixed real blockers first —
broken `.claude/`-relative links, missed path references inside
`.claude/commands/`, and a missing PR-level build gate that would
otherwise have let broken links land on `main` before anyone noticed.

Landing this also turns on the engineering-docs-agent's
publish-verifier stage for this host, which checks after each nightly
run that `docs-agent-pages.yml` actually ran for the current `main`
HEAD and that the published pages are reachable.

Two things from the PR were still unverified as of merge and are
worth a second look before you treat the site as fully proven out:
the Pages auto-deploy actually firing on a push to `main`, and the
first nightly engineering-docs-agent run under `framework: mkdocs`
completing cleanly.
