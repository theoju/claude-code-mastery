The PR also pre-computes `rankedNextActions` (the filtered, weight×deficit-sorted top next-actions) into `assessment.json` via `scripts/rank-next-actions.mjs` during `npm run assess`, and updates the `/self-assessment` skill (SKILL.md) plus CLAUDE.md to read that pre-computed list rather than hand-rolling the satisfiedWhen filter or ranking logic themselves. Adds test coverage across predicate evaluation, ranking, and run-assessment integration.

Previously the milestone catalog only covered 8 of the 12 scored dimensions; this lands detectors for the remaining three. Supporting changes extend scripts/_usage-data.mjs and add coverage in scripts/__tests__/progression.test.mjs.
- PR #110: Introduces a per-command partition in the transcript-scanning layer (`scripts/_usage-data.mjs`) that separates 'posture' commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) from 'volume' commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`). Posture commands are now only counted from transcripts when `classifySessionKind` returns `interactive_cli` or `unknown`, while volume commands continue to be counted across all scanned session kinds. A fail-loud `assertCommandPartition` check runs at module load to catch drift (disjointness, missing classification, dead classification).

Introduces a pure `stageRanInEntry(entry, legacyNumber, newName)` helper that normalizes across the singular-stage, legacy-numeric stages_run, and new-string stages_run generations.

- PR #119: Fixed a scoring bug in the Memory & Context Management Execution scorer: `signalsSummary.btwCommandUses` was previously computed via `Math.max` blending `~/.claude.json`'s cumulative all-time `btwUseCount` with the 30-day windowed transcript+history session-coverage count for `/btw` usage. This conflated two independent semantic axes — time window (windowed vs. cumulative) and counter class (session-coverage vs. raw invocation count) — which silently inflated the windowed ratio and made it drift upward with account age rather than reflecting recent posture. The fix exposes the cumulative count separately as `cliBtwUseCountAllTime` and reroutes the tip 33 predicate to use it directly, leaving `btwCommandUses` as a pure windowed session-coverage signal.

Added a PR-level `mkdocs build --strict` gate (`docs-build-check.yml`) and a publish workflow (`docs-agent-pages.yml`), migrated the existing flat `docs/*.md` files verbatim into `docs/site-src/`, and introduced `mkdocs.yml` + `requirements-docs.txt` as the new docs toolchain.
- PR #122: Recorded three post-merge lessons learned from the PR #121 / CCE-81 GitHub Pages deployment incident: (1) `actions/configure-pages@v6`'s `enablement: true` does not actually bootstrap Pages on a first deploy because the workflow's default GITHUB_TOKEN lacks admin scope, requiring a one-time `gh api -X POST .../pages` call (or manual UI toggle) before the first run; (2) once Pages exists via `build_type=workflow`, `enablement: true` becomes a permanent no-op and was removed from the workflow; and (3) monitor scripts polling deploy status must be run under bash rather than zsh, since `status`/`pipestatus` are read-only zsh parameters that crash a poll loop on assignment, silently masking successful deploys. Updates land in CLAUDE.md's Conventions section plus post-implementation-correction notes in the mkdocs upgrade spec and plan docs.

Updated the corresponding vitest assertion into a regression guard against re-adding the line, and appended a one-line resolution footer to the existing POST-IMPLEMENTATION CORRECTION block in the mkdocs-upgrade design spec.
