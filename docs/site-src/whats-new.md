- PR #104: Added a 12-line DSL grammar block to `.claude/skills/self-assessment/SKILL.md` documenting all 7 `satisfiedWhen` operator classes, as a tactical fix for a recurring bug class where a model running the skill hand-wrote its own predicate filter (incorrectly assuming `satisfiedWhen` was an object rather than the canonical string DSL), causing the evaluator to return null for every predicate and silently defeat next-action filtering. The PR also ships the accompanying design spec and implementation plan for a follow-up structural fix (a dedicated predicate-ranker).
- PR #106: Extracts a single canonical predicate/DSL evaluator (scripts/predicate.mjs) that both the assessment scripts and the TypeScript app layer now share — app/lib/assessment.ts's evaluatePredicate collapses to a passthrough re-export, guarded by a reference-equality test so the two implementations can never diverge again. Adds scripts/rank-next-actions.mjs, which filters out already-satisfied rubric actions and ranks the rest by weight × deficit with a deterministic 5-tier tie-break; run-assessment.mjs now wires this in so every `npm run assess` writes a pre-computed top-10 rankedNextActions array into assessment.json. SKILL.md is simplified to consume that pre-computed array instead of re-implementing the filter, and two new CLAUDE.md hard rules codify both the single-evaluator-source rule and the no-hand-rolled-ranking rule.
- PR #107: Added regression test coverage in the predicate-ranker test suite: a pinned test for the internal `axisOrder()` mapping, and an extended equality (`=`) test asserting cross-type-coercion behavior. Also removed a stale stash entry made obsolete by two earlier PRs. No production code was modified.
- PR #108: Added three new telemetry-dated milestone detectors — scheduled, remote, and verification — to scripts/progression.mjs, closing the /progression timeline's coverage gap for CCE-33 (previously only 8 of 12 scored dimensions had a detector). Supporting change extends scanTranscriptModes with a per-session commands: Set<string> field to power the new detectors. The probe-implementation-status tracker spec was synced in the same PR per the repo's hard rule, and live verification confirmed all three milestones fire with backdated telemetry timestamps.
- PR #110: Introduced a strict partition between 'posture' Claude Code commands (like /color, /clear, /compact, /rewind) and 'volume' commands (like /loop, /schedule, /go) when scoring usage from transcripts. Posture commands are now only counted toward scoring when the originating session is classified as interactive_cli or unknown, so observer and SDK-orchestrated sessions no longer artificially inflate posture-related scores. Volume commands continue to be counted across all session kinds since autonomous-workflow signal is valid regardless of session type. A new assertCommandPartition check runs at module load to fail loudly if a command is ever added to both categories or left unclassified.
- PR #111: Updated the docs-agent-nightly GitHub Actions workflow to replace the deprecated `app-id` input with `client-id`, and moved `JIRA_EMAIL` from `secrets` to `vars` since it is a basic-auth username rather than a credential.
- PR #113: Ship-journal stage-credit counting now recognizes /ship Stage 2 (verify-agent) and Stage 3 (simplify) dispatches across all three historical journal formats (singular entry.stage, legacy-numeric stages_run, and new-string stages_run). A new pure helper, stageRanInEntry, collapses the three detection paths into one strict-equality check, and run-assessment.mjs MAX-merges the journal-derived counter into simplifyCommandUses.
- PR #114: Moved four already-shipped implementation plans from docs/superpowers/plans/ into docs/superpowers/plans/archived/. This is a pure file-rename with no content changes.

Both switch to a ratio-based `withGates({ transcripts: true, universe: "interactive_or_unknown" })` scorer, and the `/focus` and `/rewind` command counters were unified from raw total-invocation counts to session-coverage counts (deduped per session, matching the posture-command convention used elsewhere). A new `interactiveOrUnknownSessionsAnalyzed` denominator and an `interactive_or_unknown` universe option were added to support these ratios.

Added scaffold, config, and path-migration test coverage, and updated the rubric/self-assessment docs to reflect the new docs site.
- PR #122: Post-merge documentation update recording two operational lessons discovered after PR #121/CCE-81 shipped: (1) GitHub's `actions/configure-pages@v6` action's `enablement: true` flag does not actually bootstrap Pages on a repo's first deploy because the default GITHUB_TOKEN lacks admin scope, requiring a manual `gh api POST .../pages` call or UI toggle before the first workflow run; and (2) monitor scripts polling CI/deploy status must avoid zsh's read-only built-in parameters `status` and `pipestatus`, which crash the shell if assigned to inside a loop.
