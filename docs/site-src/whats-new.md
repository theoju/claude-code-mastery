## 2026-06-03T08:47:01.922977+00:00
- PR #121: Upgraded the engineering-docs-agent integration from 'framework: none' to 'framework: mkdocs', publishing a Material-theme docs site at https://theoju.github.io/claude-code-self-assessment/. The change adds two GitHub Actions CI workflows — a push-to-main deploy pipeline (docs-agent-pages.yml) and a PR-level mkdocs build --strict gate (docs-build-check.yml) — migrates existing flat docs/*.md files into docs/site-src/ with nine broken relative links repaired, flips the agent config.yml to activate the publish-verifier stage, and adds 21 new Vitest test cases covering path migration, scaffold integrity, and config contract validation.
- PR #120: Version bump to v0.9.19, cutting a release that bundles two previously merged PRs: PR #119 (fix scoring honesty by unblending `cliBtwUseCount` from `btwCommandUses` — CCE-78, preventing ratio inflation in the Memory Execution scorer) and PR #118 (archiving completed plans for CCE-72 and CCE-76). The only file directly changed in this PR is `package.json`.
- PR #119: The scoring pipeline's `btwCommandUses` signal no longer blends the cumulative all-time `~/.claude.json#btwUseCount` counter (via Math.max) into the 30-day windowed session-coverage counter. A new separate `signalsSummary` field `cliBtwUseCountAllTime` now carries the cumulative source, and the `btw-side-channel` predicate (Boris tips 33 and 54) is rerouted to target `cliBtwUseCountAllTime>=1` rather than the windowed `btwCommandUses`. The Memory Execution score is intentionally unchanged (16→16); the fix prevents future score drift as account age grows. CLAUDE.md gained a hard rule documenting the cumulative-vs-windowed counter semantics and the per-field semantic partition to prevent recurrence.
- PR #118: Two implementation plan documents for already-shipped features (CCE-72 /ship journal stage-credit and CCE-76 Memory+Customization Execution scorers) were moved via `git mv` from `docs/superpowers/plans/` into `docs/superpowers/plans/archived/`. No content was altered; this is a pure housekeeping archival step following the v0.9.18 release.
- PR #117: Release v0.9.18 bumps package.json and formally bundles 13 PRs landed since v0.9.17 (2026-05-26). Headline changes include: new Execution scorers for the Memory and Terminal & Customization dimensions (CCE-76 / PR #116); a per-command POSTURE/VOLUME partition that corrects scoring fidelity by restricting posture-command counting to interactive_cli/unknown sessions while preserving autonomous-workflow signal for volume commands (CCE-71 / PR #110); /ship Stage 2/3 credit detection across all three journal-format generations (CCE-72 / PR #113); a canonical predicate evaluator with pre-computed rankedNextActions in assessment.json (PR #106); and telemetry-dated detectors for the /progression timeline (CCE-33 / PR #108).
- PR #116: Replaced the `noTelemetry()` placeholder stubs for the Memory & Context Management and Terminal & Customization Execution scorers with real `withGates({ transcripts: true, universe: "interactive_or_unknown" })` ratio scorers. The new scorers consume MAX-merged posture-command session-coverage counters (/btw, /clear, /compact, /rewind for Memory; /color, /voice, /focus for Customization) drawn from transcripts filtered to interactive_cli and unknown session kinds. As a prerequisite, `focusCommandUses` and `rewindCommandUses` were unified from per-message to per-session counters, and a new `interactiveOrUnknownSessionsAnalyzed` field was added to insights-signals. This completes all 12 dimension Execution scorers (CCE-76), turning two formerly italic-unmeasured radar vertices into real scored vertices.
- PR #114: Moved four shipped plan files from `docs/superpowers/plans/` into `docs/superpowers/plans/archived/` as part of a plans-audit housekeeping pass. The four plans cover runtime-adoption probes, CCE-33 progression detectors, per-command partition, and predicate ranker — all previously landed. No content was modified; this is a pure file-move archival operation.
- PR #113: Fixed the /ship workflow stage counter to correctly credit Stage 2 (verify-agent) and Stage 3 (simplify) dispatches across all three ship journal format generations: singular `entry.stage`, legacy-numeric `stages_run`, and new-string `stages_run`. The `stageRanInEntry()` helper in `scripts/signals.mjs` now detects stage execution regardless of which journal format generation produced the entry. The probe tracker spec (`docs/superpowers/specs/2026-05-25-probe-implementation-status.md`) was updated in the same PR, a new design spec and plan were added, and test coverage was extended for both `build-signals-summary` and `gather-ship-journal`.
- PR #111: Two-line edit to `.github/workflows/docs-agent-nightly.yml` migrating the GitHub App authentication field from `app-id` to `client-id: ${{ vars.DOCS_AGENT_APP_CLIENT_ID }}` and moving the `JIRA_EMAIL` value from a repository secret (`secrets.JIRA_EMAIL`) to a repository variable (`vars.JIRA_EMAIL`).
- PR #110: Codifies the posture-vs-volume command partition in the transcript scanner (`scripts/_usage-data.mjs`). Posture commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are now gated to `interactive_cli ∪ unknown` sessions only, preventing observer-session markup from double-counting user invocations. Volume commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) continue to be counted across all session kinds so autonomous-workflow signal is preserved. A fail-loud `assertCommandPartition` runs at module load to enforce disjointness and completeness of the two sets going forward.
- PR #108: Added three new telemetry-dated milestone detectors — scheduled, remote, and verification — to scripts/progression.mjs, closing the /progression timeline coverage gap tracked as CCE-33. Previously, 8 of 12 scored dimensions had detectors; the scheduled, remote, and verification dimensions had none, so heavy real usage in those areas produced no milestones and the timeline appeared frozen after the first-run wall. The change also extends scripts/_usage-data.mjs with the supporting signal extraction, adds tests in scripts/__tests__/progression.test.mjs, updates the probe implementation status tracker (docs/superpowers/specs/2026-05-25-probe-implementation-status.md), and introduces a design spec and plan doc under docs/superpowers/specs/ and docs/superpowers/plans/.
- PR #107: Pure test-suite housekeeping following PR #106: tightened two minor review findings in the predicate and rank-next-actions test files. No production code was touched and no user-visible behaviour changed.
- PR #106: Extracted a canonical DSL predicate evaluator into `scripts/predicate.mjs` and made `app/lib/assessment.ts` a thin passthrough re-export of it (enforced by a CI test). Added `scripts/rank-next-actions.mjs` to filter and sort next-actions by weight × deficit, and wired it into `scripts/run-assessment.mjs` so every `npm run assess` writes a pre-computed `rankedNextActions[10]` array into `app/data/assessment.json`. Updated the self-assessment skill and CLAUDE.md to direct consumers to read the pre-computed list rather than re-implementing the ranking logic.
- PR #104: Added a 12-line DSL grammar block to `.claude/skills/self-assessment/SKILL.md` documenting all 7 `satisfiedWhen` operator classes (truthy/falsy path checks, numeric comparisons, equality/membership, conjunction, and version checks). Also introduced a design spec and implementation plan for a two-PR 'predicate-ranker' initiative: PR 1 (this PR) is the tactical stopgap; PR 2 will extract `evaluatePredicate` to `scripts/predicate.mjs`, pre-compute ranked next-actions in `run-assessment.mjs`, and write them to `assessment.json.rankedNextActions` so the skill becomes a trivial reader.
- PR #102: Corrected a one-character JSON schema error in `.engineering-docs-agent/state.json`: the `dismissed_gap_flags` field was bootstrapped as an empty array (`[]`) instead of an empty object (`{}`). The plugin's state schema requires this field to be a JSON object; the incorrect type caused the engineering-docs-agent nightly run to fail on startup.
- PR #100: PR #100 bootstraps the engineering-docs-agent plugin on the claude-code-self-assessment host repository with `framework: none`. It adds the host-side agent config (`.engineering-docs-agent/config.yml`), an example and live state file, and a GitHub Actions nightly workflow (`.github/workflows/docs-agent-nightly.yml`) that triggers the agent to update lens pages on a schedule.
- PR #101: Added a new Conventions entry to CLAUDE.md documenting the `/progression` timeline's dual milestone-source architecture: telemetry milestones (9 detectors in `scripts/progression.mjs`, self-dated from full session history independent of `--insights-lookback`) and config milestones (8 detectors in `scripts/config-progression.mjs`, stamped at first observed run and frozen). Also records the first-run caveat explaining why all 8 config milestones share the same `firstSeenAt` timestamp, and documents a coverage gap — 3 of 12 scored dimensions (`scheduled`, `remote`, `verification`) have no milestone detector — tracked as CCE-33.
