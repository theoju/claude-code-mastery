- PR #122: Post-merge follow-up to PR #121 / CCE-81 recording three durable lessons from the mkdocs/GitHub Pages deploy incident: (1) `actions/configure-pages@v6 enablement: true` does not bootstrap Pages on first deploy because the workflow's GITHUB_TOKEN lacks admin scope — fix requires a one-time `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow` call or equivalent UI step; (2) monitor scripts must avoid assigning to zsh's reserved built-ins `status` and `pipestatus` (crashes with `read-only variable: status`) — rename loop locals or shebang with bash; (3) a monitor exiting non-zero with no event lines emitted is almost always a script bug, not a failure of the watched system.
