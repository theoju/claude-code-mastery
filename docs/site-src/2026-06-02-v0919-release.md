# v0.9.19 — Scoring-honesty bugfix (CCE-78)

`package.json` version: **0.9.19**. This is a scoring-correctness release; no
dashboard UI changed.

## What was wrong

`scripts/run-assessment.mjs` built the `signalsSummary` object with this blend
at line 134:

```js
btwCommandUses: Math.max(maxProbe(s, "cliBtwUseCount"), s.cliBtwUseCount ?? 0)
```

`btwCommandUses` is a **30-day windowed session-coverage counter** — it counts
the fraction of interactive sessions in the last 30 days that included a `/btw`
command. `btwUseCount` (from `~/.claude.json`) is a **cumulative all-time
invocation count** — it grows monotonically with account age and is never reset.

`Math.max` silently promoted the higher of the two. For users with historical
`/btw` adoption but low recent usage, the cumulative count won the `Math.max`
and inflated the ratio numerator. The 30-day score drifted upward with account
age rather than reflecting actual recent posture. CCE-78 captured the issue;
PR #119 introduced the fix.

The root semantic violation: a ratio's numerator must be drawn from the same
universe as its denominator. Mixing a cumulative all-time counter into a
windowed ratio produces a number that can only go up, never correct itself.

## What changed (PR #119 + PR #120)

**`scripts/run-assessment.mjs`** — the `Math.max` blend is removed.
`btwCommandUses` is now projected directly from the 30-day windowed counter
only. The cumulative all-time source is exposed as a **separate**
`cliBtwUseCountAllTime` field on `signalsSummary` so nothing that needed
it is silently dropped.

**`app/data/rubric.json`** — the `satisfiedWhen` predicate for tips 33 and 54
(the `/btw` side-channel probe) is rerouted from `btwCommandUses` to
`cliBtwUseCountAllTime`. Tip satisfaction is preserved: you still get credit
for having ever adopted `/btw`; it's just tested against the right counter class
(cumulative adoption, not windowed recency).

**Memory Execution score is unchanged by design.** The numerator change
corrects the _surface_ exposed to predicates; the scorer's actual ratio — which
uses `clearSessionCount + compactSessionCount` as its windowed numerator — was
not affected.

**CLAUDE.md** — a new hard rule documents the two semantic axes every ratio
numerator field must be classified on before inclusion: (a) time window
(windowed vs. cumulative) and (b) counter class (session-coverage vs. raw
invocation count). The `Math.max` blend is the reference violation.

**Plan archives** — the CCE-72 and CCE-76 landed plans are moved to
`docs/superpowers/plans/archived/` as housekeeping.

## Follow-on work

**CCE-79** is filed for a deeper per-field semantic redesign of the Memory
Execution scorer. The original numerator summed `/btw + /clear + /compact +
/rewind` even though the four fields span three different counter classes. The
redesign restricts the numerator to the two session-coverage signals
(`clearSessionCount + compactSessionCount`), surfaces `/btw` as cumulative
evidence text via `cliBtwUseCountAllTime`, keeps `/rewind` only as a next-action
probe, and recalibrates the rubric target from 92 → 60 to match the narrowed
realistic ceiling. CCE-79 is tracked separately and did not land in this release.

## Upgrade

No migration required. Run `npm run assess` — the corrected `signalsSummary`
projection takes effect immediately. If your `/btw` cumulative count was
carrying your Memory score above what 30-day usage would justify, you may see
the windowed ratio drop to its correct value.
