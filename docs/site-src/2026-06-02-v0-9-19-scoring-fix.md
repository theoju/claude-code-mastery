# v0.9.19 — Scoring Honesty Fix (CCE-78)

**Released:** 2026-06-02  
**PRs bundled:** #118 (housekeeping), #119 (CCE-78 fix)

## What changed

### Primary: cumulative counter no longer bleeds into windowed ratio (PR #119 / CCE-78)

`signalsSummary.btwCommandUses` previously held a `Math.max()`-blended value:

```js
btwCommandUses: Math.max(cliBtwUseCount, windowedTranscriptCount)
```

`cliBtwUseCount` comes from `~/.claude.json` — a **cumulative all-time invocation count**. The windowed transcript counter (`btwCommandUses`) is a **30-day session-coverage** figure. Blending them with `Math.max` caused the Memory Execution numerator to drift upward with account age regardless of recent `/btw` usage — a user who used `/btw` 200 times a year ago would score as if they'd used it recently.

The fix separates the two surfaces:

| Field | Source | Semantic | Used for |
| --- | --- | --- | --- |
| `btwCommandUses` | transcript scan | 30-day session-coverage (windowed) | Memory Execution ratio numerator |
| `cliBtwUseCountAllTime` | `~/.claude.json` | cumulative all-time invocation count | Evidence text only |

The `btw-side-channel` predicate in the rubric (tips 33 and 54) is rerouted to `cliBtwUseCountAllTime` — this is a binary adoption check (`>= 1`), so cumulative scope is appropriate for a "have you ever used this?" gate. The windowed `btwCommandUses` feeds the ratio scorer where time-window accuracy matters.

### Secondary: plan-file housekeeping (PR #118)

CCE-72 and CCE-76 plan files are moved to the archive after shipping in v0.9.18. No scorer or signal changes.

## Why this matters

Execution scorers that mix cumulative all-time counters into windowed ratio numerators produce ratios that **increase with account age, not recent practice**. The Memory Execution dimension is the scoring surface you actually want to act on — if `/btw` appears strongly there, that should mean you used it in the last 30 days, not in the last 3 years.

The CLAUDE.md hard rules now encode a two-axis classification gate that must pass before any field enters a ratio numerator:

| Axis | Permitted classes |
| --- | --- |
| (a) Time window | all fields in the same numerator must share the same window (windowed vs. cumulative) |
| (b) Counter class | session-coverage (deduped per session) vs. raw invocation count |

If a new field's class on either axis differs from existing inputs, it doesn't belong in the same `sum`. Route it to evidence text (cumulative), a separate binary predicate, or a separate ratio with a matched denominator.

## What to expect

After upgrading to v0.9.19, users whose all-time `/btw` count was larger than their 30-day session coverage will see `btwCommandUses` drop in `signalsSummary`. This is the correct behavior. The Memory Execution score may adjust accordingly. The `btw-side-channel` predicate (tips 33/54) continues to resolve as before via `cliBtwUseCountAllTime`.

Follow-up work — redesigning the full Memory Execution scorer to apply per-field semantic categorization across all commands it counts — is filed as **CCE-79** and is out of scope for this release.
