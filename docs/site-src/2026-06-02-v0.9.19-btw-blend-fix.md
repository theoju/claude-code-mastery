# v0.9.19 — unblending the `/btw` cumulative counter

`package.json` bumps to `0.9.19` in this release. The version number itself
carries no behavior; the substance is a fix to how `signalsSummary` reports
`/btw` usage, implemented in the already-merged PR that this release bundles
(CCE-78), plus archiving the landed CCE-72/CCE-76 plans as housekeeping.
Memory Execution scoring is unchanged by this release — the scorer already
read `maxProbe(...)` directly — this is a fix to the `signalsSummary`
projection that the predicate engine and downstream tooling consume.

## What was wrong

`signalsSummary.btwCommandUses` was built with a `Math.max` blend:

```
Math.max(maxProbe(s, field), cumulativeCounter)
```

That's ergonomic for a single field, but it silently mixed two counters that
belong on different axes:

- **time window** — `btwCommandUses` is a 30-day windowed, session-coverage
  figure; `~/.claude.json`'s `btwUseCount` is a cumulative, all-time
  invocation count.
- **counter class** — session-coverage counters are deduped per session;
  invocation counts are raw and keep climbing regardless of recent activity.

Blending them into one numerator meant a user's `/btw` adoption could read as
high in the current 30-day window purely because they'd used it heavily
months ago — the ratio drifted up with account age rather than reflecting
recent posture. This is the same class of bug the project's cumulative-vs-
windowed rule exists to catch, and it was caught the same way the rule
prescribes: by checking each field against both axes (time window, counter
class) before letting it into a shared numerator.

## The fix

The cumulative counter is now exposed as its own field,
`cliBtwUseCountAllTime`, instead of being folded into `btwCommandUses`. The
rubric's `btw-side-channel` predicate was rerouted to read
`cliBtwUseCountAllTime` directly — a cumulative-adoption check belongs on a
cumulative field, not smuggled into a windowed one. `btwCommandUses` now
reports session-coverage only, matching every other field in its numerator.

## Follow-up

The broader Memory Execution scorer redesign — restricting the numerator to
same-class session-coverage signals rather than treating all `/btw`-adjacent
counters as fungible — is tracked separately as CCE-79 and isn't part of
this release.
