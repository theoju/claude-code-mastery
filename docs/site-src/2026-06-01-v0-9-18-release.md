# v0.9.18: Execution-axis coverage completes for all 12 dimensions

PR [#117](https://github.com/theoju/claude-code-self-assessment/pull/117) bumps
`package.json` from `0.9.17` to `0.9.18`. The PR itself is a version-only
change — no code — but it's the release marker for 13 previously-merged PRs,
and the one worth reading the tag notes for: it closes the last real gap in
the Execution axis.

## The headline: Memory & Terminal get Execution scorers

Before this release, ten of twelve rubric dimensions had an Execution scorer
(the axis that answers "are you using it?", as opposed to Platform Setup's
"is it configured?"). Memory & Context Management and Terminal &
Customization were the two holdouts — the radar rendered them as
honestly-unmeasured (italic label, `gapReason` set) rather than silently
zero.

CCE-76 (PR #116) closes both. The new scorers use
`withGates({transcripts: true, universe: "interactive_or_unknown"})` ratio
scoring, consuming the transcript-derived posture-command coverage counters
that CCE-71 introduced — the same `interactive_cli ∪ unknown`-gated counters,
now measured against the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`). This is the same
pattern already established for `learning` (the `★ Insight` banner) and
`parallel` (worktree usage): pull a real behavioral signal out of transcripts
rather than inventing a synthetic one.

With this landed, **Model & Effort Tuning is now the only partially-measured
dimension** — Opus usage is scored from transcripts, but effort level
(`/effort max` and friends) stays settings-only because there's no
transcript-observable proxy for it yet. Every other dimension has full
two-axis coverage.

## What else shipped in this cycle

The release also packages several scoring-fidelity fixes that landed as
separate PRs since v0.9.17 (2026-05-26):

- **Posture/volume command partition (CCE-71).** A fail-loud
  `assertCommandPartition` check now runs at module load, asserting that
  `POSTURE_COMMANDS` and `VOLUME_COMMANDS` in `scripts/_usage-data.mjs` stay
  disjoint and fully classified. Posture commands (`/color`, `/btw`,
  `/clear`, `/compact`, etc.) only count from transcripts when
  `classifySessionKind` returns `interactive_cli` or the conservative
  `"unknown"` fallback; volume commands (`/loop`, `/schedule`, `/babysit`,
  `/go`, `/batch`) count across every scanned session kind, because
  autonomous-workflow signal is real regardless of which session emitted it.
- **Ship-journal stage counting (CCE-72, PR #113).** `stageRanInEntry()`
  detects stage execution across all three journal format generations
  (singular `entry.stage`, legacy-numeric `stages_run`, new-string
  `stages_run`), so historical `/ship` runs still count correctly toward
  automation scoring.
- **Canonical predicate evaluator + precomputed next-actions (PR #106).**
  `scripts/predicate.mjs` becomes the single source of truth for the
  `satisfiedWhen` DSL; `app/lib/assessment.ts` re-exports it as a one-line
  passthrough rather than duplicating the implementation.
  `assessment.json.rankedNextActions` now ships pre-computed (filtered by
  `satisfiedWhen`, sorted by weight × deficit) — consumers read the top-10
  from the file rather than re-implementing the filter.
- **Progression-timeline detectors for scheduled/remote/verification
  (CCE-33).** Closes a coverage gap where those three dimensions never
  produced a milestone on `/progression`, even under heavy real usage.

## Why this matters

The two-axis model (Platform Setup vs. Execution) is only as trustworthy as
its weakest dimension. Two dimensions rendering permanently italic on the
radar wasn't a bug, but it was a gap in the promise: "are you using them?"
should be answerable for everything the dashboard scores, not ten-twelfths
of it. This release is the point where that promise holds for every
dimension except the one (effort level) that genuinely has no observable
signal yet.
