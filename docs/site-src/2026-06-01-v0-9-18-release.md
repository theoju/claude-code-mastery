# v0.9.18 release notes

Released 2026-06-01. Packages 13 PRs landed since v0.9.17. All functional
changes are in the constituent PRs; PR #117 is the version bump only.

## What changed

### Full Execution coverage across all 12 dimensions (CCE-76, PR #116)

The two remaining `noTelemetry` stubs — **Memory & Context Management** and
**Terminal & Customization** — are replaced with transcript-backed ratio
scorers. Both dimensions now derive Execution scores from
`interactive_cli ∪ unknown` sessions, consuming the posture-command coverage
signals introduced in CCE-71. Every dimension on the radar now has a live
Execution number. The italic-unmeasured label (`gapReason !== null`) only
appears when the session window is genuinely empty, not as a permanent
placeholder.

### `/btw` cumulative-vs-windowed blend fix (CCE-78)

`run-assessment.mjs` previously `Math.max`'d `cliBtwUseCount` (a cumulative
all-time invocation count) into `btwCommandUses` (a 30-day session-coverage
counter) as a predicate-ergonomics shortcut. This silently corrupted the
Memory Execution ratio's numerator: the blend drifted up with account age
rather than reflecting recent posture, and the two fields belong to different
counter classes.

Fix: `cliBtwUseCountAllTime` is now a separate field on `signalsSummary`.
The tip-33 predicate (`/btw` adoption check) targets `cliBtwUseCountAllTime`
directly. The Memory Execution ratio's numerator is restricted to the two
session-coverage signals (`/clear` + `/compact`) and the rubric target was
recalibrated from 92 → 60 to match the narrowed realistic ceiling (CCE-79
redesign, same release).

### Planning scorer numerator/denominator universe fix

The planning Execution scorer was dividing `planModeSessionCount`
(plan mode across all interactive sessions) by `multiTaskSessionCount`
(interactive ∩ multi-task). Because the numerator universe was a superset of
the denominator universe, the ratio could exceed 100% — observed as
`Plan mode: 36/34 multi-task sessions (105.88%)`.

Fix: `planModeMultiTaskSessionCount` (interactive ∩ multi-task ∩ plan-mode)
is introduced as the numerator so both sides of the ratio share the same
universe. The denominator constraint is now asserted in a source-level
`gatherInsightsSignals` test so a future gate-drop at the counting layer
fails CI.

### Posture/volume command partition enforcement

`POSTURE_COMMANDS` and `VOLUME_COMMANDS` in `scripts/_usage-data.mjs` are
now the canonical, enforced partition for transcript command counting.
Posture commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`,
`/simplify`, `/rewind`, `/fewer-permission-prompts`) are counted only from
`interactive_cli` or `unknown` sessions. Volume commands (`/loop`,
`/schedule`, `/babysit`, `/go`, `/batch`) are counted across all session
kinds — autonomous-workflow signal is valid regardless of which session
emitted it.

A fail-loud `assertCommandPartition` assertion runs at module load and catches
drift (disjointness, missing classification, dead classification). If
`npm run assess` exits non-zero with no `assessment.json` written, check
stderr for this assertion before assuming an environmental issue.

## Upgrade notes

No breaking changes. Existing `assessment.json` files are forward-compatible;
re-run `npm run assess` to get updated scores under the corrected scorers.

If you have downstream tooling that reads `btwCommandUses` as a proxy for
all-time `/btw` adoption (rather than 30-day session coverage), switch to
`cliBtwUseCountAllTime` on `signalsSummary`.
