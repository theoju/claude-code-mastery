# v0.9.18 release — 2026-06-01

Bundles 13 PRs landed since v0.9.17. The version bump (the only diff in PR #117
itself) cuts a stable tag against those fixes.

---

## Headline changes

### All 12 Execution dimensions now scored

Memory & Context Management and Terminal & Customization previously returned
`gapReason: "noTelemetry"` — their Execution vertices on the radar were
italic-unmeasured stubs. Both now use transcript-gated ratio scoring:

- The Memory scorer counts `/clear` + `/compact` invocations across
  `interactive_cli | unknown` sessions against the matched session universe.
  `/btw` is surfaced separately as cumulative evidence text (not folded into
  the ratio numerator) to keep the time-window semantics clean — see the
  CCE-79 redesign notes in CLAUDE.md.
- The Terminal & Customization scorer applies the same posture-session gate
  to its command signals.

The radar now only marks a dimension italic when `gapReason !== null` at
runtime (e.g. zero interactive sessions in the scoring window), not by default.

### Per-command POSTURE / VOLUME partition

A `POSTURE_COMMANDS` / `VOLUME_COMMANDS` split in `scripts/_usage-data.mjs`
prevents observer, SDK-orchestrated, and subagent sessions from inflating
posture-command counters:

- **Posture commands** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are counted
  only from `interactive_cli | unknown` sessions.
- **Volume commands** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) are
  counted across all session kinds — autonomous-workflow signal is valid
  regardless of which session emitted it.

A fail-loud `assertCommandPartition` assertion runs at module load. If
`npm run assess` exits non-zero with no `assessment.json` written, check
stderr for partition errors before assuming an environmental issue.

### `/ship` journal stage-counter fix

The stage-counter logic in `scripts/signals.mjs` now covers all three journal
format generations via `stageRanInEntry()`:

| Generation | Format shape |
| --- | --- |
| Original | singular `entry.stage` integer |
| Legacy numeric | `stages_run` array of numbers |
| Current string | `stages_run` array of stage names |

The fix corrects undercount of verify-agent and simplify adoption signals that
appeared when older journal entries were present in the scan window.

### Canonical predicate evaluator + pre-computed next-actions

`scripts/predicate.mjs` is now the single source for the `satisfiedWhen` DSL
evaluator. `app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough
re-export — the test `app/lib/__tests__/predicate-passthrough.test.ts` asserts
reference equality; a duplicate implementation fails CI.

`assessment.json` now includes a `rankedNextActions` field (top 10, sorted by
`weight × deficit`). The `/self-assessment` skill reads from this pre-computed
list — it must not re-implement the filter or ranking logic.

### `/progression` timeline coverage

The three previously uncovered dimensions — `scheduled`, `remote`, and
`verification` — now have telemetry-dated detectors. The timeline no longer
appears frozen for heavy users of those workflows once the next `npm run assess`
runs.

## Upgrade notes

No breaking changes. Pull the tag and run `npm run assess` — the new scorers
activate automatically. If you have old journal files from multiple format
generations, the stage-counter fix will increase your verify-agent and simplify
adoption signals on the next run.

If `npm run assess` exits non-zero with no output file, check stderr for the
`assertCommandPartition` boundary error before chasing other causes.
