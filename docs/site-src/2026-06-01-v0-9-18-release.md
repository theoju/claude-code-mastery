# v0.9.18 — Memory & Customization Execution + Scoring Fidelity

Released 2026-06-01. This release completes full Execution coverage across all
twelve dimensions and fixes two scoring-correctness bugs in the Memory Execution
ratio that caused inflated or drifting numerator values.

## All twelve dimensions are now Execution-scored

As of CCE-76 (PR #116), every dimension in the radar has an Execution scorer.
The two that previously fell back to `gapReason` — **Memory & Context
Management** and **Terminal & Customization** — now consume
transcript-derived posture-command coverage signals. Italic-unmeasured labels on
the radar (`¹` footnote + 0.65 opacity) now only appear for dimensions where
`gapReason !== null` at scoring time, not as a permanent fixture for those two
dims.

## Posture-command signals use the `interactive_or_unknown` session universe

Memory and Terminal Execution scorers count posture commands (e.g. `/btw`,
`/compact`, `/color`, `/voice`, `/focus`) from transcripts, but only in sessions
where session kind is `interactive_cli` or `unknown`. The denominator for these
scorers is the combined `interactive_or_unknown` universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`).

This matches the session-kind gate already applied to `POSTURE_COMMANDS` in
`scripts/_usage-data.mjs`: observer, SDK-orchestrated, and subagent sessions run
with fixed defaults and aren't settable by you, so they don't belong in posture
ratios. The `unknown` kind is included as the conservative fallback (sessions
that can't be classified but look interactive).

## Memory Execution ratio numerator fix (CCE-78)

`v0.9.17` and earlier blended `cliBtwUseCount` (a cumulative all-time
invocation counter from `~/.claude.json`) into `btwCommandUses` (a 30-day
windowed session-coverage counter) via `Math.max`. That silently overstated the
Memory Execution numerator for long-lived accounts: the cumulative counter only
grows, so it dominated the blended value and drove the ratio upward with account
age rather than recent posture.

**Fix:** `cliBtwUseCountAllTime` is now a separate `signalsSummary` field.
Habit-adoption predicates (`≥1` checks, tip 33) are routed to the all-time
field. The Memory Execution ratio's numerator uses only the 30-day windowed
`btwCommandUses`. The two fields are semantically distinct — time window and
counter class — and must not be fungibly combined.

```
Before (wrong):  btwCommandUses = Math.max(windowed_coverage, cumulative_invocations)
After  (correct): btwCommandUses = windowed 30-day session-coverage only
                  cliBtwUseCountAllTime = cumulative all-time, habit predicates only
```

## Denominator semantics (CCE-79 follow-up context)

The Memory Execution scorer redesign (per-field semantics rather than a
fungible sum over posture-command uses) is filed as CCE-79 for the next cycle.
The v0.9.18 fix addresses the numerator corruption; CCE-79 will extend the
per-field approach across the full Memory signal set so each component of the
score traces cleanly to a defined window and session universe.

## Upgrade notes

No config changes required. Run `npm run assess` to pick up the corrected
numbers. If your Memory or Terminal Execution scores shift from previous runs,
that reflects the correction — the old values were inflated.

The `interactive_or_unknown` session count is now exposed in `signalsSummary`
as `interactiveOrUnknownSessionCount` for transparency on the probes page and
in assessment output.
