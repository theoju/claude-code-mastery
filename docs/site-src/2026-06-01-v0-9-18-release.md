# v0.9.18

`package.json` bumped to `0.9.18` in PR #117 — a release-chore commit with no
code changes of its own. It marks the release point for 13 PRs merged since
v0.9.17, which together close out the last measurement gaps in the scoring
model. If you're looking for the actual behavior changes, they're in the PRs
listed below, not in the version bump itself.

## What landed in this cycle

**All twelve rubric dimensions now have Execution scorers.** Memory &
Context Management and Terminal & Customization — the last two holdouts,
previously routed to `gapReason` as unmeasured — got theirs via `withGates`
ratio scorers (PR #116, CCE-76). The numerators are MAX-merged
transcript-plus-history posture-command counters, following the same
`interactive_cli ∪ unknown` gating precedent CCE-71 established for
`learning` (the `★ Insight` banner) and `parallel` (worktree usage). One
caveat carried forward from the CLAUDE.md conventions: Model & Effort Tuning
stays partially measured — Opus usage is scored from transcripts, effort
level is still settings-only.

**A fail-loud command partition stops observer/SDK sessions from inflating
posture counters** (PR #110). `POSTURE_COMMANDS` and `VOLUME_COMMANDS` in
`scripts/_usage-data.mjs` are now the canonical source of truth: posture
commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`,
`/simplify`, `/rewind`, `/fewer-permission-prompts`) are only counted from
transcripts when `classifySessionKind` returns `interactive_cli` or the
conservative `"unknown"` fallback. Volume commands (`/loop`, `/schedule`,
`/babysit`, `/go`, `/batch`) are still counted across every scanned session
kind, because autonomous-workflow signal is real regardless of which session
kind emitted it. An `assertCommandPartition` check runs at module load and
catches drift — disjointness, missing classification, dead classification —
before it silently corrupts a ratio.

**`/ship` stage-dispatch counting spans all three ship-journal format
generations** (PR #113, CCE-72): singular `entry.stage`, legacy-numeric
`stages_run`, and the newer string `stages_run`. The canonical
stage-number/-name mapping lives inline in `scripts/signals.mjs` as
`stageRanInEntry`; new stages append to the end (stages 0–7 currently:
pre-flight, test, verify-agent, simplify, code-review, commit, push-pr,
jira-update), never insert in the middle, so the numeric detector arm stays
stable.

**A canonical predicate evaluator and pre-computed `rankedNextActions`
landed in `assessment.json`.** `scripts/predicate.mjs` is now the single
source of truth for the `satisfiedWhen` DSL; `app/lib/assessment.ts`'s
`evaluatePredicate` is a one-line passthrough re-export, enforced by a
reference-equality test so a duplicate implementation can't drift back in.
`scripts/rank-next-actions.mjs` filters and sorts the top-N next-actions by
weight×deficit and writes the result straight into `assessment.json` —
consumers (including the `/self-assessment` skill) read the pre-computed
list rather than hand-rolling the filter or the ranking again.

**The `/progression` timeline gained telemetry-dated detectors for
`scheduled`, `remote`, and `verification`** (CCE-33), closing the coverage
gap called out in earlier cycles where those three dimensions had no
milestone detector and the timeline looked frozen past the first-run wall
for anyone using them heavily.

## Why this is one release, not thirteen PRs

None of the 13 PRs individually justified a version bump on their own —
each closes a specific measurement gap (a missing scorer, a counting bug, a
coverage hole) rather than shipping a new user-facing feature. Tagging them
together as v0.9.18 gives downstream consumers — the docs site, the
probe-implementation tracker, anyone diffing rubric behavior between
releases — a single point to reference instead of reconstructing "what
changed" from 13 separate diffs. The tickets behind this cycle: CCE-76,
CCE-71, CCE-72, CCE-33, CCE-57, CCE-65, CCE-66.
