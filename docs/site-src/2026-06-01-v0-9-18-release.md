# v0.9.18 — Execution Coverage Complete

v0.9.18 bundles 13 merged PRs into a single version bump. The theme is
**measurement fidelity**: every place the Execution axis was silent, inflated,
or undercounted has been fixed. No breaking changes; drop-in upgrade.

## What's new

### Execution scorers for Memory and Terminal & Customization

The last two dimensions that still returned `noTelemetry()` stubs now have real
transcript-gated ratio scorers. All 12 scored dimensions carry an Execution score.
The radar no longer marks Memory & Context Management and Terminal & Customization
with italic/unmeasured labels unless your window genuinely contains zero
`interactive_cli` or `unknown` sessions — in which case `gapReason` is set and
the label returns, as intended.

Both scorers consume the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`), matching the same
posture-command coverage signals introduced in CCE-71.

### Per-command POSTURE / VOLUME partition

Observer, SDK-orchestrated, and subagent sessions were silently contributing to
posture-command ratios (permissions, memory, customization). v0.9.18 introduces
a canonical `POSTURE_COMMANDS` / `VOLUME_COMMANDS` partition in
`scripts/_usage-data.mjs`:

- **Posture commands** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are counted
  only from sessions where `classifySessionKind` returns `interactive_cli` or
  `unknown`.
- **Volume commands** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) are
  counted across every session kind — autonomous-workflow signal is real
  regardless of which session type emitted it.

A fail-loud `assertCommandPartition` check runs at module load and catches any
future drift (disjointness violations, missing classifications, dead entries).
If `npm run assess` exits non-zero with no `assessment.json` written, check
stderr for this assertion before assuming an environment issue.

### /ship journal-counter fix (all three format generations)

The `/ship` Stage 2 (verify-agent) and Stage 3 (simplify) adoption counters
were undercounting because the reader only handled one journal format shape.
The fix uses `stageRanInEntry()`, which detects stage execution across all
three generations: singular `entry.stage`, legacy-numeric `stages_run`, and
the current string `stages_run`. Verify-agent and simplify adoption rates
in the Automation Execution scorer are now accurate.

### Canonical predicate evaluator and pre-computed next-actions

`scripts/predicate.mjs` is the single source of truth for the `satisfiedWhen`
DSL. `app/lib/assessment.ts:evaluatePredicate` is now a one-line passthrough
re-export — the implementation is never duplicated. A new CI test
(`predicate-passthrough.test.ts`) asserts reference equality; a duplicate fails
the build.

`assessment.json` now includes a `rankedNextActions` field (top-10, sorted by
`weight × deficit`). The `/self-assessment` slash command reads from there
rather than re-implementing the filter and ranking inline. Surfacing a
satisfied action as a TODO is a data-layer regression, not a display-layer one.

### Progression detectors for scheduled, remote, and verification

Three dimensions had no telemetry-dated milestone detectors, so the
`/progression` timeline appeared frozen for heavy users of scheduled tasks,
remote/mobile sessions, and verification workflows. v0.9.18 adds detectors for
all three, bringing full coverage across the 12 scored dimensions.

## Other changes

- **Engineering-docs-agent plugin onboarding** — mkdocs scaffold, CI workflow
  wired, Pages bootstrap via `gh api POST .../pages` (the
  `actions/configure-pages@v6 enablement: true` field does not bootstrap Pages
  on a first deploy; the API call is required).
- **`state.json` shape fix** — a field mismatch in the `/ship` state file was
  causing stale reads after concurrent runs.
- **Jira workflow migration** — the CCE project's automation now uses client-id
  auth rather than legacy API tokens, aligning with Atlassian's deprecation
  timeline.
- **Archived landing plans** — superseded mkdocs migration plans moved to
  `docs/superpowers/plans/archived/`.

## No breaking changes

`assessment.json` gains `rankedNextActions` and the per-dimension
`executionRawScore` fields are preserved. Existing `assessment-history.json`
entries are read-compatible. The only user-visible behavioral change is that
Memory and Terminal & Customization Execution scores are now non-zero (or
correctly `gapReason`-flagged), which may shift your radar shape on the first
post-upgrade run.
