# Release v0.9.18

PR #117 bumped `package.json` from `0.9.17` to `0.9.18`. That's the only file
the PR itself touched — no source change. The reason it's worth a release note
is what it closes out: this tag is the point where **all twelve scoring
dimensions have an Execution scorer**, not just a Platform Setup one.

## What actually shipped (across the bundled PRs)

The 0.9.18 cycle bundles 13 previously-merged PRs (CCE-33, CCE-57, CCE-65,
CCE-66, CCE-71, CCE-72, CCE-76, and others). The headline change is CCE-76 /
PR #116: **Memory & Context Management and Terminal & Customization** — the
last two dimensions still returning `noTelemetry()` placeholders on the
Execution axis — now have real ratio scorers.

Those scorers are gated on the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`), consuming the
transcript-derived posture-command coverage signals that CCE-71 (PR #110)
introduced. CCE-71 is the other half of what makes this safe to ship: it
partitions commands into `POSTURE_COMMANDS` (`/color`, `/voice`, `/focus`,
`/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`,
`/fewer-permission-prompts`) and `VOLUME_COMMANDS` (`/loop`, `/schedule`,
`/babysit`, `/go`, `/batch`) in `scripts/_usage-data.mjs`. Posture commands
only count toward a scorer when `classifySessionKind` resolves the session to
`interactive_cli` or the conservative `"unknown"` fallback — an
`observer`/`sdk_orchestrated`/`subagent` session can't inflate a posture
ratio just by existing. Volume commands still count everywhere, since
autonomous-workflow signal is real regardless of which session kind emitted
it. A fail-loud `assertCommandPartition` check runs at module load to catch
future drift between the two lists.

Net effect on the rubric: with Memory & Customization Execution live, only
**Model & Effort Tuning** remains partially measured — the Opus-usage half is
scored from transcripts, but effort level (`/effort max` and friends) is
still settings-only, so there's no transcript signal to score it against yet.
Italic-unmeasured labels on the radar now apply strictly to dimensions whose
Execution score returns a non-null `gapReason` (e.g., a zero-interactive-
session window), not to a whole dimension category.

## Why cut the tag here

The bundled PRs landed over several days; #117 is the deliberate checkpoint
where the last Execution-scoring gap closed, so it's the right moment to
freeze a version and let anyone pulling the dashboard get the full
twelve-dimension Execution axis in one upgrade rather than mid-stream.

## Note on this record

This page documents PR #117 as a release milestone rather than a design
change — the PR diff itself is a one-line version bump. If you're looking for
the scorer implementation details, read CCE-76 / PR #116 (Memory &
Customization Execution scorer) and CCE-71 / PR #110 (posture/volume command
partition) directly; this note doesn't re-derive their individual doc targets.

As of this writing, `package.json` on `main` has already moved past `0.9.18`
(to `0.9.19`) — that's expected for a dated release record; treat the version
number above as "what shipped as of this tag," not "what's current."
