# v0.9.18: Execution scoring reaches all 12 dimensions

PR #117 bumps `package.json` to `0.9.18`. The PR itself is a pure
version-tagging commit — no source changes — but it's the release checkpoint
for 13 PRs merged since v0.9.17, headlined by **CCE-76** (PR #116).

## What actually shipped

CCE-76 replaced the `noTelemetry()` placeholders on the **Memory & Context
Management** and **Terminal & Customization** Execution scorers with real
`withGates({ transcripts: true, universe: "interactive_or_unknown" })` ratio
scorers. Both now consume the MAX-merged transcript+history posture-command
counters introduced by CCE-71 — the same `interactive_cli ∪ unknown`-gated
counting approach already used elsewhere in the scoring engine.

That closes the last gap in Execution coverage: as of this release, **all
twelve rubric dimensions have an Execution scorer**. Before CCE-76, Memory and
Customization were the two dimensions with no "are you using it?" signal at
all — they rendered as honestly-unmeasured (italic label, footnote) rather
than scored zero. Now both report a real ratio against the
`interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`), following the
precedent set by `learning` (the `★ Insight` banner) and `parallel` (worktree
usage) — transcript-derived signal folded into Execution scoring rather than
kept siloed as a Platform Setup-only probe.

**Model & Effort Tuning** remains the one dimension that's still only
partially measured: the Opus-usage half is scored from transcripts, but
effort level (`max` / `default` / etc.) is settings-only and has no
Execution-side signal. On the radar, the italic-unmeasured treatment now
applies strictly to dimensions whose Execution score returns
`gapReason !== null` — for example, zero interactive sessions in the scoring
window — not to any dimension by default.

## The other 12 bundled tickets

PR #117's version bump also folds in CCE-33, CCE-57, CCE-65, CCE-66, CCE-71,
and CCE-72, along with the remaining PRs in the run between v0.9.17 and
v0.9.18. None of them changed the shape of the scoring contract the way
CCE-76 did — CCE-71 is the transcript+history counter-merging groundwork that
CCE-76 builds on, and the rest are incremental fixes and refactors landed in
the same window. If you're auditing what changed dimension-by-dimension,
CCE-76 / PR #116 is the one to read.

## Why this matters

Before this release, a user could have a well-configured Memory workflow
(good CLAUDE.md hygiene, `/clear` and `/compact` habits) or a fully
customized terminal setup and see no Execution credit for either — the
radar would mark them unmeasured no matter how consistently they were used.
That's now fixed: both dimensions score on real usage data, closing the
Platform-Setup-vs-Execution gap that the two-axis model exists to surface in
the first place.
