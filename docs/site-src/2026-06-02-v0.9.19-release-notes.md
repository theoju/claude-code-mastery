# v0.9.19 release notes

**Released:** 2026-06-02 · **PR:** [#120](https://github.com/theoju/claude-code-self-assessment/pull/120) · **Version:** `package.json` `0.9.18 → 0.9.19`

This is a patch release. PR #120 itself only bumps the version number — it
cuts the release once two already-landed pieces of work were sitting on
`main`: the CCE-78 scoring-honesty fix (shipped in PR #119) and a housekeeping
PR archiving the landed CCE-72/CCE-76 plans. If you're diffing behavior, look
at PR #119, not #120 — the version bump is the release event, not the fix.

## What changed underneath this release

The substantive change bundled into v0.9.19 is the CCE-78 fix: the scorer no
longer blends cumulative all-time `/btw` usage into the 30-day windowed
`signalsSummary.btwCommandUses` field. Before the fix, `run-assessment.mjs`
`Math.max`'d `cliBtwUseCount` (a cumulative, all-time invocation count) into
`btwCommandUses` (a 30-day, session-coverage count) for predicate
convenience — which silently corrupted the Memory Execution ratio's
numerator by mixing a counter that only grows with account age into a
windowed ratio that's supposed to reflect recent posture.

The fix exposes the cumulative count on its own field,
`cliBtwUseCountAllTime`, and reroutes the tip 33/54 `/btw`-adoption predicate
to read from that field instead. `btwCommandUses` now stays honestly
windowed. If you rely on the raw `signalsSummary` output — for a custom
scorer, a next-action predicate, or ad-hoc analysis — check which of these
two fields you're reading; they're no longer interchangeable, and treating
`cliBtwUseCountAllTime` as if it were a 30-day count will overstate recent
usage.

See `CLAUDE.md`'s "Don't blend cumulative all-time counters into windowed
ratio surfaces" rule for the general pattern this fix established — it's now
the standard to apply before adding any new field to a ratio numerator.

## Also in this release

A housekeeping PR archived the completed CCE-72 and CCE-76 plans (the
Execution-scorer work that landed all twelve dimensions with Execution
scorers, including the transcript-derived posture-command coverage signals
for Memory & Context Management and Terminal & Customization). No behavior
change; it moves finished planning docs out of the active plans directory.

## Upgrading

Nothing to do beyond pulling `main` — there's no config migration or schema
change. If you have code that reads `signalsSummary.btwCommandUses` and
expected it to include lifetime `/btw` usage, switch to
`signalsSummary.cliBtwUseCountAllTime` for that cumulative view.
