# v0.9.18 — Execution scoring complete across all 12 dimensions

**Released:** 2026-06-22 · **Bundles:** PRs #99–#116 (13 PRs since v0.9.17)

v0.9.18 marks the completion of Execution scoring across all 12 scored
dimensions. Memory & Context Management and Terminal & Customization were the
last two dims with no "Are you using it?" signal on the radar; both now produce
ratio-based Execution scores gated to the `interactive_cli ∪ unknown` session
universe. The release also plugs an observer/SDK session inflation bug in
posture counters, fixes a multi-format journal undercount for `/ship` stage
adoption, and closes a gap in the `/progression` timeline that left three
dimensions appearing frozen past the first-run wall.

## What changed

### CCE-76 — Memory & Context and Terminal & Customization Execution scorers (PR #116)

Both dimensions previously routed to `gapReason: "unmeasured"` on the Execution
axis. They now use ratio-based scorers that count posture-command coverage
against the `interactive_cli ∪ unknown` session universe. Numerator signals
come from MAX-merged transcript and history counters — the same MAX-merge
pattern used by the existing Learning Execution scorer — so a command detected
in either source is counted once, not doubled.

The radar no longer italicizes either dimension label. If a scoring window
contains no qualifying interactive or unknown sessions, `gapReason` re-engages
and the italic returns — so the label is honestly unmeasured, not silently zero.

Model & Effort Tuning remains the one partially-measured dimension: the Opus
usage half scores from transcripts; effort level stays settings-only.

### CCE-71 — Fail-loud POSTURE / VOLUME command partition (PR #110)

`scripts/_usage-data.mjs` now declares two explicit command sets:

- **`POSTURE_COMMANDS`** — `/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`. Counted only
  when `classifySessionKind` returns `interactive_cli` or `unknown`.
- **`VOLUME_COMMANDS`** — `/loop`, `/schedule`, `/babysit`, `/go`, `/batch`.
  Counted across every scanned session kind.

A `assertCommandPartition` call runs at module load and fails loud if any
command is absent from both sets, present in both, or classified dead. Before
this change, observer / SDK / subagent sessions were included in posture counts,
artificially inflating ratios for commands like `/clear` and `/compact`.

### CCE-72 — `/ship` stage adoption signal undercount fix (PR #113)

The ship-journal counter logic now uses `stageRanInEntry()` to detect Stage 2
(verify-agent) and Stage 3 (simplify) execution across all three journal format
generations:

| Format generation | Shape |
| --- | --- |
| Singular | `entry.stage` (string) |
| Legacy numeric | `entry.stages_run` (array of numbers) |
| Current string | `entry.stages_run` (array of strings) |

Before this fix, the numeric and current-string format entries were not being
counted, which understated real `/ship` verify-agent and simplify adoption
signals.

### PR #106 — Single canonical DSL evaluator + pre-computed `rankedNextActions`

`scripts/predicate.mjs` is now the only implementation of the `satisfiedWhen`
DSL evaluator. `app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough
re-export, not a copy. A test asserts reference equality between the two —
divergence fails CI before the grammar can drift.

`assessment.json` now includes `rankedNextActions` (pre-computed top-10, sorted
by `weight × deficit`). The `/self-assessment` slash command reads from this
field instead of re-implementing the filter and ranking inline. A satisfied
action will not reappear as a TODO.

### CCE-33 — `/progression` timeline detectors for scheduled, remote, verification (PR #108)

Three dimensions previously had no telemetry-dated detectors, so their timeline
entries appeared frozen past the first-run wall regardless of real usage.
v0.9.18 adds detectors for:

- `scheduled` — detects `/schedule` and `/loop` command usage from transcripts
- `remote` — detects remote / mobile session activity from session-meta
- `verification` — detects `/ship` Stage 2 (verify-agent) markers

Each detector self-dates from session `start_time` over full history, independent
of the `--insights-lookback` window, matching the behavior of the existing nine
detectors.

## Upgrading

No migration steps. Pull the latest commit and run `npm run assess` — the new
scorers and partition assertion activate automatically. If `npm run assess` exits
non-zero with no `assessment.json` written, check stderr for a
`POSTURE_COMMANDS` / `VOLUME_COMMANDS` partition error before assuming an
environmental issue.

## Breaking changes

None.
