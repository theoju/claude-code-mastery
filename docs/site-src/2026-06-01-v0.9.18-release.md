# v0.9.18 release digest

Release date: 2026-06-01. Bundles 13 PRs landed since v0.9.17.

## What changed

### Execution measurement now covers all 12 dimensions (CCE-76)

Before this release, **Memory & Context Management** and **Terminal & Customization** had no Execution scorer — they fell through to `gapReason: "no_data"` and rendered as italic-unmeasured on the radar. Both dimensions now have transcript-gated ratio scorers that count posture-command coverage across `interactive_cli ∪ unknown` sessions, the same universe used by the learning and parallel scorers.

Memory Execution counts `/clear` and `/compact` session coverage (30-day windowed, deduped per session) against the `interactive_or_unknown` session universe. The `/btw` invocation count is surfaced separately as cumulative evidence text, not blended into the ratio numerator — avoiding the window-mismatch that CCE-78 documented and fixed in the same cycle. The rubric target was recalibrated from 92 → 60 to match the realistic ceiling of the narrower numerator.

Customization Execution counts `/color`, `/voice`, `/focus`, and `/simplify` posture-command coverage against the same session universe.

Both scorers consume the `interactive_cli ∪ unknown`-gated counters introduced by CCE-71 (see below).

### Posture/volume command partition (CCE-71)

A per-command `POSTURE_COMMANDS` / `VOLUME_COMMANDS` partition in `scripts/_usage-data.mjs` prevents observer, SDK-orchestrated, and subagent sessions from inflating posture counters. Posture commands (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are counted only when `classifySessionKind` returns `interactive_cli` or `"unknown"`. Volume commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) are counted across every scanned session kind — autonomous-workflow signal is real regardless of which session kind emitted it.

A `assertCommandPartition` assertion runs at module load and fails loudly if the two sets drift (overlap, missing classification, or dead entry). If `npm run assess` exits non-zero with no `assessment.json` written, check stderr for this assertion before assuming an environmental issue.

### Canonical predicate evaluator + pre-computed next-actions

`scripts/predicate.mjs` is now the single source for the `satisfiedWhen` DSL evaluator. `app/lib/assessment.ts:evaluatePredicate` is a one-line passthrough re-export. A test (`app/lib/__tests__/predicate-passthrough.test.ts`) asserts reference equality; a duplicate implementation fails CI.

Pre-computed `rankedNextActions` land in `assessment.json` on every `npm run assess` run. The `/self-assessment` skill reads the top-10 from the written file rather than re-implementing the weight×deficit ranking inline. A satisfied action no longer appears as a TODO — fix the data layer if it does, not the report.

### `/ship` journal stage counters across all format generations

`signals.mjs::stageRanInEntry()` now detects stage execution across all three journal format generations: singular `entry.stage`, legacy-numeric `stages_run`, and new-string `stages_run`. The adoption-signal undercount that affected `/ship` runs on older journal shapes is corrected. Stages 0–7 map to: pre-flight, test, verify-agent, simplify, code-review, commit, push-pr, jira-update.

### Progression timeline: three previously uncovered dimensions

The `/progression` timeline gains telemetry-dated detectors for `scheduled`, `remote`, and `verification`. Before this release those three dimensions had no detector, so heavy real usage produced no milestone and the timeline appeared frozen. Milestone dates are self-dated from session `start_time` over full history, independent of `--insights-lookback`.

## Scoring impact

If your Execution scores for Memory or Customization were previously showing as unmeasured (italic on the radar, `gapReason !== null`), they will now produce numeric scores on the next `npm run assess` run that includes transcripts. The score may start low — the scorer measures recent posture-command coverage, not lifetime usage. Run with `--include-transcripts` to populate both dimensions.

The Memory Execution target drop (92 → 60) means previously-borderline Memory scores will read higher post-upgrade; the change reflects the narrowed realistic ceiling of the `/clear + /compact` numerator, not a softening of the standard.
