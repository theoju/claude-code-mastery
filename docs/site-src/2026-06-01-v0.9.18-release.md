# v0.9.18 release

PR #117 bumps `package.json` from 0.9.17 to 0.9.18. The PR itself touches
nothing but the version field — no scoring logic, no schema, no rubric
change. What it marks is a consolidation point: 13 PRs merged since v0.9.17
land under one tag so the dashboard's scoring behavior (and its growing test
count) are traceable to a release rather than scattered across individual
merge commits.

## What's actually in the release

The substantive work belongs to the bundled PRs, not to #117. The two with
the widest blast radius:

- **All 12 dimensions now have Execution scorers (CCE-76 / PR #116).**
  Memory & Context Management and Terminal & Customization were the last two
  dims returning `noTelemetry()` placeholders instead of a scored Execution
  value. Both now consume transcript-derived posture-command coverage
  signals (the `interactive_cli ∪ unknown`-gated counters from CCE-71)
  against the `interactive_or_unknown` session universe
  (`sessionsByKind.interactive_cli + sessionsByKind.unknown`). This mirrors
  the precedent already set by `learning` (the `★ Insight` banner) and
  `parallel` (worktree usage) — transcript signals feeding an Execution
  score, not just Platform Setup. Model & Effort Tuning stays the one
  partially-measured dimension: Opus usage is scored from transcripts,
  effort level remains settings-only. On the radar, the italic
  unmeasured-dimension label now applies strictly to dims where the
  Execution scorer returns `gapReason !== null` (e.g. a window with zero
  interactive sessions) — it's no longer a blanket "these two dims are
  always unmeasured" rule, because after CCE-76 there's no dimension left
  that's *structurally* unmeasured.

- **Posture-vs-volume command partition (CCE-71 / PR #110).** Before this,
  command counting risked letting `sdk_orchestrated`, `observer`, and
  `subagent` sessions inflate posture counters that are only meaningful for
  sessions a user is actually steering. The fix splits commands into
  `POSTURE_COMMANDS` (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) — counted
  from transcripts only when `classifySessionKind` returns
  `interactive_cli` or the conservative `"unknown"` fallback — and
  `VOLUME_COMMANDS` (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) —
  counted across every scanned session kind, since autonomous-workflow
  signal is real regardless of which session kind emitted it. Both lists
  are canonical in `scripts/_usage-data.mjs`, and a fail-loud
  `assertCommandPartition` check runs at module load to catch drift
  (disjointness, missing classification, dead classification) before it
  reaches scoring.

## Why this matters for the docs site

None of the above required a new doc page at merge time if the merging PR
was already documented individually — the CLAUDE.md changelog entries for
CCE-76 and CCE-71 predate this release tag. This page exists to record the
release milestone itself: v0.9.18 is the point at which "12/12 dimensions
scored on both axes" became true, and the point at which the posture/volume
partition became the enforced contract for any future command-counting
change (see the `POSTURE_COMMANDS` / `VOLUME_COMMANDS` rule in CLAUDE.md).
If you're auditing when a specific scoring behavior went live, v0.9.18 is
the tag to check out.

Note that `package.json` has since moved past 0.9.18 (current main is at
0.9.19 as of this writing) — this page is a historical release marker, not
a description of the latest state. Check `docs/site-src/whats-new.md` (or
the corresponding entry for the newer tag) for what shipped after.
