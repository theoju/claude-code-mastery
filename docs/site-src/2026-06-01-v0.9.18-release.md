# v0.9.18: Execution scoring reaches all twelve dimensions

Released 2026-06-01 via [PR #117](https://github.com/theoju/claude-code-self-assessment/pull/117),
a version-bump release PR that bundles 13 previously-merged PRs. The `package.json`
version moved to `0.9.18`; there's no net-new code in the release PR itself — it just
marks the point where the bundled work ships.

## What changed

The headline change is **CCE-76** (PR #116): the Memory and Terminal &
Customization dimensions get real Execution scorers. Before this release, both
dimensions were wired through `noTelemetry()` — a placeholder that routed them
straight to "unmeasured" (`gapReason !== null`) regardless of what a user
actually did in their sessions. They only ever carried a Platform Setup score.

CCE-76 replaces both placeholders with `withGates({ transcripts: true, universe:
"interactive_or_unknown" })` ratio scorers. The numerators are the same
posture-command counters CCE-71 introduced — transcript-derived counts of
posture commands (`/clear`, `/compact`, `/color`, `/voice`, `/focus`, etc.),
MAX-merged across transcript and history sources — but gated to the
`interactive_cli ∪ unknown` session set rather than counted indiscriminately.
The denominator is the new `interactive_or_unknown` session universe:
`sessionsByKind.interactive_cli + sessionsByKind.unknown`.

This mirrors the precedent already set by two other Execution scorers:
`learning` (driven by the `★ Insight` banner) and `parallel` (driven by
worktree usage). Mixing a transcript-derived signal into an Execution score
isn't new here — what's new is that Memory and Customization finally get one.

With this landing, **all twelve rubric dimensions now have an Execution
scorer.** Model & Effort Tuning remains the sole *partially*-measured
dimension: the Opus-usage half is scored from transcripts, but effort level
(`/effort max` and friends) stays settings-only, since a user's chosen effort
level isn't something a transcript records after the fact.

One consequence worth knowing if you're reading the radar: the italic
"unmeasured" label now applies strictly to dimensions whose Execution score
returns a non-null `gapReason` at scoring time — for example, zero interactive
sessions inside the current lookback window — rather than to a fixed set of
dimensions that were structurally incapable of being scored. Memory and
Customization are no longer in that structurally-incapable set.

## Why it matters

Before v0.9.18, a user could have a fully-configured MEMORY.md setup and a
tuned `/color`/`/voice` posture and still see those two dimensions render
as unmeasured on the Execution axis — not because they weren't using the
tools, but because the scorer had no signal wired up to check. That gap is
closed. If you're diagnosing a low Execution score post-upgrade, it's now a
real reflection of posture-command usage in `interactive_cli` and `unknown`
sessions, not an artifact of missing instrumentation.

## Bundled work

The release PR itself only touches `package.json`. The substantive changes
shipped across the 13 PRs merged since v0.9.17, spanning tickets CCE-33,
CCE-57, CCE-65, CCE-66, CCE-71, CCE-72, and CCE-76 — CCE-76 (PR #116) is the
one covered above; the others predate this note and aren't re-summarized
here.
