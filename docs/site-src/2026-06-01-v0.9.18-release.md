# v0.9.18 Release Notes

Released 2026-06-01. Bundles 13 PRs landed since [v0.9.17](https://github.com/theoju/claude-code-self-assessment/releases/tag/v0.9.17) (2026-05-26). No breaking changes. Test suite: 647 → 666 passing tests.

## Headline changes

### All twelve dimensions now have Execution scorers — CCE-76 / PR #116

Memory & Context Management and Terminal & Customization were previously marked unmeasured (`gapReason !== null`) on the Execution axis. Both now have real scorers consuming **transcript-derived posture-command coverage signals** introduced in CCE-71. The denominator is `sessionsByKind.interactive_cli + sessionsByKind.unknown` (the `interactive_or_unknown` universe), matching the precedent set by the learning and parallel scorers. Dims whose Execution score still returns a non-null `gapReason` render italic on the radar with a `¹` footnote — the set is now smaller.

### Per-command POSTURE/VOLUME partition — CCE-71 / PR #110

`_usage-data.mjs` now maintains two canonical sets:

- **`POSTURE_COMMANDS`** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) — counted from transcripts only when `classifySessionKind` returns `interactive_cli` or `unknown`. Keeps posture ratios honest: `sdk_orchestrated`, `observer`, and `subagent` sessions run with SDK defaults and would silently dilute the numerator.
- **`VOLUME_COMMANDS`** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) — counted across every scanned session kind. Autonomous-workflow signal is real regardless of which session emitted it.

A fail-loud `assertCommandPartition` runs at module load and catches drift (disjointness, missing classification). If `npm run assess` exits non-zero with no `assessment.json` written, check stderr for partition errors before assuming an environmental issue.

### `/ship` Stage 2 + 3 journal credit — CCE-72 / PR #113

The ship-journal counters now detect Stage 2 (verify-agent) and Stage 3 (simplify) execution across all three journal format generations (singular `entry.stage`, legacy-numeric `stages_run`, new-string `stages_run`). The canonical stage-number / stage-name mapping lives in `scripts/signals.mjs::stageRanInEntry`. New stages append to the end of the workflow; the numeric detector arm stays stable.

### Canonical predicate evaluator + pre-computed `rankedNextActions` — PR #106

`scripts/predicate.mjs` is now the single source of truth for the `satisfiedWhen` DSL. `app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough re-export — the implementation is never duplicated. `assessment.json` now includes a pre-computed `rankedNextActions` (top-10, sorted by weight × deficit). The `/self-assessment` skill reads from this field directly rather than re-implementing the filter and ranking locally.

### `/progression` timeline detectors for previously uncovered dimensions — CCE-33 / PR #108

The telemetry milestone walker (`scripts/progression.mjs`) added detectors for dimensions that previously produced no timeline entries. The catalog formerly covered 8 of 12 scored dimensions; `scheduled`, `remote`, and `verification` had no detector, so heavy real usage there produced a frozen timeline past the first-run wall. The new detectors fill that gap.

## Upgrade

No migration steps. Pull the latest `main`, run `npm install`, and re-run `npm run assess`. The new Execution scorers take effect immediately on your next scored run.
