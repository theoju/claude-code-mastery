# v0.9.18 release notes

v0.9.18 bundles 13 PRs landed since v0.9.17. The headline changes close
measurement gaps on the Execution axis, harden the command-counting layer,
and unify two previously-forked evaluator paths.

---

## What shipped

### All 12 dimensions now have Execution scorers

**Memory & Context Management** and **Terminal & Customization** were the last
two dimensions without an Execution score. Both now use transcript-derived
posture-command counters gated on `withGates({ transcripts: true, universe: "interactive_or_unknown" })`.

The posture commands counted are `/clear` and `/compact` (Memory) and `/color`,
`/voice`, `/focus`, `/simplify` (Customization). Sessions classified as
`sdk_orchestrated`, `observer`, or `subagent` are excluded from the universe
because their posture is set by the SDK, not the user — counting them would
silently dilute the numerator against a denominator the user doesn't control.

Dimensions that still return `gapReason !== null` (genuinely unmeasured
Execution segments) show italic labels and a footnote on the radar rather than
a false zero.

### POSTURE/VOLUME command partition

A per-command partition separates posture commands from volume commands at the
counting layer:

- **Posture commands** (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
  `/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) are counted
  only from sessions where `classifySessionKind` returns `interactive_cli` or
  `unknown`. Observer, SDK, and subagent sessions are excluded.
- **Volume commands** (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) are
  counted across every session kind — autonomous-workflow signal is real
  regardless of which session emitted it.

A fail-loud `assertCommandPartition` runs at module load and catches drift
(disjointness, missing classification, dead classification). If `npm run assess`
exits non-zero with no `assessment.json` written, check stderr for partition
errors before assuming an environmental issue.

**Background:** v0.9.17 attempted a blanket "exclude observer/sdk/subagent from
`scanTranscriptInvocations`" fix and regressed the `scheduled` scorer from 75 →
63 by deleting genuine volume-command signal. That fix was reverted; the
per-command partition is the correct shape.

### `/ship` journal counter unification (Stages 2 and 3)

Stage 2 (verify-agent) and Stage 3 (simplify) adoption counters now detect
dispatches across all three journal format generations: singular `entry.stage`,
legacy-numeric `stages_run`, and the current string-keyed `stages_run`. Earlier
versions only matched one format, understating verify-agent and simplify usage
in sessions written under older journal shapes.

### Canonical predicate evaluator + pre-computed next-actions

`scripts/predicate.mjs` is now the single canonical DSL evaluator.
`app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough re-export —
no copy of the implementation. A CI test (`predicate-passthrough.test.ts`)
asserts reference equality; a duplicate fails the suite.

`assessment.json` now carries a `rankedNextActions` array (top-10,
weight×deficit order). The `/self-assessment` slash command reads this
pre-computed list rather than re-implementing the satisfiedWhen filter inline.
Surfacing a satisfied action as a TODO is a data-layer regression, not a
display bug — fix `rankedNextActions`, not the report.

### Progression timeline: three new dimension detectors

The `/progression` timeline previously had no telemetry-dated detectors for the
`scheduled`, `remote`, and `verification` dimensions, so heavy real usage in
those areas produced no milestone. v0.9.18 adds detectors for all three,
closing the coverage gap. The existing `automation`, `integrations`, `learning`,
`memory`, `model-effort`, `parallel`, `permissions`, and `planning` detectors
are unchanged.

## Supporting changes

- **Engineering-docs-agent plugin onboarding.** `framework: mkdocs` added to
  `.engineering-docs-agent/config.yml`; two CI workflows added
  (`docs-agent-pages.yml`, `docs-build-check.yml`).
- **`state.json` shape fix.** Corrects a field-name mismatch that caused the
  `/ship` state reader to silently skip Jira context in certain repo layouts.
- **Jira workflow migration.** Transitions aligned with the current board
  column names after the v0.9.17 cycle's column rename.
- **Plan archiving.** Completed plans moved to
  `docs/superpowers/plans/archived/` to keep the active plans directory
  actionable.

## Test count

666 tests across 39 files (up from 647 in v0.9.17).

The new cases cover: the `assertCommandPartition` boundary, posture-command
counter scoping per session kind, journal-format unification for Stages 2–3,
predicate passthrough reference equality, and the three new progression
detectors.
