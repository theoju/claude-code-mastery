# v0.9.18 release — complete Execution coverage across all 12 dimensions

Released 2026-06-01. Bundles 13 PRs (#99–#116) landed since v0.9.17.

## Headline: all 12 Execution scorers are now live

The two long-standing `noTelemetry` stubs — **Memory & Context Management** and
**Terminal & Customization** — are replaced with real scorers that read
transcript-derived posture-command counters. Both dims now produce an Execution
vertex on the radar rather than the italic/unmeasured footnote form. The `/insights`
narrative's gap between "Platform Setup installed" and "Execution fired" is
therefore surfaced for all 12 scored dimensions, not 10.

### How the new scorers work

Posture commands are counted only from `interactive_cli` and `unknown` session
kinds — the sessions where the user's hands are actually on the keyboard.
`sdk_orchestrated`, `observer`, and `subagent` sessions are excluded: they
run with SDK defaults and would silently dilute posture ratios if included.

A canonical `POSTURE_COMMANDS` / `VOLUME_COMMANDS` partition in
`scripts/_usage-data.mjs` declares which commands belong to which category.
A fail-loud `assertCommandPartition` runs at module load and catches any drift
(disjointness violation, missing classification, dead classification). If
`npm run assess` exits non-zero with no `assessment.json` written, check stderr
for this assertion before assuming an environmental issue.

Volume commands (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`) are counted
across every session kind — autonomous-workflow signal is real regardless of
which session emitted it.

## /ship stage-counter fix

The Stage 2 (verify-agent) and Stage 3 (simplify) dispatch counters in
`scripts/signals.mjs` now correctly recognize all three journal format
generations: singular `entry.stage`, legacy-numeric `stages_run`, and the
current-string `stages_run`. This fixes an adoption-signal undercount for
engineers who have been running `/ship` since its early format.

## Predicate evaluator canonicalized

`scripts/predicate.mjs` is now the single source of truth for the DSL
evaluator. `app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough
re-export. A new test (`app/lib/__tests__/predicate-passthrough.test.ts`)
asserts the two are reference-equal; a duplicate implementation fails CI.

## rankedNextActions pre-computed in assessment.json

`scripts/rank-next-actions.mjs` now runs as part of every `npm run assess`
invocation and writes the top-10 priority actions to
`assessment.json.rankedNextActions`. The `/self-assessment` slash command reads
this pre-computed list rather than re-implementing the `satisfiedWhen` filter
or `weight×deficit` ranking inline.

## /progression coverage extended

The `/progression` timeline gained telemetry-dated detectors for the
**scheduled**, **remote**, and **verification** dimensions (CCE-33). Previously
these three had no detector, so real usage produced no milestone and the
timeline appeared frozen past the first-run wall.
