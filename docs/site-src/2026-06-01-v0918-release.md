# v0.9.18 release notes

v0.9.18 bundles 13 PRs (#99–#116) landed since v0.9.17. No breaking changes.

## What changed

### All 12 Execution dims now return real scores

Memory & Context Management and Terminal & Customization were the last two
dimensions routing to `noTelemetry()` — meaning the Execution radar displayed
them as honestly-unmeasured rather than scored. Both now return ratio scores
derived from transcript posture-command signals. The radar italic-and-footnote
treatment now applies only to dims whose Execution scorer returns a non-null
`gapReason` at runtime (e.g. zero interactive sessions in the scoring window).

### POSTURE/VOLUME command partition

A `POSTURE_COMMANDS` / `VOLUME_COMMANDS` split in `scripts/_usage-data.mjs`
separates commands whose value is about _posture_ (e.g. `/clear`, `/compact`,
`/color`, `/btw`) from commands whose value is about _volume_ (e.g. `/loop`,
`/batch`, `/go`). Posture commands are counted only from `interactive_cli` and
`unknown` sessions; volume commands count across every session kind. This
prevents observer and SDK-orchestrated sessions from silently inflating posture
ratios.

A `assertCommandPartition` call runs at module load and fails loudly on any
drift in the partition — disjointness violations, an unclassified command, or a
classification that matches nothing. If `npm run assess` exits non-zero with no
`assessment.json` written, check stderr for this boundary assertion before
assuming an environment problem.

### /ship Stage 2 and Stage 3 dispatch counts fixed

Ship-journal counter logic now uses `stageRanInEntry()` to detect stage
execution across all three journal format generations (singular `entry.stage`,
legacy-numeric `stages_run`, new-string `stages_run`). Stage 2 (verify-agent)
and Stage 3 (simplify) dispatch counts were under-tallied on journals written
by older `/ship` versions.

### Predicate evaluator canonicalized

`scripts/predicate.mjs` is now the single source for the `satisfiedWhen` DSL
evaluator. `app/lib/assessment.ts:evaluatePredicate` is a 1-line passthrough
re-export. A CI test (`predicate-passthrough.test.ts`) asserts reference
equality so a copied implementation fails immediately. Pre-computed
`rankedNextActions` are written to `assessment.json` on every run; the
`/self-assessment` slash command reads the top-10 from there rather than
re-implementing the filter or ranking.

### /progression gains three new dimension detectors

The `/progression` timeline previously had no telemetry-dated detectors for
the `scheduled`, `remote`, and `verification` dimensions — heavy real usage
there produced no milestone and the timeline looked frozen past the first-run
wall. v0.9.18 adds detectors for all three, so sessions in those dims now stamp
dated milestones alongside the existing nine.

## Upgrading

Pull the tag and run `npm install` (only `package.json` changed in the release
commit itself; all substantive code landed in the sub-PRs).

```bash
git pull
npm install
npm run assess:print
```

No config changes required. Existing `assessment.json` and
`assessment-history.json` files are forward-compatible.
