# v0.9.18 release notes

v0.9.18 (PR #117) is a version-bump-only release: `package.json` and nothing
else. It exists to draw a line under 13 PRs merged since v0.9.17 and publish
them as a versioned checkpoint — the substantive work shipped in its own PRs
earlier in the cycle, this tag just marks "these are now released."

## Headline: all 12 dimensions are Execution-scored

The dashboard scores two independent axes per dimension — Platform Setup
("is it configured?") and Execution ("do you actually use it?"). Since
v0.9.17, Memory & Context Management and Terminal & Customization were the
last two of the twelve dimensions still routing to `noTelemetry()` on the
Execution axis, rendered on the radar as italic, unmeasured vertices. CCE-76
(PR #116) closed that gap: both dimensions now have gated ratio scorers
built from **MAX-merged transcript+history posture-command counters**, and
every dimension the rubric tracks now returns a real Execution score.

The one caveat carried forward: Model & Effort Tuning stays *partially*
measured. Its Opus-usage half is scored from transcripts; effort level
(`/effort max` and friends) remains settings-only, so that dimension keeps
its `gapReason` where applicable rather than pretending to full coverage.

## Supporting fix: posture counters no longer leak across session kinds

CCE-76's new scorers consume the posture-command coverage signals introduced
by CCE-71 (PR #110), which partitions every counted slash command into
`POSTURE_COMMANDS` (`/color`, `/voice`, `/focus`, `/btw`, `/clear`,
`/compact`, `/simplify`, `/rewind`, `/fewer-permission-prompts`) and
`VOLUME_COMMANDS` (`/loop`, `/schedule`, `/babysit`, `/go`, `/batch`). Posture
commands only count from transcript sessions classified `interactive_cli` or
the conservative `"unknown"` fallback — a user's plan-mode or permission
posture isn't something an `sdk_orchestrated`, `observer`, or `subagent`
session can set, so counting those would dilute the ratio's numerator with
signal the user never actually produced. Volume commands still count across
every scanned session kind, since autonomous-workflow usage is real
regardless of which session emitted it. This partition is enforced at module
load by a fail-loud `assertCommandPartition` in `scripts/_usage-data.mjs`, so
a future regression that reintroduces cross-contamination fails immediately
rather than silently skewing a score.

Both of these land in the same architectural line as the two precedents
already in the scoring model: `learning` (the `★ Insight` banner) and
`parallel` (worktree usage) already mixed transcript-derived signals into
Execution scoring. Memory and Customization now follow the same pattern
rather than introducing a new one.

## What this release does *not* change

- No rubric weight or target changes — this is a coverage release, not a
  retuning.
- No changes to the Platform Setup axis; the work here is entirely on the
  Execution side.
- No new probes were added to the catalog by PR #117 itself; the probe
  count changes attributable to CCE-76/CCE-71 were already reflected before
  this tag, since those PRs merged ahead of the version bump.

## Also bundled in this checkpoint

PR #117 is the release point for the rest of the CCE-33 / CCE-57 / CCE-65 /
CCE-66 cycle alongside CCE-71 and CCE-76. If you're auditing what changed
between v0.9.17 and v0.9.18, treat those individual PRs — not this one — as
the source of truth for behavior; this page exists to tell you the release
happened, not to re-derive their design rationale.

## Upgrading

There's no migration step. `npm install && npm run assess` picks up the new
scorers automatically — expect Memory & Context and Terminal & Customization
to show real (non-italic) Execution numbers on your next run instead of the
unmeasured placeholder.
