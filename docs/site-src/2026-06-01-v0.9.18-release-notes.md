# v0.9.18 release notes

[PR #117](https://github.com/theoju/claude-code-self-assessment/pull/117) tags v0.9.18. The diff itself is a
one-line version bump in `package.json` — no code changes. What it ships is
13 previously-merged PRs, packaged as a single tagged, test-verified release
rather than left unreleased on `main`.

## What landed

**All 12 rubric dimensions now have Execution scorers.** Memory & Context
Management and Terminal & Customization were the last two dimensions
lacking an Execution-axis measurement. CCE-76 (PR #116) closes both by
having their scorers consume MAX-merged transcript+history posture-command
counters — the same `interactive_cli ∪ unknown`-gated counters CCE-71
introduced — against the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`). Model & Effort
Tuning remains the one partially-measured dimension: Opus usage is scored
from transcripts, effort level stays settings-only. On the radar, the
italic "unmeasured" label now only applies to dimensions whose Execution
score returns `gapReason !== null` (for example, zero interactive sessions
in the scoring window) — not to a dimension category as a whole.

**Posture vs. volume command partition, fail-loud.** Observer and
SDK-orchestrated sessions don't reflect a user's actual settable posture,
so counting their command usage toward posture ratios silently inflates
them. `POSTURE_COMMANDS` and `VOLUME_COMMANDS` in `scripts/_usage-data.mjs`
are now the canonical partition: posture commands (`/color`, `/voice`,
`/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`,
`/fewer-permission-prompts`) are only counted from transcripts when
`classifySessionKind` returns `interactive_cli` or the conservative
`"unknown"` fallback; volume commands (`/loop`, `/schedule`, `/babysit`,
`/go`, `/batch`) count across every scanned session kind, since
autonomous-workflow signal is real regardless of which session type
emitted it. A fail-loud `assertCommandPartition` check runs at module load
and catches drift — disjointness, missing classification, or dead
classification all fail immediately rather than silently corrupting a
ratio.

**`/ship` stage-dispatch counting across all three journal formats.**
CCE-72 (PR #113) introduces `stageRanInEntry()` to detect whether a given
`/ship` stage (test, verify-agent, simplify, code-review, commit,
push-pr, jira-update) ran, reading across the three ship-journal
generations that have existed over this project's history: the original
singular `entry.stage` field, the legacy-numeric `stages_run` array, and
the current new-string `stages_run` array. The stage-number-to-name
mapping is fixed in `scripts/signals.mjs`; new stages append to the end
of the workflow rather than inserting in the middle, so the numeric
detector arm stays stable.

**Canonical predicate evaluator, pre-computed ranked next-actions.**
`scripts/predicate.mjs` is now the single source of truth for the
`satisfiedWhen` DSL; `app/lib/assessment.ts`'s `evaluatePredicate` is a
1-line passthrough re-export, enforced by a reference-equality test so a
duplicate implementation fails CI rather than silently drifting from the
canonical evaluator. `scripts/rank-next-actions.mjs` now writes a
pre-computed, weight×deficit-sorted top-10 directly into
`assessment.json.rankedNextActions` — the self-assessment skill reads
this list rather than re-implementing the filter or the ranking itself.

**Telemetry-dated `/progression` detectors for the three previously-blind
dimensions.** CCE-33 closes the coverage gap flagged in earlier progress
tracking: `scheduled`, `remote`, and `verification` had no milestone
detector, so heavy real usage in those dimensions produced no entry and
the `/progression` timeline looked frozen past the dashboard's first run.
The new detectors are self-dated from session `start_time`, matching the
existing telemetry-milestone approach in `scripts/progression.mjs` rather
than the config-milestone approach (which stamps `firstSeenAt` at
first-observed-run and can't recover true historical adoption dates).

## Why a release PR for a version bump

The auto-mode classifier blocks direct pushes to `main`, including trivial
`chore(release): bump version` commits — release PRs go through the same
review path as everything else. Bundling 13 merged PRs behind one tag
gives the accumulated CCE-76 / CCE-71 / CCE-72 / CCE-33 / CCE-57 / CCE-65 /
CCE-66 feature set a single, test-verified, discoverable release point
rather than leaving it scattered across unreleased commits on `main`.

## What this page is not

This is a release digest, not a feature spec. The architectural detail for
each bundled change (scorer formulas, DSL grammar, journal-format
detection) lives against its own PR and ticket — CCE-76 / PR #116,
CCE-71 / PR #110, CCE-72 / PR #113, CCE-33, CCE-57, CCE-65, CCE-66 — and
this page should not duplicate those edits. It exists to give the tagged
release itself a discoverable anchor.
