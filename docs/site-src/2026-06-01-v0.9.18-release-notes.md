# v0.9.18 release notes

`package.json` bumped to `0.9.18` in PR #117 (`package.json`). The PR itself
touches only the version field — no source changes — but it's the release
checkpoint for 13 PRs merged since v0.9.17. Two are worth calling out
directly; the rest are already documented under their own PRs and aren't
re-explained here.

## Full 12-dimension Execution coverage (CCE-76 / PR #116)

Before this release, two of the twelve rubric dimensions — Memory & Context
Management and Terminal & Customization — had no Execution scorer and
rendered as unmeasured. CCE-76 closes that gap: both dimensions now consume
transcript-derived posture-command coverage signals, gated to the
`interactive_cli ∪ unknown` session classification introduced by CCE-71, and
scored against the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`).

This is the same pattern already used for `learning` (the `★ Insight` banner
signal) and `parallel` (worktree usage) — pulling behavioral signal from
transcripts into Execution scoring rather than leaving it Platform-Setup-only.
With this PR, **all twelve dimensions have Execution scorers**. Model & Effort
Tuning remains the sole partially-measured dimension: the Opus-usage half is
scored from transcripts, but effort level is still settings-only and can't be
observed from telemetry. On the radar, the italic "unmeasured" label now only
applies to dimensions whose Execution score returns a non-null `gapReason` —
for example, a window with zero interactive sessions — rather than to any
dimension lacking a scorer at all.

## Posture/volume command partition fix (CCE-71 / PR #110)

CCE-71 fixes a scoring-fidelity issue in transcript-based command counting:
observer and SDK-orchestrated sessions were inflating posture counters that
should only reflect commands a user actually chose to run interactively.
The fix partitions tracked commands into `POSTURE_COMMANDS` and
`VOLUME_COMMANDS` in `scripts/_usage-data.mjs`. Posture commands (`/color`,
`/voice`, `/focus`, `/btw`, `/clear`, `/compact`, `/simplify`, `/rewind`,
`/fewer-permission-prompts`) are now counted from transcripts only when
`classifySessionKind` returns `interactive_cli` or the conservative
`"unknown"` fallback. Volume commands (`/loop`, `/schedule`, `/babysit`,
`/go`, `/batch`) are still counted across every scanned session kind, since
autonomous-workflow signal is real regardless of which session kind emitted
it. A fail-loud `assertCommandPartition` check runs at module load to catch
future drift — disjointness violations, missing classification, or dead
classification arms all fail immediately rather than silently corrupting a
ratio.

This is also the CCE-76 dimensions' upstream dependency: the
`interactive_cli ∪ unknown` gating that Memory and Customization Execution
scoring relies on is the same gate this partition fix establishes for
posture-command counting.

## What this release does not include

The PR that bumps the version does no scoring or UI work itself — treat
`package.json`'s `0.9.18` as a marker on the commit graph, not a functional
change to audit on its own. If you're looking for the underlying behavior
change, read CCE-76 (PR #116) and CCE-71 (PR #110) directly; this page exists
to record that they shipped together under this tag.
