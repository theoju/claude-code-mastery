# v0.9.18 release notes

`package.json` bumped to `0.9.18` in PR #117, tagging 13 PRs merged since
v0.9.17. The bump PR itself only touches the version field — the substantive
work landed in the 13 PRs it packages. This page is the point-in-time
changelog record for that release, not a re-documentation of each underlying
change (those are covered separately where they landed).

## Headline: Execution scoring gap closed

Before this release, two of the twelve scored dimensions — Memory & Context
Management and Terminal & Customization — had no Execution scorer and
rendered as honestly-unmeasured (italic label, `gapReason` set) on the radar.
**All twelve dimensions now have Execution scorers** (CCE-76). Memory and
Customization consume the transcript-derived posture-command coverage
signals introduced in CCE-71 — the `interactive_cli ∪ unknown`-gated
counters — evaluated against the `interactive_or_unknown` session universe
(`sessionsByKind.interactive_cli + sessionsByKind.unknown`). This is the same
shape already used for `learning` (the `★ Insight` banner) and `parallel`
(worktree usage): transcript signals feeding the Execution axis, not just
Platform Setup.

Model & Effort Tuning remains the one dimension that's only partially
measured — the Opus-usage half scores from transcripts, but effort level
stays settings-only (Platform Setup can't infer it from cooked telemetry).
The radar's italic-unmeasured treatment now applies strictly to dimensions
whose Execution score returns a non-null `gapReason` (e.g., zero interactive
sessions in the scoring window), not to a static allowlist.

## Fixes bundled into this release

- **Posture-vs-volume command partition (CCE-71).** Command counting now
  splits into `POSTURE_COMMANDS` (`/color`, `/voice`, `/focus`, `/btw`,
  `/clear`, `/compact`, `/simplify`, `/rewind`,
  `/fewer-permission-prompts`) and `VOLUME_COMMANDS` (`/loop`, `/schedule`,
  `/babysit`, `/go`, `/batch`) in `scripts/_usage-data.mjs`. Posture commands
  only count from transcripts classified `interactive_cli` or the
  conservative `"unknown"` fallback — an `sdk_orchestrated`, `observer`, or
  `subagent` session running with SDK defaults no longer dilutes a posture
  ratio's numerator. Volume commands still count across every scanned
  session kind, since autonomous-workflow signal is real regardless of which
  session emitted it. A fail-loud `assertCommandPartition` check runs at
  module load to catch drift (disjointness, missing classification, dead
  classification) before it reaches a scored ratio.
- **Ship-stage counting across journal generations (CCE-72).** `stageRanInEntry()`
  now detects stage execution consistently across all three ship-journal
  format generations the repo has accumulated: singular `entry.stage`,
  legacy-numeric `stages_run`, and new-string `stages_run`. The canonical
  stage-number/-name mapping (stages 0–7: pre-flight, test, verify-agent,
  simplify, code-review, commit, push-pr, jira-update) lives inline in
  `scripts/signals.mjs`.
- **Canonical predicate evaluator + pre-computed ranked next-actions (PR #106).**
  `scripts/predicate.mjs` is now the single source of truth for the
  `satisfiedWhen` DSL; `app/lib/assessment.ts:evaluatePredicate` is a 1-line
  passthrough re-export, held to reference-equality by
  `app/lib/__tests__/predicate-passthrough.test.ts`. The filtered,
  weight×deficit-sorted top-N next-actions are pre-computed into
  `assessment.json.rankedNextActions` — consumers (including the
  self-assessment skill) read that field directly rather than
  re-implementing the filter/rank logic.
- **Telemetry-dated progression detectors for scheduled/remote/verification
  (CCE-33).** The `/progression` timeline's config-milestone catalog
  previously covered 8 of 12 scored dimensions. This release adds detectors
  for the three that had none, so heavy real usage in those areas now
  produces a dated milestone instead of leaving the timeline frozen at the
  first-run wall.

## What this release does not change

The bump PR (#117) carries no source diff beyond `package.json` — all
behavior changes described above shipped in their originating PRs before
this tag. If you're auditing a specific fix, look at the referenced PR/CCE
number rather than this release commit.
