# v0.9.18 release notes

PR #117 cut the `v0.9.18` release: a version bump only (`package.json`,
no code changes) marking the point where 13 PRs merged since `v0.9.17`
land as a single, citable point in project history.

## Headline: full 12-dimension Execution coverage (CCE-76 / PR #116)

The change worth reading about in this release is bundled, not in the tag
commit itself. **CCE-76 (PR #116)** replaces the no-telemetry placeholder
that Memory & Context Management and Terminal & Customization carried on
the Execution axis with real ratio scorers:

- Both dimensions now consume **transcript-derived posture-command
  coverage signals** — the `interactive_cli ∪ unknown`-gated counters
  introduced in CCE-71 — against the `interactive_or_unknown` session
  universe (`sessionsByKind.interactive_cli + sessionsByKind.unknown`).
- This mixes transcript signal into Execution scoring for these two
  dims, following the same precedent already set by `learning` (the
  `★ Insight` banner) and `parallel` (worktree usage).
- With this change, **all twelve rubric dimensions have Execution
  scorers** — the radar no longer needs the "unmeasured" placeholder for
  Memory or Terminal & Customization.

**Model & Effort Tuning remains the one partially-measured dimension**:
the Opus-usage half is scored from transcripts, but effort level is
still settings-only (Platform Setup axis). Italic-unmeasured labels on
the radar now apply only to dimensions whose Execution score returns
`gapReason !== null` — for example, zero interactive sessions in the
scoring window — not to a dimension category as a whole.

## What to check after upgrading

If you're running a local `~/.claude/` with meaningful transcript
history, re-run `npm run assess:print` after pulling `v0.9.18`. You
should see:

- Memory & Context Management and Terminal & Customization both
  reporting an Execution score (not the unmeasured/italic radar label),
  assuming you have `interactive_cli` or `unknown`-kind sessions in the
  lookback window.
- No change to Platform Setup scoring for either dimension — this
  release only fills in the Execution axis.

As with every Execution scorer, the underlying counters are MAX-merged
across transcript and cooked-telemetry history rather than summed, so
re-running the assessment repeatedly won't inflate the score.
